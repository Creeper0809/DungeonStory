## ECON-002 직원·용병의 일급, 체불, 예측

| 종류 | 실제 일급 |
| --- | --- |
| 직원 | 30 + 레벨×2 + max(0,역할수당) |
| 용병 최초 견적/선불 | 60 + max(1,레벨)×4 + max(0,역할수당) + 장비품질수당 |
| 용병 갱신 | 60 + 레벨×4 + 장비품질수당 |
| 창립자·하수인 | 0 |

장비품질수당은 ownerCharacterId가 같은 전투 장비마다 max(0,quality enum 값)×4를 더한다. 장착 여부 필터는 없으므로 “착용 중인 장비만”으로 축약하지 않는다.

직원은 그날 일급+기존 체불액 전체를 지불하고, 잔액 부족이면 부분 지급하지 않고 전액을 체불액으로 남긴다. 기분 -6/300초, factor 최대중첩3이다. 정산은 직원ID ordinal 순이므로 부족한 날 누가 먼저 지급받는지도 무작위가 아니다. 같은 날짜는 lastSettledDay로 다시 정산하지 않는다. 직원 다음 용병, 그 다음 유료시설 계약 정산이 실제 운영일 어댑터에 연결된다.

용병은 첫 일급을 선불로 내며 고용일을 이미 정산한 날로 기록한다. 갱신 지불 실패는 체불 유지가 아니라 비활성/퇴장과 경보다. 실제 고용 UI→RegularCustomerRuntime→EmploymentContractRuntime 연결을 확인했다. 작성 용병 고용시설은 술음료장1개, 역할수당0·최소 후보 만족도65다.

ForecastCost(n)는 활성 유급 인력 일급×max(0,n)에 활성 직원 체불액을 한 번 더한다(n=0이면0). HUD는 임금/용병 일급, 3일 고정지출, 보호자금, 최근 거래8개를 표시한다.

**현재 문서 공백:** 가이드에는 임금 지급 여부와 영입 간격은 있지만 이 공식, 창립자 예외, 체불/용병 퇴장 차이, 정산·예측 방식이 없다. 단골 자격·10일 영입 간격은 기존 조사와 중복 집계하지 않는다.

**미확인/예외:** 최초 용병 견적의 역할수당은 갱신식에서 빠진다. 현재 작성수당은0이므로 통상 플레이의 실제 과금 오류로 확정하지 않는다. SetEmployeeRolePremium의 운영 UI 호출은 미발견이며 임의 수당 편집 기능이 있다고 문서화하지 않는다. 구형 DungeonEconomyCalculator의 인원×35+근무×10은 현재 운영일 정산 권위가 아니다.

## ECON-003 자동구매의 예산·보호금·재고·찜 규칙

실제 UI는 ShopFeatureSurfacePresenter의 예산 조정·재고목표 순환·찜 토글이고, DailyFacilityShopRuntime.Refresh→AutoProcurementRuntime.ProcessShopRefresh가 실행한다.

- 하루에 한 번. 다음 날 refresh에서 전날 임금·시설 계약비를 먼저 정산한다.
- 보호금=max(사용자 최소보호금, 임금3일 예측+유료시설계약3일 예측).
- 가용예산=min(일일 구매예산, max(0,현재잔액-보호금)).
- 카테고리 재고 규칙을 우선순위 내림차순→ruleId ordinal 순으로 처리한 뒤 찜 규칙을 같은 순서로 처리한다.
- 목표 재고는 해당 카테고리의 모든 월드 스택 수량 합 기준이다. 창고에 보관된 수량만을 뜻하지 않으며, 이 계산 자체에는 Forbidden/예약/Carried 상태 제외 필터가 없다.
- 요청량=min(목표-보유량, 일일최대량 또는 무제한, 오늘 공급량), 단가=제안총비용/제안수량. 최대단가 초과 시 건너뛰고 예산 부족이면 floor(예산/단가)로 줄이며 비용은 ceil(단가×수량).
- 같은 날 같은 카테고리 제안은 한 번 처리한다. 실패 상태도 processedOfferKeys에 추가된 뒤 발생할 수 있어 같은 날 재시도를 일반 보장하면 안 된다.
- UI 재고목표는0→10→25→50→100→0개, 첫 설정 일일최대25개·최대단가 ceil(카테고리 기본단가×2).
- 찜은 상품 유형/정의ID/태그, 최대가격·최대보유량으로 필터링하고 현재 기본 토글 최대보유량은1개다. 설치된 시설 수가 아니라 해당 설치키트/청사진 실물 수량을 센다.
- 조달 규칙·예산·최소보호금·lastProcessedDay·처리키·최근결과는 TreasuryEconomyPersistence의 조달 상태로 캡처/복원된다.

**위키:** 외부 구매 정산은 설명하지만 위 설정/우선순위/3일 보호금/발동시점/재고 범위는 설명하지 않는다.

**반증:** 자동구매는 불일치 수량이면 전액 환불하는 분기가 있으나 현재 SpawnItemAtDropoff→WorldItemSpawner.Spawn의 정상 경로는0 또는 전량을 반환한다. 이것만으로 부분배송 무료취득이 실제 발생한다고 보고하지 않는다. 예외 발생 도중 생성과 환불 원자성은 별도 실행 확인 대상이다. 다른 수동구매의 부분정산식과 무조건 같다고 쓰지도 않는다.

## ECON-004 세력 계약과 다른 지역 공급 계약

상권 통합(research:commerce:integration) 연구 후 창고 운영 화면의 수락/거절로 사용하는 별도 생성형 계약이다. 세력의 authored 계약과 혼동하지 않는다.

- 3일마다 최대3개 새 제안. 지역명은 변경 교역권/경쟁 던전 전초권/봉인 지대. 이전 Offered는 갱신 때 Declined로 만료한다. 후보가0이면 제안도0이다.
- 품목 후보는 Resource 목록의 Raw/Intermediate/FinishedGood/Food/Medicine/Ammunition이며 연구 해금 필요. 최소단가 원료·중간재1, 나머지5.
- item ID/날짜 stable hash 정렬과 고정 인덱스 선택. 세번째 제안만 다른 보조 품목을 추가할 수 있다.
- 아래 인구는 어댑터의 주인/직원 판정 수이며 코드에 독립적인 “성인 생산인구만” 필터가 없다. 완료 연구수는 실제 완료 프로젝트 수다.

```text
P = clamp(floor(인구/3),0,10)
R = clamp(floor(완료연구수/12),0,5)
원료 요구량 = clamp(20+3P+5R+4×제안index,20,80)
중간재 요구량 = clamp(10+2P+3R+2×제안index,10,40)
그 외 요구량 = clamp(2+floor(P/2)+R+제안index,2,12)
보조품목량 = max(2, ResolveAmount(보조품목,index+1)/2의 정수 몫)
보상 = max(1, round(max(1,Σ단가×수량)×1.20×clamp(대형사업배율,1,1.25)))
```

- 수락에는 연구·하차장·물리 입력 소유자 개설이 필요하다. 기한=max(기존기한,수락일+3).
- 평가1게임초마다 물품 배송을 요청·우선화한다. 운반 중 commitment와 실제 도착을 구분하고 전량 도착 전에는 보상을 주지 않는다.
- 전량 도착→exact 물리 Transfer 영수증→중앙 금화 입금→영수증 승인→목적지 정리 순서를 보존한다. 단계 상태가 있는 것과 모든 장애/저장 지점의 exact-once 재현을 마쳤다는 것은 다르다.
- 현재일>기한에 실패 처리한다. 당일은 아직 기한 안이다. 실패 시 목적지 정리가 끝나야 Failed로 바뀐다.
- 보상은 현재 이 생성기에서 금화다. 완료 함수에서 세력 관계·통행권을 직접 변경하지 않는다.
- 창고 패널은 요구 수량/금화/기한/배송 상태를 표시한다. 최근10일 유효EWU 부담률은 이 생성기/패널에서 사용하지 않는다.
