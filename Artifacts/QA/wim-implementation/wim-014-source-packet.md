# WIM-014 source packet — transplant-organ preservation

Status: source-only investigation, 2026-09-06. No KB, Unity, asset, runtime, or wiki generation was run.

## Current authority

- The plan requires each transplant-organ lot to use the existing `2..8°C` query, retain one elapsed-time counter across storage/carry/surgery-buffer movement, and use physical disposal/output on expiry: [wim-implementation-plan.md](../../../docs/game-design/wim-implementation-plan.md) `WIM-014` (line 170).
- `EnvironmentalThresholdRules.IsOrganPreservationSafe(float)` is inclusive `>= 2f && <= 8f`; `EnvironmentalFieldRuntimeApplicationAdapter.IsOrganPreservationSafe(Vector2Int)` reads the actual cell and returns false when no cell exists.  The query is already registered as `IEnvironmentalFieldQuery` by `DungeonWorldSimulationRegistration` (lines 873–879).
- `SurgicalPartRuntime` owns the sole natural-organ lot state.  `TryCreateExtractedPart` creates a unique loose world stack, assigns `freshnessSeconds = 360` (two 180-second days), records its stack ID, then calls `RequestOrganStorage` ([SurgicalPartRuntime.cs](../../../Assets/Scripts/Services/Medical/SurgicalPartRuntime.cs), lines 101–168).  `SurgicalPartInstance` already saves freshness, linked physical stack, M08 ID, canister provenance, and installation provenance; no new lot timer or save field is needed.

## Existing cooling authoring

- M08 (`building:9508`) authors `BuildingOrganStorageAbility { preservationDays: 15, fuelPerDay: 1, capacity: 8 }`, plus separate biological storage (8 lots/12,500 g) and a general fuel consumer. It has **no** `BuildingThermalEmitterAbility`: [M08_장기보관함.asset](../../../Assets/Resources/SO/Building/Medical/M08_장기보관함.asset), lines 123–159.
- Existing refrigeration is available without a new cooling feature. E10 (`building:1501`, 냉각기) is a powered cool emitter at 8°C, player-configurable from 2 to 8°C, radius 3, 3°C/s, requiring power (8 demand): [E10_냉각기.asset](../../../Assets/Resources/SO/Building/Modular/E10_냉각기.asset), lines 155–179. E11 (`building:1502`, 공조기) is an alternative powered thermostat configurable from 2 to 30°C, radius 4 (default 22°C): [E11_공조기.asset](../../../Assets/Resources/SO/Building/Modular/E11_공조기.asset), lines 151–184.
- The environmental query is spatial; it has no M08/same-room special case. E10 is unlocked by `research:environment:cold-work`; E11 by `research:environment:rune-insulation`. M08 itself is unlocked by `research:medical:organ-preservation`. Thus M08 research alone does not author an operational refrigeration source.

## Preflight and expiry

- At order creation, `SurgeryRuntime.TryCreateOrder` validates and reserves the selected part. `SurgicalPartRuntime.TryReserveForOrder` rejects a natural organ at `freshnessSeconds <= 0` ([SurgeryRuntime.cs](../../../Assets/Scripts/Services/Medical/SurgeryRuntime.cs), lines 1000–1021; [SurgicalPartRuntime.cs](../../../Assets/Scripts/Services/Medical/SurgicalPartRuntime.cs), lines 596–632).
- At effect execution, `InstallSurgicalPartEffectHandler` calls `TryConsumeForInstallation` ([SurgicalProcedureEffectHandlers.cs](../../../Assets/Scripts/Services/Medical/SurgicalProcedureEffectHandlers.cs), lines 783–820). That method verifies identity/reservation and performs the existing physical transfer, but does **not** repeat the natural-organ freshness check. A final stale-lot check belongs there before the transfer commit.
- `TickFreshness` is per natural-organ part. It reads the linked stack, applies the `2/15` rate only when working M08 + canister are true, otherwise `1`, and never resets `freshnessSeconds` ([SurgicalPartRuntime.cs](../../../Assets/Scripts/Services/Medical/SurgicalPartRuntime.cs), lines 799–859). On expiry with a live stack it calls `DeleteStack`, calls `SpawnItemAt` for one loose `surgery:contaminated-tissue` at the same `stack.Position`, and removes the lot record **without checking either return value**. If the linked stack is already absent, it removes only the lot record. This is neither an atomic physical transform nor valid corrupt-state recovery.

## Carrier query and physical-expiry constraints

- A no-rewrite current-cell lookup already exists. `ICharacterWorldQuery.Characters` exposes registered actors ([CharacterAiWorldRegistry.cs](../../../Assets/Scripts/Services/Character/AI/CharacterAiWorldRegistry.cs), lines 6–10); `CharacterPersistentIdentity.TryGet(actor, out CharacterId)` obtains the actor's stable ID and `CharacterActor.GetNowXY()` supplies its current cell ([CharacterPersistentIdentity.cs](../../../Assets/Scripts/Services/Character/Core/CharacterPersistentIdentity.cs), lines 24–29; [CharacterActor.cs](../../../Assets/Scripts/Services/Character/Core/CharacterActor.cs), lines 845–846). `ItemTransferService` writes `CharacterIdRegistryAdapter.GetOrAssignPersistentId(actor).Value` as the carried stack destination; the adapter returns that same `CharacterId.Value` ([CharacterIdRegistryAdapter.cs](../../../Assets/Scripts/Services/Infrastructure/CharacterIdRegistryAdapter.cs), lines 30–39).
- `SurgeryWorldServices` already receives `ICharacterWorldQuery` ([SurgeryRuntimeServices.cs](../../../Assets/Scripts/Services/Medical/SurgeryRuntimeServices.cs), lines 46–71). The smallest medical implementation is to pass that established query into `SurgicalPartRuntime` and, only for `stack.State == Carried`, resolve exactly one non-dead actor whose `CharacterPersistentIdentity.TryGet(...).Value` equals `stack.DestinationId`, then query `actor.GetNowXY()`. Non-carried stacks continue to use `stack.Position`. A missing or ambiguous carrier must fail loud; it must not silently reuse the pickup cell or introduce continuous world-stack rewrites.
- `IWorldItemStackRuntime.DeleteStack` ([WorldItemStackRuntime.cs](../../../Assets/Scripts/Services/Items/WorldItemStackRuntime.cs), lines 2203–2221) denies only blank/missing stacks and prepared-output custody. It therefore accepts `Carried` and reserved stacks, marks any item instance lost, and removes the record. `WorldItemRepository.Remove` invokes `StackRemoving`; `ItemQuantityReservationService.OnRepositoryStackRemoving` releases quantity leases with `StackInvalidated` ([WorldItemRepository.cs](../../../Assets/Scripts/Services/Items/WorldItemRepository.cs), line 1687; [ItemQuantityReservationService.cs](../../../Assets/Scripts/Services/Items/ItemQuantityReservationService.cs), lines 266–288). It does not update a character's carried-inventory component.
- The existing correct ordinary replacement boundary is `IPhysicalItemTransformService.TryTransform*` ([PhysicalItemTransformService.cs](../../../Assets/Scripts/Services/Items/PhysicalItemTransformService.cs), lines 102–137, 286–429): it validates output mass/definitions, commits outputs before removing input, and rolls outputs and sources back on failure. It intentionally rejects `Carried`, `InTransit`, and any world-item reservation. `SurgicalPartRuntime.TryReserveForOrder` only writes its own `part.reservedOrderId` ([SurgicalPartRuntime.cs](../../../Assets/Scripts/Services/Medical/SurgicalPartRuntime.cs), lines 596–640); that is distinct from an Items quantity reservation, but an actual Items-reserved stack remains ineligible for the transform.
- The existing carried terminal boundary is `ICarriedPhysicalItemBatchDispositionService.TryCommitCarriedSinkPending`, which can only **sink** a carried source. Its contract requires the owning character adapter to update carry inventory in the same rollback scope ([PhysicalItemBatchDispositionService.cs](../../../Assets/Scripts/Services/Items/PhysicalItemBatchDispositionService.cs), lines 95–119, 444–454). `CharacterConsumablesApplicationPorts.TryCommitSubstanceConsumptionPending` is the concrete pattern: capture carry, debit it, call the carried sink, restore carry on failure ([CharacterConsumablesApplicationAdapters.cs](../../../Assets/Scripts/Services/Survival/CharacterConsumablesApplicationAdapters.cs), lines 864–930). It produces no replacement output.

**Result:** no current item API atomically turns a carried or Items-reserved organ into contaminated tissue while maintaining the carrier inventory. Do not compose `DeleteStack` + `SpawnItemAt`; it may delete input on spawn failure, spawn output after a protected-input delete failure, or leave carry inventory stale. For an absent physical stack, retain the surgical-part owner and fail loud; `SurgeryRestoreCoordinator.ValidateParts` already reports a non-installed part whose `worldStackId` is absent ([SurgeryRestoreCoordinator.cs](../../../Assets/Scripts/Services/Medical/SurgeryRestoreCoordinator.cs), lines 651–684). The runtime must not remove that lot or fabricate a replacement. The only existing atomic transform can be considered for a non-carried, non-Items-reserved source after its built-in output-mass/definition preflight; carried/reserved expiry requires an explicitly owned extension of an existing Items boundary before it can publish tissue safely.

## Smallest bounded implementation seam

1. **Medical lot owner:** inject the existing `IEnvironmentalFieldQuery` and `ICharacterWorldQuery` into `SurgicalPartRuntime` (both are already registered). In `TickFreshness`, resolve a carried organ through the direct actor lookup above; retain M08 destination/fuel/canister gates and require `environmentalField.IsOrganPreservationSafe(resolvedPhysicalPosition)` before using the existing `2/15` rate. Keep the current 360-second clock, canister sink, M08 fuel state, physical capacity, and save shape.
2. **Physical expiry boundary:** consider `IPhysicalItemTransformService` only where its non-carried/non-Items-reserved and output-mass/definition preflight succeeds. For carried or Items-reserved stacks, leave the lot/physical source intact and fail loud until the responsible existing Items boundary has an explicit atomic replacement operation; do not add a generic framework or use the current two-call delete/spawn sequence.
3. **Medical final boundary:** repeat the existing natural-organ `freshnessSeconds > 0` rejection in `TryConsumeForInstallation` immediately before its physical transfer. This closes expiry between order creation and installation without adding a timer or changing procedure effects.

Focused verification after implementation: assert 2°C/8°C pass and 8.1°C fails; an M08 lot with fuel+canister has the existing `2/15` rate only in a safe cell; a warm surgery buffer and a carried lot use normal decay while retaining the same remaining counter; carrier movement changes the queried cell; a lot expiring with a physical stack produces contaminated tissue at that cell; and a lot that expires after reservation cannot be installed.
