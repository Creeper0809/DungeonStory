# DungeonStory 게임 전체 문서화 발견 기록

## 초기 상태

- Unity 프로젝트이며 다수의 도메인 어셈블리(`AI`, `Buildings`, `Combat`, `Evolution`, `Items`, `Rooms`, `Survival`, `Work`, `World` 등)가 분리되어 있다.
- 저장소 루트에 과거 대규모 기능/아키텍처 감사 문서와 계획 기록이 존재한다.
- 기존 활성 계획은 `2026-07-29-instance-evolution`이므로 이번 문서화 계획은 별도 디렉터리로 격리한다.
- 프로젝트 지침은 조용한 fallback을 금지하고, 상위 게임플레이 API와 하위 계산/Unity 표현 계층의 분리를 강조한다.

## 분석 원칙

- 파일 존재만으로 구현 완료를 판정하지 않는다.
- 씬 부트스트랩, 프리팹/에셋 참조, 이벤트 구독, 테스트/검증 흔적을 통해 실제 연결 여부를 확인한다.
- 코드에 직접 드러난 기능, 데이터로 준비된 콘텐츠, 설계 의도로만 남은 항목을 분리한다.

## 기존 루트 계획에서 확인한 큰 기능 축

- 공격/원정은 3인 파티, 전·중·후열, 분기 노드, 보급품, 지속 체력/스트레스, 야영/후퇴/영구 사망, 지역 보스와 최종 `truth_core` 승리 구조다.
- 캐릭터는 영속 ID, 50레벨 성장, 잠재력/스탯 성장, 서사 기록, 종족 액티브·일반 액티브·패시브·궁극기 슬롯, 규칙 기반 모듈과 제한된 LLM 생성 스킬을 가진다.
- 시작 흐름은 타이틀 → 전용 준비 씬 → 소유자 1명 + 동종족 직원 2명 선택이며, 후보 교체/리롤/초기 스킬 준비가 있다.
- 비금화 자원은 물리 아이템 스택으로 존재하고, 창고·운반·상점·제작·원정 보급·보상·절도를 연결한다. 운반 중량과 과적 이동 패널티가 있다.
- 건설은 즉시 완성이 아니라 건설 현장, 실물 재료 예약/픽업/투입, 작업량 진행, 완성 건물 교체로 이어진다.
- 생존은 허기/갈증/위생/기분/건강, 결핍 피해, 붕괴, 절박한 행동, 오염/청소, 시체/도축, 비상 자가 돌봄까지 포함한다.
- 야생동물은 서식지 자원, 방목/포식/사냥/반격/도축과 외부 장식 생태 변화를 가진다.
- 침입 방어는 경비 정책, 근접 차단/교대, 원거리 전투, 집결과 실물 장비 수령, 소유자 대피, 수동 제압을 포함한다.
- 공통 전투 해석기는 근접/원거리/투척, 사거리, 사격 모드, 회피, 방향성 엄폐, 아군 오사, 관통, 신체 부위, 출혈, 제압, 장비 품질·내구·탄약을 처리한다.
- 외부 세계는 연못/날씨/야간 위험/사건/접대/순찰/위생과 물리 행위자를 연결하고, 지역 압력은 동일 세력에 일부 전파된다.
- 서커스/포로 시스템은 명성, 부상 조건, 혈액과 기억 잔여물 같은 물리 자원 및 작업 소비처와 연결된다.
- UI에는 시설/캐릭터/아이템 클릭 우선순위, 아이템 더미 상세, 작업/건설 진행, 전투 명령, 방어 정책, 개발자 모드(112개 명령), 반응형 데스크톱/세로 화면 검증 흔적이 있다.
- 성능 구조는 가중 A*/Dijkstra, 버전 캐시, 검색 예산, due-time 스케줄러를 사용하며 기존 기록상 500 캐릭터 프로파일을 통과했다.
- 루트 계획의 거의 모든 과거 단계가 `Completed`로 표기되어 있으나, 최종 문서에서는 실제 현재 코드/씬/에셋 참조와 다시 대조해야 한다.

## 기존 발견 기록에서 보강한 구현 세부

- Grid는 모든 콘텐츠 변경용 버전과 구조/이동 버전을 분리해 아이템·야생동물 이동이 경로/방 캐시를 불필요하게 무효화하지 않도록 했다.
- 일반전 승리는 원정을 끝내거나 완전 회복시키지 않고 경로 선택으로 복귀한다. 보스 승리만 지역을 종결하며 상처와 스트레스는 시설 회복 루프에 남는다.
- 방 품질은 시설 선택, 기분, 손님, 작업 가능 시간에 영향을 주되 공격 전투 스탯을 직접 올리지 않는다.
- 스킬 생성은 규칙이 희귀도/예산/허용 모듈/진형 마스크를 먼저 결정하고, LLM 출력은 JSON 검증·재시도·취소 revision·영속 요청 키로 통제한다.
- 장비는 공통 인스턴스 런타임이 유일한 권위이며 템플릿이 아니라 장비 인스턴스가 품질, 내구, 탄약, 사격 모드, 투척 회수, 방어층을 소유한다.
- 외부 사건과 보상은 추상 카운터에서 실제 귀환 경계의 포로·야생동물·모집 후보 및 지역 압력으로 전환된 기록이 있다.
- 음식은 일일 추상 차감과 실제 식사를 중복 적용하지 않고, 캐릭터가 실제 식사를 완료할 때만 소비하도록 통합했다.
- 물리 건설 재료는 `Stored → 목적지 예약 Stored → carried → FacilityBuffer` 소유권 단계로 이동하며, 요청 시 창고 바닥에 떨어뜨리는 과거 결함을 제거했다.
- 창고 식별자는 같은 종류 건물 인스턴스가 충돌하지 않도록 건물 정의 ID와 Grid 위치를 포함한다.
- 침입자는 교전 중 이동 코루틴이 매 Grid step 전에 교전 런타임을 확인하며, 전투 연출은 논리 점유를 망가뜨리지 않도록 시각 자식만 움직인다.
- 야생동물 사냥도 공통 전투 해석기를 사용하고, 단순화된 신체 부위 손상과 이동성/회피 저하가 저장된다.
- 500 캐릭터 성능 판단 결과, 현재 작은 격자에서는 요청당 Jobs/Burst가 오히려 비효율적이라 보류하고 메인 스레드 버전 캐시·예산·스케줄링을 선택했다.

## 현재 진행 중인 V18 성격의 기능

- 현재 활성 계획은 시설과 개별 전투 장비의 무한 진화 시스템이다.
- 사용 이력 ledger, 계층형 compaction, 결정론적 해시, 효과/부담 모듈, 촉매, 조율(attunement)을 기반으로 한다.
- 시설은 진화 시 결정론적 3개 후보 중 플레이어가 선택하고, 방은 진화 소유자가 아니라 현재 환경/시너지를 제공한다.
- 장비는 개별 인스턴스가 사용 이력을 축적하고 플레이어가 재련 재료를 고르면 사용 성향에서 진화 방향을 유도한다.
- LLM은 서사 표현만 담당하며 기계적 효과, 해시, 증거, 예산, 진화 자격을 결정하지 못한다.
- 촉매는 물리 경제·작업 지시·운반과 연결되며, 시설 이동은 인스턴스 진화를 보존하지만 파괴 후 재건축은 보존하지 않는 설계다.
- 활성 계획상 모델/저장 기반 단계는 완료, 시설·장비·물리 촉매/작업/UI 통합은 진행 중, 최종 검증은 대기 상태다. 따라서 최종 문서에서 `구현 중`으로 명확히 분류해야 한다.
- 현재 코드에는 이미 bounded usage ledger, 결정론적 계층 compaction, 진화 노드, 방 활성 규칙, 조율 기록, 촉매 계열, 시설/장비 효과 모듈이 추가되었다.
- 시설은 기존 `FacilityEvolutionStateComponent`/건물 상태 모듈을 확장하며, 장비는 `CombatEquipmentInstance` 내부에 진화 상태를 두어 별도 권위 저장소를 만들지 않는다.
- 시설 생산·연구·작업 시간은 활성 진화 modifier를 소비하고, 부담은 방 호환성에 관계없이 유지된다.
- 재련/시설 개조는 실제 촉매·재료 예약, 운반, 시설 buffer, 기존 Craft 작업 루프를 거치며 즉시 완료되지 않는다.
- 촉매 분해, 동등 등급 정제, potency 강화, 150% 금화 교환 경로가 추가되었다.
- 공격, 방패 block, 방어구 피격이 장비 사용/조율 이력에 기록되고, 장비 저장 섹션은 독립 버전 상승 및 구버전 generation 0 복원을 지원한다.

## 현재 저장소 규모

- `Assets/Scripts` 아래 프로젝트 자체 C# 스크립트는 약 825개다. Behavior Designer 런타임/에디터 소스 약 533개는 외부 프레임워크로 분리해 분석해야 한다.
- 프로젝트 에셋 전체에는 `.asset` 약 1,428개, `.png` 313개, `.unity` 27개(복구 씬 포함), `.prefab` 17개, `.asmdef` 18개가 있다.
- 코드 파일 구조에서 AI, 건물, 전투, 아이템, 메타, 공격 원정, 운영, 모집, 연구, 방, 런 흐름, 생존, 합성, 야생동물, UI/프레젠테이션 도메인이 실제로 확인된다.
- 현재 UI 코드에는 시작 파티 준비, 직원 관리/작업 우선순위, 건물 기능 패널, 시설 이전, 장비 제작, 시설/장비 진화, 연구 트리, 방어, 포로, 원정, 운영, 상점, 창고, 생태 보기, 정확한 월드 클릭 선택이 존재한다.
- EditMode/PlayMode 검증 코드가 각 도메인과 UI에 다수 함께 존재해, 기능 연결 여부를 검증한 흔적이 상당히 강하다.

## 프로젝트 구성과 실행 흐름

- Unity 버전은 `6000.3.8f1`, URP 2D 17.3, Input System 1.18, VContainer 1.19를 사용한다. Behavior Designer도 프로젝트에 포함되어 있다.
- 빌드 씬 순서는 `TitleScene → StartPreparationScene → GameplayScene → SampleScene`이다. `CharacterAiTestScene`은 빌드 목록 밖의 테스트 씬이다.
- 자체 코드의 가장 큰 영역은 Character(151), Infrastructure(75), UI(57), Buildings(50), Combat(38), Offense(33), Invasion(31), Economy(27), FacilityEvolution(24), Items/Operation(각 22), Survival(21)이다.
- 도메인 모델 어셈블리는 AI, Buildings, Characters, Combat, Evolution, Invasion, Items, Offense, Rooms, Survival, Wildlife, Work, World로 나뉘며 Foundation/Infrastructure/Presentation 경계가 별도로 있다.
- 기존 `docs/game-design`에는 개요, 플레이어 경험, 던전 구조, 경제/시간, 시설/합성, 인벤토리/물류, 직원/행위자, 몬스터 손님, 침입, 원정, 메타 진행, 런 변수/이벤트 등의 기획 문서가 이미 있다.
- `docs/implementation-reports`에는 P1~P3 기능별 구현 보고서, 구현 근거 매트릭스, 파일 맵, 검증 감사가 있어 코드 분석과 교차 검증할 수 있다.

## 기존 게임 디자인 문서에서 확인한 기획 정체성

- 장르는 `몬스터 사회의 던전 운영/경영 + 방어 + 외부 원정 + 로그라이트 메타 진행`의 결합으로 기획되어 있다.
- 플레이어는 인간 모험가가 아니라 몬스터 던전의 사장으로, 몬스터 손님과 직원을 먹이고 쉬게 하고 즐기게 하면서 동시에 모험가 침입을 버틴다.
- 핵심 판타지는 고정 정답 배치를 찾는 것이 아니라, 매 런의 사장 종족·시설·합성 계보·직원/방어 인력·런 변수·외부 보상을 조합해 “이번 던전이 왜 오래 버티는가”를 만드는 것이다.
- 관리 루프는 손님 방문 → 욕구 충족 시설 이용 → 직원 운영 → 매출/재고 변화 → 시설 건설·확장·합성 → 더 강한 손님/침입 대응으로 설계되어 있다.
- 방어 루프는 경고 → 배치/동선/방어 시설/인력 준비 → 자동 교전 관찰 → 피해와 원인 기록 → 수리/재배치/강화로 이어진다.
- 플레이어 경험 원칙은 문제 발생 → 감정/알림 → 상세 기록 → 원인 정보 축적 → 해결 방향 추론 → 다음 선택 실행이다. UI가 답을 직접 지시하기보다 관찰 근거를 제공하려는 기획이다.
- 캐릭터는 기본적으로 AI가 자율 행동하고, 플레이어의 직접 명령은 순간 조작보다 우선 목표 지정에 가깝다.
- 런 종료의 원안은 침입자가 사장 방에 도달해 최종 교전 후 사장이 사망하는 것이며, 런 성과로 메타 강화가 열린다.
- 기존 TODO에는 복도 부착형 함정, 방 안 다중 독립 시설, 문 잠금/함정/원거리 방어, 전투 경로 리플레이, 전 시설 5단계 계보, 다종 침입자 유형, 깊은 생산 체계, 멀티 던전 실시간 시스템, 전체 원정 월드맵, 단계형 시설 요구가 장기 후보로 남아 있다.

## 기존 구현 근거와 QA에서 확인한 상태

- P1~P3 구현 근거 매트릭스는 AI 계획, 초기 시설, 손님 AI, 캐릭터/종족/사장, 작업 우선순위·지정·근무, 재고/공급/정산/피드백, 침입/방어/전투 보고, 상점/연구/합성/시설 진화/도감, 단골/모집/불만/반란, 런 변수/종료/메타 진행, 월드맵/원정/보상을 각각 디버그 시나리오와 연결한다.
- 오래된 통합 기록은 29개 스위트 29 PASS였고, 이후 루트 계획에는 더 넓은 V17 검증까지 축적되어 있다. 최종 문서에서는 검증 날짜와 현재 코드 상태가 다를 수 있음을 명시한다.
- QA 기록에는 실제 씬에서 손님 방문, 상점 재고 이동, 침입 생성·시설 피해, 모집, 직원 반란/격리/제압, 원정과 보상, 시설 진화, 건설 UI, 정확한 Input System 포인터 배치, 대화/감정 bubble, 사장 사망과 메타 결과까지 확인한 흔적이 있다.
- 마지막 기존 QA 결론은 “구현 기능 카탈로그와 자동 release 기준은 확인됨”이지만, 새 유저 관점의 이해도·페이싱·보상 간격·재플레이 동기는 사람의 클린 프로필 첫 플레이가 남은 최종 게이트라고 평가했다.
- 따라서 기술 구현량은 매우 크지만, 기획 완성도 문서에서는 `시스템 구현`과 `콘텐츠 밀도/온보딩/밸런스 검증`을 별개로 판정해야 한다.

## 런타임 조립 구조

- `DungeonRuntimeLifetimeScope`가 Gameplay 씬의 composition root다.
- 등록 순서는 Foundation/Work → Combat/Invasion → World Simulation → Save → Core Infrastructure → Facility → Character → AI/Rooms → Progression/Offense → Presentation으로 나뉜다.
- 씬에서 단 하나만 있어야 하는 `OwnerCommandController`와 `RegularCustomerRuntime`은 `SingleRequired`로 강제하여 중복/누락을 조용히 허용하지 않는다.
- 실제 씬 참조에는 UI, 정산, 알림, 런 변수, Grid/건설, 카메라, 사장 선택, 건물 정보, 월드맵/원정/보상, 침입 위협/디렉터/전투 보고, 시설 진화/합성/도감, 로컬 LLM, 평판, 직원 불만, 스포너, AI 스케줄러, 사장 런 관리자, 일일 상점, 연구, 메타 진행, 야생 서식지/외부 구역이 포함된다.
- Build callback은 씬 계층 전체를 DI하고 아이템 더미 패널, 야생동물 패널, 단골 손님, 외부 활동, 야생동물, 식사 런타임을 즉시 resolve해 실제 실행을 보장한다.
- 입력은 Input System UI module을 보장하고 legacy `StandaloneInputModule`은 비활성화한다.

## 런/원정 상태 전이 코드

- 런 phase는 1~3일 Preparation, 4~6일 Growth, 7~9일 Escalation, 10일 이후 EndlessDefense다.
- 10일마다 보스 침입 cycle이 예약되며 cycle마다 보스 체력/피해는 `+35%`, 위협 상승은 `+20%` 누적된다. 방어 실패나 사장 사망은 Defeat다.
- 방어 보스는 런을 끝내는 승리 조건이 아니다. 승리는 외부 원정 마지막 `truth_core`에서 `OffenseTruthRevealedEvent`가 발생할 때만 완료된다.
- 난이도는 Easy/Normal/Hard이며 외부 원정 적 능력치에 Easy `0.8x`, Hard 체력 `1.25x`, 공격 `1.2x`, 선제/속도 `1.1x`가 적용된다.
- 원정 적 캠페인은 6단계로 농장 집행관 → 상단 경비/석궁병 → 무기고 경비/대장 → 비전 수호기/마나 이상체 → Slime/Orc/Vampire 경쟁 던전 파티 → 봉인 수호자/진실 감시자로 구성된다.
- 일반 경로 전투는 node 깊이에 따라 적 수와 위험도가 줄고, boss node는 전체 편성을 사용한다. 지역 인력/무장/물류/정보 압력 약화가 적 수·체력·공격·준비도를 낮춘다.
- 전투는 사망/다운 시 진형을 앞으로 압축하며, 공격은 무기 사거리/정확도/진형 거리, guard/vulnerability, 신체 부위, 출혈, 제압, 방패/엄폐/방어구 내구를 반영한다.
- 런 결과는 생존 시간, 운영일, 정산 횟수, 방어한 침입, 최대 위협, 최종 위협, 최초 시설/recipe 발견, 원정 성공, 난이도, 승패를 메타 결과 snapshot으로 만든다.

## 운영·생산·연구 루프 코드

- 운영일 정산 보고서는 매출, 방문 수/평균 만족, 시설별 매출, 종족별 방문, 소비 재고, 창고 재고, 재입고 실패, 손상 시설/수리 예상, 사건/알림, 직원 근무·비번·피로·기분, 유지비, 급여, 이전 부채, 납부/미납, 마감 잔고, 연속 적자를 집계한다.
- 운영일 시작/종료 event와 시설 방문/매출/재고 소비/절도/재입고 event가 정산 ledger로 모이며, 보고 이력은 20개로 제한된다.
- 생산은 bill별 RepeatCount 또는 목표 재고 모드를 지원하고, 중단·작업 진행·허용 재료/작업자·최소 reserve·목표 stock을 저장한다.
- 생산 입력은 작업 시설 목적지로 실물 배송을 요청하고, 재료가 도착하지 않으면 `WaitingForMaterials`; 도착 후 Ready/InProgress로 전환한다. 부족 시 운반 작업자 재계획을 요청한다.
- recipe가 요구하는 연구가 완료되지 않으면 생산이 차단된다.
- 연구는 프로젝트 queue, active 항목, 순서 이동, 일시 중단 사유, 개별 진행도, 완료 집합을 가지고 저장/복원한다.

## 작업/AI 실행 구조

- 내장 작업 유형은 운영, 보충, 건설, 수리, 청소, 연구, 경비, 접대, 구조, 휴식, 제작, 운반, 사냥, 도축, 물 긷기, 조리, 치료, 연료 보충, 간수, 공연, 채집, 파종, 수확, 벌목, 채석, 동물 돌봄, 대형 프로젝트 총 27종이다.
- 건설 작업 상태는 `WaitingForMaterials → Ready → InProgress → Completed`이며 Blocked/Cancelled도 있다.
- 건설 현장은 건물별 필요 작업량과 재료 category를 가지며, 실물 자원 목적지 ID로 배송을 요청한다. 고아가 된 현장 주문은 취소·환급하고, 준비됐지만 작업자가 없는 현장은 주기적으로 강제 재계획한다.
- 건설 작업은 worker 영속 ID를 예약하고 진행률을 누적하며 완료 시 실제 건물로 교체한다. 취소 시 배송 중/버퍼/저장 재료를 목적지 예약에서 해제하거나 제거할 수 있다.
- 캐릭터 AI 결정 pipeline은 `critical → 결핍 붕괴 → 잠금 행동 → 계속 가능한 현재 행동 → macro goal → emergency → routine utility → idle` 계층을 가진다.
- AI는 안전한 긴급 욕구가 현재 행동을 중단할지 판정하고, job giver 후보를 계층별로 점수화한다. 실행 실패는 no grid/no path/path deferred/destroyed/cooldown/no score 등 구체 이유로 남긴다.
- macro 행동에는 불평, 특정 시설 회피, 던전 퇴장, 기물 파손이 있으며, 결핍/낮은 기분/사회 기억이 단순 대기 대신 행동으로 이어진다.
- 목적지는 예약되고, 이동 중 급한 재경로는 urgent 경로 검색을 사용하며, 행동 종료/실패 시 예약을 해제한다.

## 생존·포로·서커스·외부·방 환경

- 결핍 런타임은 안전한 긴급 구호, 절박한 물 마시기, 감염/정신 불안 부담, 붕괴 유형, 비살상 제압, 금기 행동/목격자 기억, 이동/작업 속도 패널티를 처리하고 상세 진단 카운터까지 제공한다.
- 서커스 공연 상태는 구성 → 참가자 호송 → 관객 입장 → 공연 → 정산 → 청소/치료 → 완료/취소다.
- 공연은 포로/야생동물/전투/공개 잔혹성, 사고 위험, 만족도, 명성, 입장료/매출, 공연장 bonus, 오염, 목격자 기분, 도박 변동, 치료/청소, 배신 검사를 가진다.
- 공연 치사 정책은 다운 시 중단, 사고 허용, 죽을 때까지 싸움, 지정 처형 4종이다.
- 포획 야생동물은 운송 대기 → 운송 → 우리 → 공연 이동/공연/복귀 → 방생/탈출 상태를 가지며 먹이·물 배송, 질병 위험, 길들이기, 우리 수용량이 있다.
- 외부 구역은 입구, drop zone, 접대 지점, 경비 초소, 순찰 지점, 야외 휴식, 원정 집결, 사건 지점 8종이다.
- 외부 구역은 청결, 손상, 순찰/접대 준비도, 대기 방문객, 첫인상 bonus, 완료 작업을 축적하고 외부 사건 및 원정 출발/귀환 이동을 저장한다.
- 방 환경 상태는 사용 가능/열린 경계/문 없음/자체 완결이며, 면적·빈 공간·문/벽·역할·고급감·위생·넓이·아름다움·청결·인상·보호·온도·환기·조명을 계산한다.
- 방 점수는 시설 선호와 운영/연구/보충/경비/제작 작업 시간에 최대 약 ±15% 영향을 준다. 구조/시설/오염 버전 기반 cache를 사용한다.

## 진화 모듈 1차 코드 확인

- 시설 진화의 기본 방향은 생산, 서비스, 연구, 생존, 방어, 오락, 방 시너지, 위험 과부하 8종이다.
- 장비 진화의 기본 방향은 근접, 원거리, 방어, 생존, 위험 5종이다.
- 각 방향은 이득과 부담이 반드시 짝을 이룬다. 예: 생산량 증가/연료 증가, 연구량 증가/열 증가, 방 시너지/정비 부담, 근접 피해/중량, 원거리 명중/재장전, 방어/이동 저하.
- 방 시너지 모듈은 청결 40, 공간 35 이상에서만 benefit이 활성화되지만 burden은 별도 유지되는 구조다.

## 현재 진화 구현의 구체 규칙

- 사용 ledger의 현재 세대 raw event는 128개로 제한되고, 이전 세대는 level·세대 범위·event 수·총량·해시·핵심 사건·참가자·태그를 가진 compacted segment로 보존된다.
- 시설 후보는 주 역할, 방 시너지, 위험 촉매 3종이며, 숙련 요구치는 `120 + 60 × 현재 세대`다.
- 시설 개조는 binding 재료와 촉매, 작업량, 목적지 buffer를 가진 작업 주문이다. 재보정도 별도 주문으로 보존된다.
- 시설 이전은 해체 → package 대기 → 재설치 → blocked 상태이며, 원래 영속 ID와 진화 이력을 보존한다. 해체 작업량은 기본 건설량 25%, 재설치는 50%다.
- 장비 진화 방향은 균형, 근접, 원거리, 명중, 처형, 차단, 보호, 생존 8종이며 재련 주문은 재료 대기/준비/진행/완료/취소/막힘 상태를 가진다.
- 조율은 소유자 영속 ID별 affinity, 달성 tier, 시작 세대, root/history node를 기록한다.
- 진화 서사 요청은 target, node, parent, effect, history hash, 세대, effect budget, 시도 수, 완료/취소, 증거/참가자/태그를 저장한다.

## 런 변화와 메타 성장 콘텐츠

- 운영 런 변수 9종: Slime 집단 방문, Orc 연회, Vampire 야간 방문, 식량 배송 지연, 잡화 할인, 마나 재고 과잉, 방문 상인, 방어 시설 할인, 설계도 소문.
- 침입 런 변수 5종: 정찰 흔적, 기습, 무장 침입자, 약탈 우선, 지친 침입자. 패턴, 집중 시간, 재경로, 시설 피해 주기, 최종 피해를 바꾼다.
