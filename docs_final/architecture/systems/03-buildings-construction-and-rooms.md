# 건물 배치, 건설과 방 판정

## 구현 개요

건물 정의는 크기, 배치 규칙과 조립된 능력을 제공하고, `GridBuildingPlacementService`가 실제 점유 등록을 조정한다. 일반 건설은 완성 건물을 즉시 두지 않는다. 공사 현장을 건설 레이어에 놓고 작업 주문을 만든 뒤, 완료 콜백이 성공하면 현장을 제거하고 완성 건물을 등록한다.

```mermaid
flowchart LR
    D[BuildingSO] --> V[배치 검증]
    V --> S[ConstructionSite 등록]
    S --> W[건설 작업 주문]
    W --> M[재료와 WU 투입]
    M --> C[완료 콜백]
    C --> B[완성 건물 등록]
    B --> R[방 구조 버전 변경]
    R --> L[RoomLayout 재계산]
```

## 공사 수명주기

공사 현장은 대상 건물 정의, 연결된 작업 주문 ID, 전달 재료, 작업자 슬롯, 예약과 안전 판정 상태를 가진다. 작업 주문 생성에 실패하면 현장 배치를 되돌린다. 완료 콜백이 완성 건물 배치에 성공한 뒤에만 현장을 제거한다. 취소는 주문 취소와 전달 재료 환불을 먼저 요청한다.

이 순서는 화면 오브젝트를 먼저 바꾸고 경제 상태를 나중에 맞추는 방식보다 실패 복구가 분명하다. 공사 현장과 완성 건물은 서로 다른 그리드 점유 객체다.

## 방 판정

방 판정은 구조 스냅샷에서 연결된 내부 셀을 flood fill로 모은다. 경계와 문, 가구의 역할을 종합해 `RoomInstance`와 `RoomLayout`을 만든다. 레이아웃에는 계산에 사용한 구조 버전이 함께 들어간다. 환경, 서비스 가능 여부와 방 경험 평가는 이 레이아웃 스냅샷을 입력으로 받는 도메인 계산이다.

복원은 방 ID 중복과 한 셀의 중복 점유를 검사한 뒤 분리된 후보 레이아웃을 만든다. 라이브 레이아웃은 후보가 유효할 때만 교체된다.

## 적용된 최적화와 비용 통제

| 구현 | 실제 효과 | 한계 |
|---|---|---|
| 배치 전 전체 셀 검증 | 중간까지만 등록된 건물 방지 | 큰 건물은 모든 셀을 검사한다 |
| 공사 안전 결과의 버전 캐시 | 같은 구조, 건물 상태, 작업자 위치에서 재계산 생략 | 셋 중 하나가 바뀌면 다시 계산한다 |
| 작업자 ID별 예약과 고정 슬롯 | 병렬 작업 충돌을 직접 조회 | 만료 예약 정리가 필요하다 |
| 구조 버전이 든 방 레이아웃 | 구조가 그대로면 공간 해석 재사용 | 현재 구현의 재계산 범위가 국소적이라고 단정할 수 없다 |
| 초기 배치의 위치 인덱스 | 같은 셀의 중복 경계를 빠르게 정리 | 초기화와 확장 시 컬렉션 생성 비용이 있다 |
| 분리된 복원 후보 | 잘못된 방 데이터가 라이브 상태를 훼손하지 않는다 | 복원 시 후보 컬렉션을 새로 만든다 |

## 적용 사례

두 칸짜리 제련소를 추가한다고 가정한다. 기존 배치 능력과 건물 능력만 조합하면 정의 자산에서 크기, 생산 능력, 전력 수요와 작업 완료 효과를 설정한다. 배치 서비스는 두 셀 모두를 먼저 검사하고 공사 현장을 만든다. 완공 후 건물의 벽 성질이 방 경계에 영향을 주면 구조 버전이 변하고 방 레이아웃이 갱신된다. 제련소 전용 배치 관리자나 전용 방 검출기를 만들 필요는 없다.

## 비용과 한계

건물 능력 조합은 성숙했지만, 배치 서비스는 공사, 즉시 배치, 파괴, 초기 레이아웃과 문 규칙을 함께 다루는 큰 조정자다. 방 flood fill도 구조 변경 때 전체 내부 영역을 다시 볼 가능성이 있다. 구조 변경이 잦은 대형 맵에서는 재계산 범위와 할당량을 별도로 측정해야 한다.

이 문서는 시설이 배치되고 방으로 판정되는 시점까지 다룬다. 설치된 시설을 실물 재료로 재편하는 합성과, 방 맥락 및 사용 이력을 다음 계보로 넘기는 절차는 [시설 합성과 사용 기반 진화](19-facility-synthesis-and-use-based-evolution.md)에서 이어서 설명한다.
