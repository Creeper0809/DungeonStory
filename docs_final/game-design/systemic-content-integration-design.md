## 1. 목적

DungeonStory의 생산·물류·주민 체계는 실제 물건, 작업량, 공간, 시설, 운반과 저장 권위를 사용한다. 반면 일부 사건형 콘텐츠는 풍부한 의도 설명을 가지고 있어도 실제 정의에서는 다음처럼 축약될 수 있다.

```text
조건 확인
→ 선택
→ 기분·관계·평판·위협·작업 지연 수치 즉시 변경
→ 종료
```

이 문서는 사건형 콘텐츠를 단순한 수치 변화에서 다음 구조로 확장하는 공통 원칙을 정의한다.

```text
실제 세계 상태에서 발생 원인 포착
→ 구체적인 대상·참여자·시설·물건을 사건 문맥으로 고정
→ 선택마다 서로 다른 실제 행동·작업·예약·위험 생성
→ 담당 시스템이 시간의 흐름에 따라 실행
→ 완료 기록과 실제 결과로 성공·부분 성공·실패 판정
→ 최종 수치 효과 적용
→ 인물·가구·시설·세력·지역·계보에 압축 가능한 흔적 저장
→ 다른 시스템이 그 흔적에 반응
```

목표는 기존 시스템이 제공하는 발생 조건, 요구 사항, 행동, 판정과 후속 반응을 조립해 콘텐츠가 실제 게임 상태를 바꾸게 하는 데 있다. 새 콘텐츠를 추가할 때마다 중앙 실행부에 전용 예외를 만들지 않아도 되어야 한다.

## 2. 핵심 판정

### 2.1 연결과 맞물림은 다르다

다음은 연결되어 있으나 상호작용의 깊이가 부족한 상태다.

```text
축제 성공 → 기분 +5
세력 요구 거절 → 원한 +8
눈보라 발생 → 작업 지연 3일
```

다음은 맞물린 상태다.

```text
눈보라
→ 실제 외부 운반 경로의 이동 비용과 시야 악화
→ 예정된 원정·수입 화물 지연
→ 연료 도착 실패로 특정 난방망 압박
→ 저온 노출 주민과 동결 배관 발생
→ 플레이어가 제설, 우회 수송, 비축 방출 중 선택
→ 실제 복구 작업과 물자 소비
→ 복구되지 않은 시설·환자의 결과가 사건 종료 뒤에도 남음
```

공통 변수를 읽거나 쓰는 것만으로는 맞물림 완료로 세지 않는다. 한 시스템의 구체적인 상태가 다른 시스템의 가능한 행동, 비용, 위험 또는 미래 후보를 바꿔야 한다.

### 2.2 최종 수치 효과는 유지한다

기분, 관계, 평판, 원한, 의무, 위협, 야망 진행 같은 수치 효과는 유효하다. 다만 중요 콘텐츠에서 이것만으로 전체 선택을 표현하지 않는다.

- 수치 효과는 실제 과정의 **최종 결과**다.
- 실제 과정 없이 수치만 적용해도 되는 것은 자동 소사건과 명시적인 추상 정책 결과로 제한한다.
- 작업, 이동, 치료, 수리, 구금, 조사, 협상, 봉헌과 물자 이전처럼 세계에서 수행 가능한 행동을 작업 지연, 세계 상태, 건강이나 금액 수치 하나로 대체하지 않는다.

## 3. 콘텐츠 결합 등급

| 등급 | 정의 | 허용 예 | 완료 판정 |
|---|---|---|---|
| `C0 장식` | 텍스트만 다르고 상태 변화 없음 | 도감 설명 | 사건·계약·연구 콘텐츠로 집계하지 않음 |
| `C1 수치` | 범용 수치 효과만 즉시 적용 | 자동 생일 기록, 경미한 분위기 변화 | 자동 소사건에만 허용 |
| `C2 실물 접촉` | 실제 물건·시설·참여자를 요구하거나 소비하지만 결과는 즉시 수치 | 간단한 문화 관습, 소규모 봉헌 | 반복 일상·소규모 요청에 허용 |
| `C3 과정 결합` | 선택이 실제 작업·예약·시설 상태·의료·전투·이동 과정을 생성 | 수리, 치료, 조사, 격리, 축제 준비 | 중요 사건의 최소 등급 |
| `C4 양방향 결합` | 실제 원인에서 발생하고 과정 결과가 다른 시스템의 미래 행동을 변경 | 오염 사고가 질병·서비스·세력 후속 사건을 변화 | 세력 장, 계절 대형 사건, 세대 핵심 사건의 최소 등급 |
| `C5 구조 변화` | 장기 정책·공급망·가문·지역·세력 상태를 바꾸어 이후 전략 경로를 분기 | 세력 동맹 공급망, 가문 기술 계승, 지역 통제 | 장기 서사·이정표·시대 전환에 요구 |

등급은 효과 개수로 계산하지 않는다. 기분, 금액과 세력 호의를 한꺼번에 바꾸더라도 실제 과정과 후속 반응이 없으면 `C1`이다.

### 3.1 콘텐츠 종류별 최소 등급

| 콘텐츠 | 최소 등급 | 추가 조건 |
|---|---:|---|
| 자동 생애 기록 | C1 | 실제 발생 근거와 참여자의 고유 식별자가 있어야 함 |
| 문화 일상 관습 | C2 | 실제 물품 또는 시설·시간·참여 중 둘 이상 사용 |
| 선택형 생애 사건 | C3 | 선택지 중 적어도 하나는 실제 과정, 모든 선택은 흔적 저장 |
| 손님 요청 | C3 | 서비스 수행 또는 물자 인계 기록으로 성공 판정 |
| 서비스 사고 | C3 | 모든 대응이 서로 다른 실제 행동을 가짐 |

| 세력 계약 | C4 | 실제 이전·호위·작업·전투 결과와 세력 측 후속 상태 |
| 세력 장 | C4 | 자기 세력과 교차 세력 또는 내부 사회 중 하나에 장기 반응 |
| 연구 분기 | C4 | 새 해금 외에 대안 경로의 기회비용과 운영 방식 변화 |
| 방어·원정 핵심 사건 | C4 | 실제 파티·장비·보급·지역·포로 상태를 양방향 사용 |
| 세대·계보 핵심 사건 | C5 | 다음 세대의 가능한 행동·숙련·의무·자산 중 하나를 변경 |
| 이정표 후속 압력 | C5 | 보상뿐 아니라 세계 규칙 또는 장기 부담을 변경 |

## 4. 공통 콘텐츠 통합 계약

모든 C3 이상 콘텐츠는 아래 열을 가진 통합 기록을 작성한다.

| 계약 | 기록할 내용 |
|---|---|
| 정의 | 안정 식별자, 콘텐츠 종류, 작성 버전, 결합 등급 |
| 발생 근거 | 어떤 실제 상태 변화나 사건이 후보를 생성하는지 |
| 원인 증거 | 실패한 주문, 손상 시설, 환자, 관계 기억, 계약, 날씨 전선처럼 원인을 재검증할 수 있는 참조 |
| 대상 고정 | 참여자·가구·시설·아이템 묶음·지역·세력·작업 주문의 고유 식별자 |
| 선택 전제 | 물건, 시설 기능, 연구, 정책, 숙련, 관계, 시간, 공간, 위험 |
| 선택 행동 | 각 선택이 생성하는 실제 행동 또는 작업 |
| 예약과 인계 | 비용의 예약 주체, 물건 이동, 반환·취소·부분 실패 규칙 |
| 진행 | 즉시, 작업량, 다단계, 기한, 일일 갱신 중 어떤 방식인지 |
| 해결 근거 | 어떤 실제 완료·부상·소비·이동·수리·전투 결과로 판정하는지 |
| 최종 효과 | 과정 뒤 적용되는 기분·관계·평판·위협·보상 |
| 영속 흔적 | 인물·가구·시설·세력·지역·계보 중 어디에 무엇을 남기는지 |
| 후속 반응 | 어떤 미래 시스템이 흔적 또는 변경된 실제 상태를 읽는지 |
| 회복·재진입 | 실패 이후의 수리, 재협상, 재도전, 손실 제한 방식 |
| 재현 규칙 | 후보·참여자·판정·보상의 난수 기준과 저장·복원 불변조건 |
| 감사 | 발생 근거, 상태의 책임, 후속 반응, 저장, 관찰과 검증 증거 |

### 4.1 발생 근거 규칙

- 설명문과 맞는 실제 원인이 없으면 중요 사건을 발생시키지 않는다.
- `도제의 큰 실수`는 아무 도제에게 무작위 발생하지 않는다. 실제 실패·저품질·재료 손실 주문과 기여한 도제를 참조한다.
- `금기 음식 제공`은 같은 문화의 손님이 있다는 이유만으로 발생하지 않는다. 실제 제공 음식, 손님 문화, 금기 판정과 서비스 영수증이 있어야 한다.
- `시설 파괴 공작`은 손상된 시설 인스턴스, 침입 경로 또는 조사 가능한 흔적을 가진다.
- 사건 후보가 선택되기 전에 원인 증거가 사라지면 사건을 조용히 다른 내용으로 바꾸지 않는다. 후보를 무효화하고 사유를 기록한다.

### 4.2 대상 고정 규칙

발생한 사건은 정의 식별자만 저장하지 않는다. 발생 시점에 아래 중 필요한 대상을 고정한다.

- 주·보조 참여자의 고유 식별자
- 가구·보호자·가문·멘토 관계의 식별자
- 시설·방·배관·전력망·지역의 식별자
- 원인이 된 작업 주문·생산 묶음·서비스·전투·원정의 식별자
- 실제 물품 묶음·고유 장비·유물의 식별자
- 관련 세력과 교차 세력의 식별자
- 발생 절대일, 기한과 난수 기준값

대상이 사망·철거·소실되면 이름이 비슷한 다른 대상을 자동 대체하지 않는다. 선택을 무효화하거나 설계된 상실 분기로 해결한다.

### 4.3 선택 행동 규칙

선택지는 실제로 수행하는 행동의 차이로 구분한다.

예시:

```text
격리한다
→ 방 접근 정책 변경
→ 환자·노출자 이동 작업
→ 식량·의약품 공급 예약
→ 격리 종료 조건 생성

치료한다
→ 진료 우선순위 변경
→ 약품·병상 예약
→ 의료 작업 주문
→ 실제 치료 결과로 판정

은폐한다
→ 서비스 기록 은폐 흔적
→ 즉시 영업 중단 회피
→ 미해결 오염원 유지
→ 발견 시 가중된 세력 원한 후보 생성
```

선택지 제목을 지웠을 때 수행 과정이 같으면 서로 다른 선택으로 세지 않는다.

### 4.4 실행과 판정 규칙

- C3 이상 선택은 선택 순간 성공한 것으로 처리하지 않는다.
- 작업·수리·치료·이동·협상·전투가 필요하면 진행 중 사건 인스턴스를 만든다.
- 성공은 실제 소비·완료·도착·생존·수리·관계 변경 기록으로 판정한다.
- 기한 종료 시 `성공/부분 성공/실패/원인 소멸/대상 상실`을 구분한다.
- 취소·저장·재개방으로 비용, 참여자, 판정 또는 보상을 재굴림하지 않는다.
- 하나의 선택이 여러 시스템을 바꾸면 실행 전에 모든 조건과 예약을 확인한다. 일부만 반영된 채 멈출 수 있는 행동은 완료 순서와 실패 시 보상 절차를 별도로 정한다.

### 4.5 흔적과 역반응 규칙

영속 흔적은 해결 여부 한 줄로 끝내지 않는다. 콘텐츠 성격에 맞는 최소 정보만 압축해 저장한다.

- 흔적, 콘텐츠 정의와 결과의 고유 식별자
- 발생한 절대일
- 주요 인물, 가구, 시설, 세력과 지역
- 결과의 성격
- 심각도 또는 판정의 확실성
- 원인이 된 완료 기록

흔적은 다음 중 하나 이상을 실제로 바꿔야 한다.

- 이후 사건 후보 가중치·금지·재발 방식
- 관계 기억과 가구·보호자 결정
- 세력 계약 종류, 가격, 지원, 보복 또는 침입 구성
- 시설 정책, 접근권, 정비 우선순위 또는 위험
- 원정 지역 정보, 목표, 경로, 지원 또는 적 준비도
- 교육·멘토·상속·가문 의무·계보 장비의 다음 세대 상태
- 이정표와 장기 세계 압력

오래된 흔적은 무한 보존하지 않는다. 최근 상세 기록과 누적 분류·횟수·최대 심각도·마지막 발생일로 압축한다.

## 5. 콘텐츠 조립 모델

새 콘텐츠는 중앙 실행부에 콘텐츠별 예외를 추가하지 않고 등록된 역할을 조립한다.

### 5.1 조립 역할

| 역할 | 예시 |
|---|---|
| 발생 조건 | 실제 생산 실패, 서비스 완료 기록, 저온 배관, 사망, 계약 만기, 원정 정찰 |
| 대상 고정 | 참여자, 대상 시설, 실제 물품 묶음, 지역과 세력 고정 |
| 요구 검사 | 기존 아이템·시설·연구·인물·세력·세계 지표 검사 |
| 실제 행동 | 작업 주문, 물자 이전, 치료, 수리, 격리, 구금, 조사, 정책 변경, 원정 목표 생성 |
| 결과 판정 | 완료 기록을 성공·부분 성공·실패로 판정 |
| 최종 수치 변화 | 실제 과정 뒤 기분·관계·평판·위협과 같은 결과 적용 |
| 흔적 기록 | 인물·가구·시설·세력·지역·계보에 흔적 기록 |
| 후속 반응 | 흔적 또는 실제 상태를 읽어 미래 후보·계약·주민 판단·압력을 변경 |

### 5.2 상태 권위

- 콘텐츠 정의에는 변하지 않는 규칙과 조립 역할만 둔다.
- 진행 중 사건은 선택, 기한, 고정된 대상, 예약과 단계 상태의 유일한 쓰기 권위다.
- 물건·시설·건강·관계·세력·원정 상태는 각 기존 시스템이 계속 소유한다.
- 사건 상태는 다른 시스템의 상태를 복사하지 않고 대상 식별자와 완료 기록만 보관한다.
- 화면 표시, 알림, 언어 모델이 만든 서사 문구와 결과 설명은 게임 상태의 권위가 아니다.

### 5.3 실패 정책

- 등록되지 않은 조립 역할, 후속 처리자가 없는 행동, 알 수 없는 흔적과 반응 식별자는 제작 단계에서 오류로 드러낸다.
- 실행 중 대상이 사라졌을 때 임의의 다른 대상이나 범용 수치 효과로 대체하지 않는다.
- 부분 실패를 허용하려면 정의에 보상 행동과 남은 예약의 처리 규칙이 있어야 한다.
- 이미 끝난 물리 작업을 되돌릴 수 없는 상태에서 최종 결과 적용이 중단되면, 완료 기록을 바탕으로 결과를 정확히 한 번 이어서 적용한다.

## 6. 콘텐츠 종류별 설계

### 6.1 선택형 생애 사건

생애 사건은 실제 경력·가구·관계·질병·작업·원정 이력에서 발생한다.

필수:

- 구체적인 주 참여자와 발생 근거
- 인물의 야망·특성·문화·관계 중 하나가 선택 비용 또는 결과를 바꿈
- 선택 결과가 즉시 XP만 지급하지 않고 실제 교육·작업·관계·자산·원정 과정 중 하나를 생성
- 최소 하나의 인물·가구·계보 흔적
- 동일 인물 또는 후계자의 미래 사건에서 역참조

자동 성장 기록은 C1을 허용하지만 실제 나이 변화, 첫 완료 작업, 식사 참여, 묘비 방문처럼 종류가 분명한 사건에서 발생해야 한다.

### 6.2 문화 관습과 축제

문화 콘텐츠는 생활 방식의 비용과 협력을 만든다.

- 준비 단계: 물품·시설·공간·담당자·시간 예약
- 참여 단계: 실제 참가자, 문화 적합성, 건강, 근무표, 안전 상태
- 진행 단계: 서비스·의식·공연·식사·추모 행동 수행
- 결산 단계: 공급 완성도, 참가율, 사고, 문화 혼합, 애도 대상에 따라 결과 판정
- 흔적: 참가자 문화 참여일, 관계 기억, 추모 전환, 세력 공동 기념일, 다음 축제 기대

성공 결과를 모든 축제에서 동일한 기간의 기분 보정으로 맞추지 않는다. 축제마다 최소 하나의 고유한 장기 회수 경로가 필요하다.

### 6.3 손님 요청과 서비스 사고

손님 요청은 아이템과 시설이 존재하는지만 보지 않고 실제 서비스를 수행해야 한다.

- 객실 사용, 식사 제공, 치료, 검역, 공연, 거래, 연구, 장비 정비 영수증
- 대기 시간, 품질, 오염, 문화 적합성, 부상과 안전 결과
- 요청 물자의 실제 이동과 인계
- 성공·부분 성공·거절·운영 실패 구분

서비스 사고는 원인이 된 서비스 완료 기록과 실제 피해자를 가져야 한다. 대응은 봉쇄, 치료, 수사, 협상, 보상, 체포와 은폐 가운데 서로 다른 행동을 조합해야 한다.

### 6.4 계절 세계 사건

사건이 영향을 준다고 적은 시스템은 실제 실행과 후속 반응에서도 연결되어야 한다.

각 사건은 다음 역할을 채운다.

1. 원인이 생긴 시스템
2. 첫 번째로 실제 영향을 받는 시스템
3. 두 번째로 실제 영향을 받는 시스템
4. 플레이어가 복구하거나 활용하는 시스템
5. 종료 후 잔여 상태 또는 기회

지속 사건은 시작·일일·종료 시점의 수치 변화보다 세계에 남아 있는 실제 조건을 우선한다. 각 시스템은 현재 조건을 읽어 자기 규칙으로 반응하고, 사건이 끝나도 이미 생긴 손상·환자·지연 화물은 자동으로 복구하지 않는다.

### 6.5 세력 장과 계약

세력은 요구, 평판, 계약과 반응을 보존하는 외부 사회 상태다.

세력별 최소 장기 상태:

- 공급 안정성
- 안보·군사 압력
- 내부 결속 또는 위기
- 던전에 대한 우호·원한·의무
- 경쟁 세력 관계
- 던전이 만든 핵심 선택 흔적

계약 결과는 세력 상태를 바꾸고, 바뀐 세력 상태는 다음 계약·카라반·지원군·적대 행동·세력 장 후보를 바꾼다. 성공 보상은 단순 평판 외에 공급망, 정보, 지원, 지역 안전, 기술 협력 중 하나를 실제로 변경한다.

### 6.6 연구 분기와 시대 변화

연구는 모든 노드를 결국 사는 선형 목록이 되지 않도록 다음 계약을 가진다.

- 각 시대 문제에는 최소 두 개의 해법 계열이 있다.
- 해법은 초기 비용, 유지비, 노동, 공간, 위험, 외부 의존, 자동화 잠재력 중 두 항목 이상이 다르다.
- 한 계열 선택은 다른 계열을 영구 봉쇄하지 않아도 되지만 의미 있는 기간 지연시킨다.
- 후속 사건·세력·기후가 선택한 계열의 장단점을 다르게 시험한다.
- 시대 전환은 상위 수치 시설을 주는 것뿐 아니라 플레이어가 관리하는 문제의 종류를 바꾼다.

문제 영역별 실제 해법 계열, 연구·시설 역할, 선택 영수증, 전환 비용, 종족·환경 상성, 이정표 대체 접근과 체크리스트 방지 감사 기준은 [`strategic-build-and-progression-design.md`](strategic-build-and-progression-design.md)를 세부 권위로 삼는다.

```text
생존기: 직접 부족 해결
정착기: 전문화·비축·내부 운반
사회기: 가구·문화·서비스·정치적 의무
산업기: 처리량·전력·정비·오염·연쇄 고장
문명기: 세대·외교·지역 공급망·대형 위험
```

### 6.7 방어·원정·포로

- 원정 사건은 실제 파티 구성, 부상, 장비 인스턴스, 탄약, 보급, 적재량, 지역 정보와 날씨를 문맥으로 고정한다.
- 정찰·협상·잠입·야영 결과는 다음 전투 목표·적 편성·경로·지원·후퇴 가능성을 바꾼다.
- 지역 승패는 던전 내부의 자원 유입, 침입 압력, 세력 상태 또는 피난민·포로 흐름으로 돌아온다.
- 포로 결정은 실제 인물의 치료·구금·노동·설득·교환·영입 상태를 바꾸고 원래 세력과 가구가 반응한다.

### 6.8 세대와 계보

세대 콘텐츠는 출생·사망 횟수만 세지 않는다.

다음 중 두 가지 이상이 후계자에게 실제로 전달되어야 한다.

- 가구 자산·부채·세력 의무
- 직업 숙련을 배울 수 있는 멘토·도구·시설 접근
- 문화와 관계 기억
- 유전·질병·신체 조건
- 계보 장비와 사용 역사
- 가문의 명예·원한·미완성 야망
- 특정 지역·세력·연구와 관련된 지식

상속은 무조건 보너스가 아니다. 강한 유산은 유지비, 의무, 원한, 경쟁 상속자 또는 시대에 맞지 않는 기술이라는 비용을 가진다.

## 7. 작업 예시

### 7.1 `life-event:apprentice-mistake`

현재 의도: 귀한 중간재 손실을 교육 기회로 삼을지 회수 노동을 시킬지 선택한다.

설계:

```text
발생 원인
  실제 제작 배치가 작업자 실수로 실패 또는 저품질 판정
  도제의 승인 기여 작업량이 기준 이상
  실제 손실·오염·손상품 스택 존재

가르친다
스승과 도제의 교육 작업량 30 생성
  작업 중 생산 인력 이탈
  완료 시 실제 실패 원인 태그에 대한 학습 기억
같은 원인의 사고 위험 감소, 관계 변화, 소량의 숙련 경험

회수시킨다
  손상품 스택을 입력으로 재생·분류 작업 생성
  회수량은 재료·오염·도제 숙련으로 판정
  성공 시 일부 실물 회수, 실패 시 추가 시간 손실
  책임을 맡긴 관계 기억과 야망 변화

역반응
  승급, 대작 의뢰, 멘토 편애 사건이 이 흔적을 참조
```

### 7.2 `seasonal:winter-frozen-pipes`

```text
발생 원인
  외기·노출 구간 온도가 임계 시간 이하
  실제 물 공급망의 취약 구간 선택

진행
  해당 구간 처리량 저하 또는 차단
  연결된 주방·병동·목욕·농업 시설이 실제 물 부족 상태를 읽음
  잔류수 오염·파손 위험이 일일 누적

대응
  가열: 연료·작업자·휴대 화로 사용, 빠르지만 화재 위험
  수리: 배관 작업과 부품, 느리지만 취약도 감소
  우회 급수: 물통·운반 노동 사용, 시설은 유지하지만 물류 압박

종료
  날씨 종료는 추가 동결만 멈춤
  파손·오염·밀린 치료와 생산은 자동 복구되지 않음
```

### 7.3 `service-incident:brawl`

```text
발생 원인
  같은 방에 있던 실제 손님·주민
  부정 관계, 문화 모욕, 음주 또는 대기 불만 영수증

분리
  경비 이동·제압 작업, 즉시 피해 제한, 서비스 중단

중재
  사교 숙련자와 회담 공간 예약, 추가 충돌 위험, 성공 시 관계 회복

체포
  실제 대상 구금·치료·소지품 보관, 세력 반응과 후속 심문

공통 결과
  실제 부상은 신체 권위에 남음
  방 손상·분실 물건·서비스 지연을 각각 기존 도메인이 소유
```

### 7.4 `life-event:inherited-debt`

```text
발생 원인
  사망자의 미결 세력 의무와 실제 가구 후계 관계

물자로 승계
  세력 요구 물품을 예약해 실제로 반출하고 인계
  완료하면 가구 의무 감소, 상속 갈등 가능

정당성 다툼
  기록·사교·세력 회담 작업
  성공하면 의무 감면, 실패하면 원한·기한 압박 증가

역반응
  후계자의 야망, 가구 신용, 세력 계약 조건, 다음 세대 기록에 반영
```

### 7.5 축제

축제는 물건을 차감하고 기분을 지급하는 한 번의 명령이 아니다.

```text
계획 확정
→ 시설·시간대·담당자·준비 물품 예약
→ 조리·장식·보안·초청 작업
→ 실제 참가자의 이동과 참석
→ 공급 완성도·참가율·안전·문화 적합성 집계
→ 성공/부분 성공/실패 결산
→ 문화 참여일·관계 기억·세력 공동 기념 흔적
```

### 7.6 세력 공급 계약

```text
세력의 실제 부족 상태가 계약 후보 생성
→ 던전이 수락하고 물품을 계약 목적지에 예약
→ 실제 물자 반출과 운송 위험
→ 도착 영수증으로 성공 판정
→ 세력 공급 안정성 상승
→ 이후 카라반 품목·가격·지원 가능성 변화
→ 경쟁 세력 또는 내부 생산이 반응
```

평판과 의무 토큰은 이 과정의 요약 결과이지 계약의 전부가 아니다.

## 8. 차별성과 전략성 판정

시스템 연결이 깊어도 선택이 사실상 같으면 콘텐츠 완성으로 보지 않는다.

### 8.1 이름 제거 테스트

콘텐츠 이름·설명·선택지 문구를 제거하고 다음만 비교한다.

- 발생 원인
- 요구 물품·시설·참여자
- 생성 명령
- 위험과 기한
- 실제 성공 판정
- 영속 흔적
- 역반응 소비자

두 콘텐츠의 실제 수행 과정이 같고 수치만 다르면 중복 후보로 감사한다.

### 8.2 선택 우위 테스트

- 균형 상태에서 모든 선택은 합리적인 이유를 가져야 한다.
- 특정 준비 상태에서는 한 선택이 명확히 유리할 수 있다.
- 같은 선택이 모든 기후·종족·시대·세력 상태에서 지배하면 실패다.
- 싼 선택은 의무, 시간, 위험, 미래 제약 중 하나를 남긴다.
- 비싼 선택은 위험 제거, 공급망, 지식, 관계 또는 장기 선택권을 제공한다.

### 8.3 시대·전략 사용률

자동 보고서는 콘텐츠별로 다음을 집계한다.

- 후보 발생률과 실제 선택률
- 선택지별 사용률과 성공·부분 성공·실패율
- 요구 시설·아이템·작업량
- 결합 등급과 실제로 수행된 시스템 행동 수
- 생성되고 다시 사용된 흔적 수와 후속 반응 횟수
- 종족·기후·정책·시대별 선택 편차
- 동일 기계 서명 그룹
- 장기간 한 번도 발생·선택·소비되지 않은 고아 콘텐츠

## 10. 자동 감사와 완료 조건

### 10.1 전수 지표

작업 보고에는 다음 수를 기록한다.

```text
전체 정의 수
C0/C1/C2/C3/C4/C5 수
중요 콘텐츠 중 C3 미만 수
실제 발생 근거 연결 수
실제 시스템 행동 연결 수
흔적 기록 연결 수
후속 반응 연결 수
완료 기록 검증 수
사용처가 없는 조립 역할·흔적·반응 식별자 수
실행 과정이 같은 콘텐츠 묶음 수
```

### 10.2 하드 실패 조건

- 중요 사건이 범용 수치 효과만 가진다.
- 영향을 준다고 적힌 시스템에 실제 검사, 행동 또는 후속 반응이 없다.
- 설명문에 수리·치료·조사·격리·협상·호위·이전이 있지만 실제 행동이 없다.
- 실제 원인 없이 무작위 대상에게 구체적 사고가 발생한다.
- 선택 순간 작업 결과와 보상을 즉시 지급한다.
- 단일 세계 상태 표시가 원인과 대상과 결과를 가진 흔적을 대신한다.
- 흔적을 남기지만 이를 읽는 미래 시스템이 없다.
- 콘텐츠 이름과 숫자만 다르고 기계 서명이 같다.
- 저장·복원 또는 화면 재개방으로 대상·결과·비용이 재추첨된다.
- 새 콘텐츠 ID별 분기를 코어 서비스에 추가해야 한다.

### 10.3 완료 단계

| 상태 | 의미 |
|---|---|
| `통합 설계 배정` | 이 문서의 통합 기록과 목표 등급을 작성함 |
| `정의 연결` | 조립 역할과 연결 관계를 선언했으나 실제 실행 증거 없음 |
| `실행 경로 검증` | 발생 근거부터 실제 행동, 상태 변경, 완료 기록과 흔적까지 연결됨 |
| `역반응 검증` | 저장 후 미래 시스템이 흔적·상태에 반응하는 경로 통과 |
| `전수 통합 완료` | 대상 카탈로그 100%, 고아 0, 중복 서명 검토, 결정론·저장·밸런스 감사 통과 |

컴파일 성공, 자산 생성, 효과의 담당 시스템 존재, 대표 사례 하나의 검증만으로 `전수 통합 완료`를 선언하지 않는다.

## 11. 전환 순서

### 11.1 1단계: 공통 조립 경로 검증

다음 네 정의를 대표 검증군으로 사용한다.

1. `life-event:apprentice-mistake`
2. `service-incident:brawl`
3. `seasonal:winter-frozen-pipes`
4. 세력 공급 계약 1개

네 콘텐츠가 각각 인물·서비스·기반 시설·외부 세력 체계를 대표한다. 기존 범용 수치 효과는 최종 결과에만 사용한다.

### 11.2 2단계: 종류별 전수 변환

1. 서비스 사고와 선택형 생애 사건
2. 계절 사건과 축제
3. 손님 요청과 세력 계약·장
4. 원정 사건과 포로 후속
5. 세대·계보와 이정표 반작용

같은 종류를 변환하는 동안 신규 수량을 늘리지 않는다.

### 11.3 3단계: 전략 경로 감사

- 연구·시설·아이템의 동일 역할 중복
- 시대별 문제 변화
- 종족·기후·세력별 대안 가치
- 장기 공급망과 소비처
- 256개 이상의 경제 난수 기준과 정책별 사용률

### 11.4 호환 경계

- 기존 C1/C2 자동 기록은 의도적으로 유지할 수 있다.
- 기존 중요 콘텐츠가 범용 수치 효과만 사용하면 구형 수치 전용 상태로 명시하고 신규 작성은 금지한다.
- 구형 효과와 신규 행동이 같은 결과를 이중 적용하지 않도록 적용 경계를 하나로 둔다.
- 모든 대상 종류가 전환되기 전에는 `시스템 콘텐츠 통합 완료`라고 보고하지 않는다.

## 12. 현재 결정과 미결정

### 확정

- 기존 물리 경제와 각 시스템의 상태 권위를 유지한다.
- 기존 범용 효과 체계는 최종 수치 결과에 한해 유지한다.
- 중요 콘텐츠는 C3 이상, 장기·세계 콘텐츠는 C4/C5를 요구한다.
- 실제 원인, 실제 과정, 실행 영수증, 영속 흔적, 역반응을 분리해 감사한다.
- 기존 조립 역할로 콘텐츠를 추가하며 콘텐츠 식별자별 중앙 실행 예외를 금지한다.

### 구현 전에 별도 구조 계약이 필요한 항목

- 진행 중 사건의 상태와 저장 형식
- 시스템 행동의 종류, 실행 담당과 등록 경계
- 흔적 저장 위치와 인물·가구·시설·세력·지역별 압축 정책
- 여러 시스템을 거치는 사건의 완료 순서와 실패 보상 절차
- 기존 요구·효과·축제·계절 사건 자료를 옮기는 방식
- 실제 수행 과정과 앞뒤 연결을 자동으로 검사하는 도구

## 13. 밸런스 상태

`밸런스 영향 없음`.

이 문서는 현재 콘텐츠의 수치, 필요 재료, 작업량, 확률, 보상, 기간 또는 진행 날짜를 변경하지 않는다. [`whole-game-balance-baseline.md`](whole-game-balance-baseline.md)의 `손님·세력·계약·사건`, `결정론적 검증 매트릭스`, `콘텐츠 추가·수정 필수 기록`을 확인했으며, 향후 구현 시 각 콘텐츠별로 별도의 `밸런스 기준 배정` 이상을 받아야 한다.
