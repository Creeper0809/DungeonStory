# DungeonStory 시스템 콘텐츠 상세 카탈로그

> 상태: 콘텐츠별 통합 설계 배정
>
> 상위 연결 계약: [`systemic-content-integration-design.md`](systemic-content-integration-design.md)
>
> 수치·내재 작업량·필요 재료·확률·기간 권위: [`whole-game-balance-baseline.md`](whole-game-balance-baseline.md)
>
> 이 문서는 현재 작성된 안정 ID를 기준으로 무엇을 실제로 구현할지 확정한다. 별도 표시가 없으면 새 이벤트 수량을 추가하지 않는다.

## 1. 문서 사용법

각 행은 다음을 확정한다.

- **발생**: 후보가 만들어지는 실제 게임 상태와 원인 영수증
- **실행**: 플레이어 선택 또는 자동 콘텐츠가 생성하는 실제 작업·이동·서비스·정책·전투
- **흔적·후속**: 완료 뒤 저장되는 결과와 그것을 읽는 다음 시스템
- **등급**: 상위 문서의 C1~C5 결합 목표

이 문서에서 `작업`은 기존 작업자·시설·경로·작업량을 쓰는 실제 주문이다. `이전`은 실제 아이템의 예약·운반·도착 기록을 뜻한다. `정책`은 대상 시설·방·가구·세력·원정에 적용되는 명시적 상태이며 단일 세계 상태 표시와 분리해 보존한다.

수치가 적혀 있지 않은 신규 작업량, 확률, 기간, 회수량과 효과 크기는 구현 전에 전역 밸런스 기준을 배정한다. 이 문서는 행동과 인과를 정하며 임의 수치를 확정하지 않는다.

## 2. 공통 실행 어휘

| 실행 종류 | 실제 의미 | 성공 영수증 |
|---|---|---|
| 물자 예약·이전 | 특정 스택을 목적지에 예약하고 운반·소비·반환 | 스택 ID별 출발·도착·소비·반환 영수증 |
| 작업 주문 | 수리, 교육, 조사, 조리, 정비, 의식, 건설 등 | 승인 기여 WU와 완료/취소/실패 원인 |
| 시설·방 정책 | 접근, 우선순위, 격리, 운영 중단, 전용 용도 | 대상 시설과 정책 버전 |
| 서비스 수행 | 식사, 숙박, 치료, 공연, 거래, 검역 | 손님·시설·제공품·품질·대기시간 영수증 |
| 의료 처리 | 진단, 격리, 치료, 수술, 노출 관리 | 환자·질병·약품·병상·신체 결과 |
| 사회 처리 | 교육, 중재, 보호자 지정, 장례, 계약 심리 | 참여자·관계 기억·가구/세력 결정 |
| 전투·원정 목표 | 정찰, 호위, 생포, 구조, 방어, 수색 | 파티·장비·보급·지역·목표 결과 |
| 세계 조건 | 홍수, 폭염, 연무, 동결, 이동창 같은 진행 상태 | 시작 원인, 영향 대상, 일일 변화, 종료 원인 |

## 12. 전투 조우 36개의 시스템 연결 계약

36개 조우의 적 구성·전장 변형·전술 의도는 주 설계서의 [23.9 전투 조우](../DungeonStory_Game_Design_and_Implementation.md#239-전투-조우)를 권위로 유지하며 이 문서에서 다시 창작하지 않는다. 대신 모든 조우가 아래 동일한 준비·진행·정산 계약을 지켜야 한다.

### 12.1 출전 전

1. 조우 후보는 실제 정찰, 침입 경로, 세력 위협, 계절 사건 또는 원정 노드가 생산한다.
2. 조우가 시작되면 적 개체·목표 시설과 경로·전장 구역·관련 세력·원인이 된 흔적을 고정한다.
3. 플레이어가 편성한 인원의 동일 인스턴스 장비, 탄약, 약품, 포획 도구, 운반 용량을 예약한다.
4. 정찰 없이 출전하면 적 세부 구성은 숨길 수 있지만 실제 예약·이동 비용은 생략하지 않는다.

### 12.2 전투 중

- 탄약·약품·내구·부상은 원본 인스턴스와 물리 스택에 기록한다.
- 생포·구조·시설 방어·호송 같은 목표는 적 전멸과 별도 완료 조건을 가진다.
- 후퇴 시 살아 있는 인원과 실제 운반 가능한 물품만 회수한다. 바닥 전리품과 시신은 전장에 남는다.
- 적은 조우 정의에 적힌 전술을 사용하되, 이전 전투 기록에 반복 전술이 남아 있으면 허용된 적응 행동을 선택할 수 있다.

### 12.3 전투 후

| 결과 | 실제 정산 | 다시 읽는 시스템 |
|---|---|---|
| 사상자·부상 | 인물 생애, 가구, 의료 대기열, 시신의 현재 위치, 장례 후보 생성 | 생애 사건, 문화 장례, 의료 부족, 복수·계보 |
| 포로·생포 | 실제 적 인스턴스를 구속·호송하고 감방 수용력과 포획 도구 내구를 사용 | 심문, 계약, 교환, 탈옥·구출 침입 |
| 전리품 | 적 장비 인스턴스·화물 스택을 운반 용량 안에서 월드로 이전 | 생산·수리·연구 표본·세력 소유권 분쟁 |
| 시설·경로 피해 | 전장 셀의 구조물 내구·문·전력·운반로를 그대로 손상 | 수리 주문, 계절 위험, 서비스 중단, 다음 침입 경로 |
| 전술 기록 | 사용한 우세 전술, 실패 원인, 지휘자, 적 생존 목격자를 저장 | 적 조합·행동 적응, 대장 시험, 세력 보복 |
| 목표 결과 | 구출자·보호 화물·파괴·점령·후퇴 목표별 영수증 | 원정 노드, 세력 장·계약, 이정표, 노출 세계 상태 |

조우는 전리품을 지급한 뒤 원인을 잊는 독립 미니게임이 아니다. 위 여섯 정산 중 해당 가능한 항목이 하나도 없는 조우는 시스템 결합 실패다.

## 13. 구현 순서

### 1단계 — 공용 기반

- 사건이 고정할 대상, 실제 행동, 장기 흔적과 후속 반응의 공통 형식을 먼저 정의한다.
- 예약, 진행, 완료 판정과 흔적 기록이 저장과 복원 뒤에도 같은 순서로 이어지게 한다.
- 현재 범용 수치 효과는 실제 과정 뒤의 요약 결과로만 남기고 선행 행동을 대체하지 못하게 한다.
- 기존 저장 자료에 진행 중 사건의 정보가 부족하면 이를 조용히 추정하지 않고 구형 자료라는 상태를 명시한다.

### 2단계 — 대표 검증 콘텐츠 4개

| 대표 콘텐츠 | 대표 시스템 | 반드시 증명할 장면 |
|---|---|---|

| `service-incident:brawl` | 서비스·경비·의료 | 실제 같은 방의 당사자가 싸우고 분리·중재·체포가 서로 다른 이동·시설·후속을 만든다. |

### 14.2 정의별 자동 감사 행

최종 감사표는 현존 217개, 누락 생애 정의 6개와 신규 후속 압력 9개를 합친 232개에 대해 다음 항목을 한 행씩 가져야 한다.

- 콘텐츠 식별자, 종류와 결합 등급
- 실제 발생 근거와 고정 대상의 종류
- 실제 행동과 완료 판정 근거의 종류
- 영속 흔적의 종류와 후속 반응 수
- 물리 투입물의 역할과 저장 권위
- 구형 범용 수치 효과만 사용하는지 여부와 감사 상태

다음은 전수 실패 조건이다.

- 시간 경과나 무작위 추첨만 있고 실제 원인 증거가 없음
- 고정 대상이 안정 식별자를 쓰지 않고 표시명이나 현재 선택 대상을 다시 조회함
- 실제 시스템 행동 없이 범용 수치 효과만 가짐
- 모든 물품을 구분 없이 소비하는 것으로 처리함
- 완료 근거 없이 영속 흔적을 먼저 기록함
- 후속 반응이 없는데 목표 등급이 C3 이상임
- 저장 복원 후 작업·소비·보상·후속 사건이 중복됨
- 사망·파괴·이사·세력 소멸 뒤 끊어진 참조를 조용히 무시함
