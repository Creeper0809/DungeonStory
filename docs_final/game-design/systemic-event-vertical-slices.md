# DungeonStory 사건 수직 슬라이스

> 상태: 목표 설계. 공용 operation·receipt·reaction 런타임의 구현 여부는 [시스템 구현 권위 체크리스트](../system-implementation-checklist.md)가 판정한다.
>
> 이 문서는 [시스템 콘텐츠 통합 설계](systemic-content-integration-design.md)의 네 canary를 플레이어의 실제 운영 경험으로 구체화한다.

## 사건이 남겨야 할 감정

사건은 플레이어가 이미 만든 구조를 다시 바라보게 하고, 평온할 때 준비할 이유와 위기를 넘긴 뒤 바꿀 이유를 남긴다.

```text
실제 원인 발견
→ 나의 현재 구조가 가진 강점·약점 확인
→ 서로 다른 실제 행동 선택
→ 세계에서 진행되는 수습
→ 결과와 손실 확인
→ 관계·시설·세력·다음 사건의 조건 변화
```

자동 생애 기록은 C1~C2에서 발생 근거와 기억을 남긴다. 아래 네 사건은 C3 이상 경로의 대표 사례다.

## 1. `life-event:apprentice-mistake`: 손실을 사람에게 어떻게 남길 것인가

| 단계 | 설계 |
|---|---|
| 실제 원인 | 도제가 기여한 제작 배치가 실패·저품질·재료 손실로 끝나고, 손상품 또는 오염된 실제 물품이 남는다. |
| 플레이어가 읽는 것 | 어떤 공정, 어떤 재료, 어떤 도제, 어떤 숙련·작업 환경이 원인이었는지 확인한다. |
| 선택 | 교육을 우선하면 숙련자와 도제의 시간을 교육·원인 분석에 묶는다. 회수를 우선하면 손상품의 분류·재생·운반 작업을 만든다. |
| 실제 진행 | 교육은 생산 인력 공백을, 회수는 추가 운반과 작업 지연을 만든다. 결과는 작업 완료와 실제 물품 회수·손실로 판정한다. |
| 남는 흔적 | 도제의 학습 기억, 멘토 관계, 실패 원인 태그, 손실을 감당한 시설·생산 공정의 이력. |
| 다음 압력과 기회 | 승급, 대작 의뢰, 멘토 편애, 같은 공정의 재발 방지 투자와 시설 재배치가 이 흔적을 읽는다. |

이 사건에서 플레이어는 당장의 자재 회수와 장기적인 사람 육성 사이에서 자기 운영 철학을 드러낸다.

## 2. `service-incident:brawl`: 환대 시설은 공간 배치까지 시험한다

| 단계 | 설계 |
|---|---|
| 실제 원인 | 같은 서비스 공간에서 실제 손님·주민이 문화 모욕, 음주, 대기 불만, 관계 악화의 영수증을 쌓아 충돌한다. |
| 플레이어가 읽는 것 | 어떤 방, 어떤 손님, 어떤 서비스 지연과 관계가 충돌을 만들었는지 확인한다. |
| 선택 | 경비로 분리해 피해를 제한하거나, 회담 공간과 중재 인력을 확보하거나, 실제 대상의 치료·구금·소지품 보관을 진행한다. |
| 실제 진행 | 서비스가 멈추고, 사람은 이동하며, 부상은 치료되고, 방 손상과 분실 물건은 해당 권위에서 처리된다. |
| 남는 흔적 | 관계 기억, 서비스 신뢰, 방의 안전·접근 정책, 세력의 평가, 구금과 중재의 기록. |
| 다음 압력과 기회 | 접견실·보안 동선·문화별 식사 공간을 재구성할 이유가 생기며, 이후 손님 요청과 세력 계약이 신뢰 기록을 읽는다. |

이 사건은 사회 수치의 충돌이 아니라, 플레이어가 설계한 서비스 공간과 운영 규칙이 실제로 시험받는 장면이다.

## 3. `seasonal:winter-frozen-pipes`: 자동화의 약점에서 운영 실력이 보인다

| 단계 | 설계 |
|---|---|
| 실제 원인 | 노출 구간의 저온 지속과 실제 물 공급망의 취약 구간이 함께 확인된다. |
| 플레이어가 읽는 것 | 어느 배관 구간이 멈췄고, 주방·병동·목욕·농업 중 어디가 먼저 물 부족을 겪는지 확인한다. |
| 선택 | 연료와 인력을 써서 가열하거나, 부품과 작업으로 수리하거나, 물통과 운반으로 우회 급수를 유지한다. |
| 실제 진행 | 구역 처리량, 물류 노동, 시설 우선순위, 오염·파손 위험이 시간에 따라 바뀐다. 날씨가 끝나도 밀린 치료·생산·손상은 남는다. |
| 남는 흔적 | 취약 구간, 수리 이력, 비상 급수 경험, 구역 차단 정책, 부족 기간의 사회·의료 결과. |
| 다음 압력과 기회 | 플레이어는 단열·우회·완충·분산 위생 중 무엇을 투자할지 결정하며, 겨울을 버틴 시설은 방어적 진화 후보가 된다. |

준비한 완충과 우회가 실제로 시간을 벌어 주면, 피해가 남은 결말도 운영의 성취가 된다.

## 4. `faction-contract:beastkin:supply`: 계약은 공급망을 확장하는 대신 의무를 남긴다

| 단계 | 설계 |
|---|---|
| 실제 원인 | 비스트킨 세력의 공급 불안정과 던전의 관계·생산·경로 조건이 계약 후보를 만든다. |
| 플레이어가 읽는 것 | 요구 화물이 현재 비축·생산·방어 보급과 경쟁하는지, 계약을 지킬 운송·호위 여유가 있는지 확인한다. |
| 선택 | 물자를 실물로 준비해 이행하거나, 가능한 범위로 협상해 의무와 보상을 바꾸거나, 거절해 내부 비축을 지킨다. |
| 실제 진행 | 물자는 계약 목적지로 예약·반출·운송되고, 경로·호위·도착 영수증으로 성공·부분 성공·실패가 판정된다. |
| 남는 흔적 | 세력 공급 안정성, 던전의 의무·신용, 남은 비축, 경쟁 세력의 반응, 다음 카라반 조건. |
| 다음 압력과 기회 | 더 좋은 조달·정보·지원 기회가 열리거나, 이행 부담·원한·경로 위험이 다음 운영을 바꾼다. |

계약의 쾌감은 평판 수치가 오르는 데 있지 않다. 플레이어가 자기 던전의 생산력과 신뢰를 외부 세계에 걸고, 그 결과로 공급망의 지형이 바뀌는 데 있다.

## 네 사건이 만드는 리듬

| 사건 | 시험하는 준비 | 플레이어가 바꾸게 되는 구조 |
|---|---|---|
| 도제의 큰 실수 | 숙련 배치, 생산 공정, 재료 회수 | 멘토링, 작업대, 품질·회수 정책 |
| 서비스 난투 | 관계, 서비스 흐름, 문화 공간, 경비 | 접견·식사·보안 동선, 접근 정책 |
| 결빙 배관 | 완충, 구역화, 연료·부품, 수동 회복 | 배관, 저장, 비상 급수, 우선 공급 |
| 비스트킨 공급 계약 | 비축, 생산 여유, 경로, 호위, 세력 신용 | 창고, 계약 조달, 방어 배치, 외교 의무 |

이 네 사건을 실제 경로로 닫은 뒤에는 같은 계약을 생애, 서비스, 계절, 세력 콘텐츠로 확장한다. 상세 행은 [콘텐츠 설계 기록](content-plans/README.md)에서 분리 관리한다.
