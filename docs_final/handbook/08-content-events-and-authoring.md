# 08. 콘텐츠 작성과 사건 통합

## 콘텐츠 작성의 목표

DungeonStory의 콘텐츠는 플레이어가 이전과 다른 판단을 하게 하는 데 가치를 둔다. 새 시설, 아이템, 조합식, 특성, 연구, 사건, 적과 세력은 각각 다른 준비와 대응을 요구해야 한다. 이름과 설명과 수치만 바뀌고 플레이 과정이 같다면 별도 콘텐츠로서의 가치가 약하다.

콘텐츠를 작성할 때는 먼저 그 대상이 세계에서 맡는 일을 설명한다. 어떤 문제를 만들거나 해결하는지, 어느 자원과 노동을 사용하며, 다른 방식과 비교해 무엇을 얻고 무엇을 감수하는지 정한다. 그다음 기존 모듈로 표현할 수 있는지 확인하고, 실행과 저장과 화면까지 이어지는 경로를 연결한다.

이 순서를 택한 이유는 데이터 수와 실제 플레이 콘텐츠의 수를 구분하기 위해서다. 자산 파일이 존재해도 콘텐츠 목록, 실행 규칙과 상태 권위에 연결되지 않으면 플레이에 나타나지 않는다. 몇 개의 공통 모듈을 사용하더라도 조합이 서로 다른 비용과 결과를 만들면 새로운 콘텐츠로 기능할 수 있다.

현재 작성 자산의 안정 식별자, 작성 항목, 연결 관계, 실제 게임에서 사용되는 근거와 존재 이유는 [콘텐츠 데이터베이스](../content-db/README.md)에서 유형별로 확인한다.

## 콘텐츠가 통과해야 하는 판단

새 콘텐츠는 다음 질문에 답할 수 있어야 한다.

1. 플레이어가 이전과 다른 결정을 내리는가.
2. 실제 시설, 물건, 인물, 작업, 시간, 공간 또는 위험을 사용하는가.
3. 다른 시스템과의 관계가 구체적인 상태 변화로 설명되는가.
4. 선택하거나 사용하지 않을 이유도 존재하는가.
5. 실패 원인과 회복 경로를 플레이어가 이해할 수 있는가.
6. 취소, 파괴와 중간 저장에서 물건과 결과가 중복되거나 사라지지 않는가.
7. 같은 이름과 숫자만 바꾼 기존 콘텐츠의 복제품은 아닌가.
8. 현재 콘텐츠 목록, 실행 규칙과 저장 경로에 실제로 연결되는가.

이 질문은 모든 콘텐츠에 같은 형태로 적용되지 않는다. 아이템은 물리 사용처와 생산망이 중요하고, 특성은 행동과 기분과 사건에 어떤 차이를 만드는지가 중요하다. 사건은 발생 원인과 선택의 실제 과정과 후속 흔적이 중요하다. 공통 목적은 콘텐츠가 시스템 안에서 책임을 가지게 하는 것이다.

## 콘텐츠 유형별 작성 단위

### 시설

시설은 배치, 방, 기반망, 생산과 서비스 능력을 조합해 작성한다. 공간, 연구 조건, 건설 재료, 작업, 입력과 출력, 환경, 고장과 철거를 기록한다. 새 시설은 해결하는 문제와 경쟁 시설을 가져야 하며, 더 높은 수치만 제공하는 상위 복제품은 기술 발전인지 전략 대안인지 구분한다.

시설 작성의 자세한 기준은 [공간 구축, 시설과 환경](03-world-building-facilities-environment.md)을 따른다.

### 아이템과 생산식

아이템은 음식, 약품, 장비, 재료처럼 용도별 규칙을 조합한다. 조합식은 구체 입력, 작업, 필요한 시설 기능, 제작 중 상태, 출력, 부산물과 물질수지를 정의한다. 만들어진 아이템이 어느 작업과 시설과 사건에서 실제로 소비되는지 확인한다.

공용 중간재는 여러 소비처의 경쟁을 만들어야 한다. 단일 용도 단계가 길어질수록 생산망은 판단 없는 통로가 되므로 완제품, 설치 부품 또는 의미 있는 분기 재료인지 검토한다. 자세한 기준은 [물질 경제, 생산과 물류](04-items-production-logistics-economy.md)를 따른다.

### 특성, 종족과 질병

특성은 능력치 보정만으로 존재 이유를 끝내지 않는다. 작업 선호, 기분 반응, 관계, 사건 후보, 생리와 실제 행동 중 무엇이 달라지는지 작성한다. 종족과 문화는 시설 효용, 환경, 음식, 번식, 의료와 사회 관계를 통해 운영 비용을 바꾼다. 질병은 전파 경로, 표적 신체, 현장 대응과 예방 방식이 달라야 한다.

자세한 기준은 [인물, 노동, 사회와 생명](05-characters-ai-society-health.md)을 따른다.

### 연구

연구는 직접 해금과 기술 인과를 가진다. 어떤 새 행동을 열고, 어느 문제를 어떤 비용으로 해결하며, 경쟁 계통을 왜 늦추는지 설명한다. 연구명과 분야가 달라도 결과적으로 같은 시설과 같은 운영 방식을 연다면 별도 전략으로 계산하지 않는다.

자세한 기준은 [연구, 진행과 전략 선택](06-research-progression-and-strategy.md)을 따른다.

### 적, 장비와 조우

적은 능력치 외에 표적, 진형, 행동 조건과 퇴각 성향을 가진다. 장비는 탄약, 중량, 사거리, 방어 자세, 내구와 생산 부담을 통해 역할이 달라진다. 조우는 목표와 전장 조건과 준비 요구가 달라야 한다. 포획 가능한 적은 개인 상태를 유지해 주민 체계로 이어질 수 있어야 한다.

자세한 기준은 [전투, 침입, 원정과 세력](07-combat-invasions-expeditions-factions.md)을 따른다.

### 사건과 장기 서사

사건은 세계의 현재 상태를 읽고, 특정 인물과 시설과 물건을 문맥으로 묶으며, 플레이어의 선택을 실제 결과로 연결한다. 사건 설명이 풍부해도 요구 조건 확인 뒤 기분이나 평판을 즉시 바꾸고 끝난다면 다른 시스템과 깊게 맞물렸다고 보기 어렵다.

사건의 목적은 운영 과정에서 이미 생긴 상황을 플레이어가 해석하고 책임 있는 선택을 하게 만드는 것이다. 사건이 세계 밖에서 이야기를 덧붙이는 대신, 세계가 쌓아 온 상태를 이야기로 읽을 수 있게 해야 한다.

## 현재 공통 기반

생애 사건, 손님 요청, 서비스 사고, 세력의 장기 이야기와 계약, 계절 사건, 결말, 조우, 질병, 야생동물과 전장 변화는 하나의 콘텐츠 목록에서 찾는다. 계절, 사회, 세력과 이정표의 현재 상태는 각 담당 시스템이 관리한다.

현재 공통 사건 처리 경로는 다음 일을 맡는다.

- 콘텐츠 요청과 결과 전달
- 발생 조건 평가
- 필요한 시설 기능 확인
- 아이템 비용 사전 검사
- 선택 결과 적용
- 경보 등록과 해제
- 플레이어 선택 실행

경보 기록은 현재 발생한 경보와 해제 순서를 저장한다. 서비스 사건은 실제 손님의 이용 과정과 시설 상태를 참조한다.

이 구조를 사용하면 안정 ID, 발생 조건, 선택지, 물품과 시설 요구, 결과와 경보 행동을 조합해 사건을 작성할 수 있다. 기존 규칙 안의 사건마다 전용 실행 코드를 새로 만들 필요가 없다.

여기까지가 현재 공통 기반이다. 여러 날에 걸친 작업, 중단과 재개, 완료 영수증, 다른 시스템의 후속 반응과 압력 기반 편성을 하나의 공통 사건 경로로 묶는 것은 아래의 설계 기준에 속한다. 실제 적용 범위는 [시스템 구현 권위 체크리스트](../system-implementation-checklist.md)가 판정한다.

## 사건이 따라야 하는 인과 순환

중요 사건은 다음 흐름을 설계 기준으로 삼는다.

```text
실제 세계 상태에서 원인이 생긴다
→ 관련 인물, 시설, 물건, 지역과 작업을 고정한다
→ 선택마다 다른 준비와 명령을 만든다
→ 기존 시스템이 이동, 작업, 치료, 협상과 전투를 실행한다
→ 실제 완료와 실패 기록으로 결과를 판정한다
→ 기분, 관계, 평판과 보상 같은 최종 효과를 적용한다
→ 인물, 가구, 시설, 세력, 지역과 계보에 흔적을 남긴다
→ 이후 시스템이 그 흔적과 바뀐 상태에 반응한다
```

이 흐름에서는 생산, 의료, 물류, 관계, 구금, 세력과 원정이 이미 제공하는 기능을 조합하고, 사건이 문맥과 선택과 판정을 맡는다. 공통 기능이 많아질수록 새로운 사건을 기존 세계 규칙 안에서 작성할 수 있고, 사건별 전용 시스템은 줄어든다.

## 발생 원인

사건의 설명과 실제 발생 원인이 일치해야 한다.

- 도제의 큰 실수는 실제 실패, 저품질 또는 재료 손실 주문과 기여한 도제를 참조한다.
- 금기 음식 제공은 실제 서비스 영수증, 제공 음식과 손님의 문화를 참조한다.
- 시설 파괴 공작은 손상된 시설, 침입 경로 또는 조사 가능한 흔적을 가진다.
- 결빙 배관 사건은 저온과 유체망과 실제 영향을 받은 구간에서 시작한다.
- 상속 분쟁은 사망자, 가족 관계, 자산과 이전 약속을 참조한다.

발생 원인이 실제 상태에 있으면 플레이어는 사건을 운이 나쁜 팝업으로만 보지 않는다. 자신의 생산 정책, 공간, 관계와 안전 관리가 어떤 결과를 만들었는지 이해할 수 있다. 다음에는 사전 예방을 시도하거나 같은 위험을 감수할 수도 있다.

원인 증거가 사건 선택 전에 사라지면 비슷한 다른 대상을 몰래 대입하지 않는다. 후보를 무효화하거나 대상 상실에 맞는 결과로 처리한다. 이름이 같은 다른 시설이나 인물로 교체하면 플레이어가 보고 있던 사건의 사실관계가 바뀐다.

## 문맥 고정

발생한 사건은 정의 ID와 함께 다음 대상을 고정한다.

- 주 참여자와 보조 참여자의 고유 인물 ID
- 가구, 보호자, 가문과 멘토 관계
- 시설, 방, 배관, 전력망과 지역 인스턴스
- 원인이 된 작업 주문, 생산 배치, 서비스, 전투와 원정
- 실제 물건 묶음, 고유 장비와 유물
- 관련 세력과 교차 세력
- 발생 절대일, 기한과 재현에 필요한 난수 기준값

문맥 고정은 선택의 책임 대상을 유지한다. 도제 사건을 열어 둔 사이 해당 도제가 사망했거나 시설이 파괴되었다면 새 도제와 시설에 같은 결과를 적용하지 않는다. 사건은 대상 상실을 인정하고 설계된 종료 또는 후속 경로를 사용한다.

## 선택지는 다른 행동이어야 한다

선택지의 차이는 문장보다 실제로 수행하는 행동에서 판정한다. `치료한다`와 `정성껏 치료한다`가 같은 약품과 같은 작업과 같은 결과를 사용한다면 별도 선택으로 볼 이유가 없다.

예를 들어 감염 사고에 대한 선택은 다음처럼 달라질 수 있다.

| 선택 | 실제로 만드는 과정 | 지불하는 비용과 남는 위험 |
|---|---|---|
| 격리 | 방 접근 변경, 환자와 노출자 이동, 급식과 약품 공급 | 공간과 운반 노동, 서비스 중단 |
| 집중 치료 | 병상과 약품 예약, 의료 우선순위 상승, 치료 작업 | 의료 자원 집중, 원인 시설은 남을 수 있음 |
| 원인 제거 | 오염 구역 폐쇄, 청소, 수리와 물질 처분 | 생산 중단과 수리 자재, 환자 치료는 별도 |
| 은폐 | 즉시 영업 중단 회피, 기록 은폐 흔적 | 오염원과 노출 유지, 발견 시 가중된 관계 결과 |

좋은 선택은 정답과 오답을 색으로 나누지 않는다. 현재 던전의 여유와 전략에 따라 가치가 달라진다. 의료 인력이 부족한 사회는 원인 제거와 격리를 택할 수 있고, 외교 계약 기한이 급한 사회는 위험을 감수하고 제한 운영을 택할 수 있다.

항상 우월한 선택이 있다면 비용이나 후속 위험이 누락되었는지 본다. 모든 선택이 같은 결과에 도달한다면 선택 수를 줄이거나 실행 차이를 다시 설계한다.

## 진행과 결과 판정

작업, 수리, 치료, 이동, 협상과 전투가 필요한 선택은 클릭 순간 성공 처리하지 않는다. 진행 중인 사건은 선택, 기한, 관련 대상, 예약과 단계를 가진다. 결과는 담당 시스템이 남긴 완료, 소비, 도착, 부상, 수리와 관계 변경 기록을 바탕으로 판정한다.

결과는 성공과 실패 두 종류로만 나누지 않는다.

- 목표와 비용을 모두 충족한 성공
- 일부 작업이나 대상을 보존한 부분 성공
- 기한이나 작업 실패
- 발생 원인이 다른 과정으로 해소된 상태
- 참여자 또는 대상 상실

이 구분이 필요한 이유는 시스템 게임의 상황이 사건 창을 기다려 주지 않기 때문이다. 플레이어가 다른 방식으로 시설을 수리했거나, 원정 중 관련 인물이 사망했거나, 침입이 공급망을 끊을 수 있다. 사건은 실제 세계 변화를 인정해야 한다.

여러 상태를 바꾸는 선택은 사전 검사와 예약 뒤 한 번에 반영하거나, 진행 단계를 명시한 기록으로 관리한다. 아이템만 소비되고 관계 결과가 빠지거나, 결과를 받은 뒤 같은 작업을 다시 시작하는 상태를 막는다.

## 최종 효과와 흔적

기분, 관계, 세력의 호의와 원한, 위협, 야망 진행, 금화와 연구 효과는 실제 과정이 끝난 뒤 적용한다. 세계에서 수행할 수 있는 행동을 수치 변화로 생략하지 않는다.

사건의 흔적은 이후 선택에 영향을 줄 만큼만 보존한다.

- 어떤 정의와 결과였는가
- 언제 일어났는가
- 어느 인물, 가구, 시설, 세력 또는 지역에 귀속되는가
- 어떤 결과 분류와 심각도를 남겼는가
- 어느 완료 기록에서 나온 결과인가

흔적은 다음 사건 후보, 관계 기억, 시설 정책, 세력 계약, 원정 정보, 교육, 상속, 계보와 이정표 압력을 바꿀 수 있다. 한 번의 선택이 영구 보너스 수치를 남기는 것보다, 미래에 가능한 행동과 의무를 바꾸는 편이 장기 서사에 적합하다.

최근 사건은 참여자와 구체 결과를 유지하고, 오래된 사건은 횟수, 마지막 발생일, 최대 심각도와 주요 결과 분류로 압축한다. 플레이어가 기억할 역사는 남기면서 저장과 관계 계산이 끝없이 커지는 일을 막는다.

## 콘텐츠 범주별 존재 이유

### 생애 사건

생애 사건은 성장, 도제, 가족, 직업, 노년, 죽음과 계승이 운영 상태에 반응하도록 만든다. 인물의 야망과 경력이 자동 수치 상승으로 끝나지 않고, 실제 작업과 관계와 자산을 요구하는 선택이 된다.

도제의 실수에서 재료를 손실로 처리할지, 다시 제작하며 교육할지, 책임을 다른 사람에게 돌릴지는 생산 비용과 관계와 경력을 다르게 만든다. 이런 사건은 주민을 기억할 이유를 제공한다.

### 문화 관습과 축제

문화 관습은 음식, 공간, 시간, 참여자와 물품을 통해 문화가 실제 생활 방식이 되게 한다. 축제는 준비, 참여, 진행과 결산의 단계를 가지며, 사회가 평시 생산을 잠시 멈추고 공동체 회복과 외교와 기억에 자원을 쓰는 선택을 만든다.

축제의 성공은 기분 보너스 하나보다 누가 참여했고, 어떤 물품과 공간을 준비했으며, 문화 갈등을 어떻게 다뤘는지에서 결정된다. 장례와 추모 행사도 상실 뒤 사회가 회복하는 실제 과정으로 기능한다.

### 계절 사건

계절 사건은 날씨 배경을 생산, 물류, 질병, 농업, 야생동물, 원정과 시설 운영의 변화로 번역한다. 눈보라는 이동과 시야를 늦추고, 수입과 원정 귀환을 지연시키며, 연료 부족과 배관 결빙을 만들 수 있다.

계절 사건의 재미는 수치 페널티를 견디는 데 있지 않다. 비축 방출, 우회 운송, 제설, 시설 중단과 위험 작업 중 어떤 대응을 택할지 결정하는 데 있다. 사건 종료 뒤에도 손상 시설과 환자와 재고 부족은 실제 상태로 남는다.

### 손님 요청과 서비스 사고

손님 요청은 접객 시설과 생산품과 사교 인력을 외부 수요에 연결한다. 고급 식사, 치료, 거래, 공연, 피난, 연구와 무장 요구는 실제 객실, 시설 기능과 물리 아이템을 사용한다.

서비스 사고는 운영 실패와 문화 갈등을 표면에 드러낸다. 난투, 절도, 오염, 금기 음식과 사절 충돌은 치료, 체포, 배상, 협상, 조사와 영업 중단처럼 서로 다른 도메인을 호출한다. 서비스 경제가 안전한 금화 생산기가 되지 않고 사회와 치안과 외교의 부담을 갖게 한다.

### 세력 장과 계약

세력 장은 관계 수치가 오르는 반복 임무보다 장기 약속과 갈등의 변화를 만든다. 각 세력의 내부 문제와 경쟁 관계에 개입하면서 공급망, 통행권, 방위 지원, 유물, 원한과 의무가 달라진다.

계약은 실제 생산품, 시설, 작업, 호위와 전투 결과를 요구한다. 성공은 실제 이전과 도착 영수증으로 판정한다. 한 세력과의 약속이 다른 세력이나 내부 문화에 어떤 반응을 만드는지도 장기 서사의 일부다.

### 방어와 원정 사건

전투 사건은 실제 파티, 장비, 탄약, 지역, 포로와 부상 상태를 사용한다. 전투 전에는 준비와 정보가, 전투 중에는 목표와 철수가, 전투 후에는 귀환과 치료와 관계가 중요하다.

전투 결과가 보상 표에서 끝나지 않고 기지 운영과 다음 위협을 바꿀 때 전투와 경영이 한 게임으로 연결된다.

### 이정표와 후속 압력

이정표는 장기 성취를 인정하고 전용 랜드마크와 세계 변화를 연다. 성취를 거치며 더 큰 규모의 책임을 받아들인다. 세력 연합은 새로운 외교 의무를, 자동 문명은 공통 기반망의 고장 위험을, 시간 고정은 지속 동력과 촉매 부담을 만들 수 있다.

이러한 후속 압력은 이정표 뒤에도 운영 판단을 남기고, 완성한 문명의 특성을 시험한다.

## 사건 편성이 따라야 할 호흡

사건 편성 계층은 현재 세계에서 유효한 후보와 제시 시점을 정해야 한다. 생존·경제·방어·사회 압력과 변화 추세, 최근 중요 사건의 범주와 강도, 미해결 관계, 참여자 점유, 준비 가능 시간, 계절·문화·세력 조건을 함께 읽어야 한다. 실제 결과는 각 상태를 맡은 시스템이 적용해야 한다.

같은 범주의 위기를 연속해서 겹치지 않도록 휴지기를 두고, 한 인물을 동시에 여러 중요 사건의 주인공으로 묶지 않는다. 평온한 구간에는 수리, 비축, 투자, 교육과 관계 정리가 집중된다. 이 시간을 사건으로 계속 채우면 플레이어는 세계를 운영하지 못하고 알림만 처리하게 된다.

미해결 관계는 후속 후보로 남는다. 배상 미지급, 수리 지연, 상처, 원한, 도제 갈등과 계약 실패가 새 사건의 원인이 되면 같은 세계가 계속 움직이는 것으로 읽힌다. 현재 상태와 연결되지 않는 사건은 희귀한 분위기 변화를 만드는 경우에만 우선순위를 얻는다.

편성 결과는 런의 난수 기준값과 안정 ID를 사용해 같은 상태에서 같은 후보가 나오도록 기록해야 한다. 실제 비용과 결과는 물질, 작업, 전투, 건강, 관계와 세력 체계가 판정한다. 극적 호흡을 위해 소비나 부상 규칙을 우회해서는 안 된다.

압력 기반 편성과 공통 장기 사건 작업의 구현 판정은 [시스템 구현 권위 체크리스트](../system-implementation-checklist.md)에 따른다.

## 사건 밀도와 플레이어의 주의력

사건이 많아도 동시에 너무 많이 제시하면 모든 선택이 알림 처리로 변한다. 중요한 사건, 긴급 사건과 자동 소사건은 서로 다른 주의 예산을 사용한다. 같은 참여자를 여러 중요 사건에 동시에 묶거나 같은 범주의 위기를 연속 발생시키는 일을 제한한다.

사건 밀도를 제한하는 이유는 콘텐츠를 숨기기 위해서가 아니다. 플레이어가 선택의 원인과 비용과 결과를 읽을 시간을 확보하기 위해서다. 자동 소사건은 요약할 수 있고, 중요한 사건은 기한과 현재 진행 상태를 명확히 보여 줘야 한다.

후보 선택은 런의 난수 기준값, 사건 ID, 절대일과 정렬된 참여자 ID를 사용한다. 저장과 재개, 화면을 다시 여는 행동으로 후보와 보상을 다시 추첨할 수 없어야 한다. 같은 세계 상태에서는 같은 결과가 나온다는 신뢰를 지키기 위한 규칙이다.

## 서사 문구와 규칙의 경계

서사 생성이나 언어 모델은 이름, 묘사, 대화와 역사 문구를 풍부하게 만들 수 있다. 그러나 발생 조건, 비용, 성공 판정, 효과와 보상은 결정론적 규칙이 소유한다. 서사 문구가 없거나 생성에 실패해도 게임 결과는 완전해야 한다.

이 경계가 필요한 이유는 문장 품질이 게임 규칙을 바꾸지 않게 하기 위해서다. 같은 사건의 비용과 결과가 문구 생성 상태에 따라 달라지면 저장, 밸런스와 플레이어 신뢰가 깨진다. 규칙이 먼저 사실을 만들고 서사는 그 사실을 표현한다.

## 사건 작성 예시

### 결빙 배관

발생 원인은 저온에 노출된 실제 유체망 구간과 유량 저하다. 사건은 영향을 받은 구역, 환자와 생산 시설, 수리 가능한 작업자와 자재를 고정한다.

플레이어는 구간을 폐쇄하고 수동 급수로 전환하거나, 위험 작업을 승인해 긴급 수리하거나, 난방을 집중해 서서히 복구할 수 있다. 폐쇄는 운반 노동과 서비스 중단을 만들고, 긴급 수리는 작업자 노출과 자재를 요구하며, 난방은 연료와 전력을 다른 곳에서 가져온다.

결과는 실제 밸브 폐쇄, 물 공급, 수리 작업과 노출 상태로 판정한다. 복구가 늦으면 병동, 식당과 생산의 부족 상태가 이후에도 남는다.

### 도제의 큰 실수

발생 원인은 실제 제작 실패나 저품질 배치와 기여한 도제다. 선택은 재료를 손실 처리하고 징계하거나, 대가의 시간을 써 재작업하고 교육하거나, 납기를 우선해 불량품을 사용하도록 승인하는 식으로 달라질 수 있다.

재작업은 생산 재료와 멘토 노동을 쓰지만 숙련과 관계에 다른 결과를 남긴다. 불량 사용은 현재 납기를 지키지만 장비 고장이나 서비스 사고의 미래 후보를 만들 수 있다. 사건이 작업 이력에서 시작하고 다시 생산과 경력으로 돌아가므로 인물 서사와 경제가 함께 움직인다.

### 서비스 난투

발생 원인은 같은 서비스 세션에 참여한 실제 손님과 주민, 관계 기억, 음주나 문화 갈등이다. 경비를 투입하면 빠르게 제압할 수 있지만 부상과 공포와 세력 반응이 생길 수 있다. 협상은 사교 인력과 시간을 요구하며 영업이 중단될 수 있다. 가해자를 은폐하면 단기 평판을 보존하지만 피해자 관계와 발견 위험을 남긴다.

해결 뒤에는 치료, 파손 물품, 체포 상태, 배상, 관계와 해당 세력의 반응이 각 권위에 기록된다. `평판 감소` 한 줄로 끝내지 않는 이유는 서비스 공간과 인물과 정책이 실제 원인이었기 때문이다.

## 조립식 사건 작성 절차

새 사건을 작성할 때는 다음 순서를 따른다.

1. 사건이 필요한 이유와 플레이어가 내릴 새로운 판단을 적는다.
2. 실제 발생 근거와 다시 검사할 수 있는 원인 증거를 정한다.
3. 참여자, 시설, 물건, 지역과 세력의 안정 참조를 정한다.
4. 선택마다 물질, 필요한 기능, 인력, 정책, 시간과 위험 요구를 작성한다.
5. 선택마다 실제로 실행할 행동과 진행 단계를 비교한다.
6. 예약, 현재 책임, 취소, 대상 상실과 기한 종료를 정의한다.
7. 성공, 부분 성공과 실패를 가르는 완료 기록을 정한다.
8. 최종 수치 효과와 영속 흔적을 분리한다.
9. 이후 어떤 시스템이 결과를 읽고 반응하는지 정한다.
10. 저장과 복원, 중복 실행과 결정론을 감사한다.

기존 발생 조건과 결과만 필요한 작은 사건은 현행 공통 경로를 조합한다. 새로운 행동이 필요하면 개별 사건 전용 분기보다 여러 콘텐츠가 재사용할 기능, 상태 권위와 실행 규칙을 추가한다.

사건별 발생, 작업, 해결과 후속 설계는 [시스템 콘텐츠 상세 카탈로그](../game-design/systemic-content-event-catalog.md), 공통 인과 계약은 [시스템 콘텐츠 통합 설계](../game-design/systemic-content-integration-design.md), 대표 사건이 플레이어에게 만드는 발견·결단·수습·후폭풍은 [사건 수직 슬라이스](../game-design/systemic-event-vertical-slices.md), 유형별 설계 행은 [콘텐츠 설계 기록](../game-design/content-plans/README.md)을 따른다. 현재 구현 사실과 적용 범위는 [시스템 구현 권위 체크리스트](../system-implementation-checklist.md)가 최종 판단한다.
