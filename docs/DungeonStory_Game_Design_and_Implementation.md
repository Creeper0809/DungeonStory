# DungeonStory 게임 설계·구현 현황 종합 문서

> 기준일: 2026-07-30
> 분석 범위: `Assets/Scripts`, ScriptableObject/Resources 데이터, 프리팹·씬, 빌드 설정, 기존 게임 디자인·구현 보고서·QA 기록, 현재 Unity Editor의 `GameplayScene`  
> 목적: 현재 **실제로 구현된 기능**, 기능들이 만드는 **게임 루프**, 코드와 데이터에서 드러나는 **콘텐츠 기획**, **플레이어 경험과 UX 계약**, **개발 중이거나 검증이 필요한 부분**을 한 파일에서 파악한다.

## 1. 게임의 현재 정체성

DungeonStory는 플레이어가 인간 모험가가 아니라 **몬스터 던전의 주인**이 되어, 몬스터 손님과 직원을 위한 생활·상업 공간을 운영하면서 인간 침입자를 방어하고, 반대로 인간 영역으로 원정을 보내 세계의 진실에 도달하는 **던전 경영 + 자율 시뮬레이션 + 공방전 + 로그라이트 메타 진행 게임**이다.

핵심 판타지는 다음 네 문장으로 요약된다.

1. 몬스터가 먹고, 쉬고, 일하고, 불평하고, 싸우며 살아가는 공간을 만든다.
2. 물건과 노동이 실제 위치를 이동하는 경제를 운영한다.
3. 점점 강해지는 인간 침입을 막는 동시에 외부 원정을 성장시킨다.
4. 한 런에서 얻은 설계·지식·기록을 다음 런의 선택지로 전환한다.

현재 프로젝트는 단순 프로토타입을 넘어 건설·물류·생산·생존·AI·전투·침입·원정·메타 진행까지 넓은 시스템 골격을 갖췄다. 다만 시스템의 양과 기술적 완성도에 비해 신규 플레이어가 구조를 자연스럽게 이해하는지, 콘텐츠 밀도·밸런스·보상 리듬이 적절한지는 별도의 사람 중심 플레이테스트가 필요한 상태다.

## 2. 상태 판정 기준

| 상태 | 의미 |
|---|---|
| **구현·연결됨** | 런타임 등록, 이벤트 연결, UI 또는 저장 구조, 기존 테스트 근거가 함께 확인됨 |
| **구현됨·재검증 필요** | 코드와 과거 QA 근거는 있으나 현재 대규모 변경 이후 전체 회귀 검증이 필요함 |
| **현재 개발 중** | 작업 트리에 구현이 있으나 활성 계획의 통합·최종 검증이 끝나지 않음 |
| **기획/장기 후보** | 문서·TODO에서 방향은 확인되지만 현재 완성 기능으로 볼 수 없음 |

분석 시점의 Unity Editor는 Unity `6000.3.8f1`로 연결되어 있고 컴파일·업데이트·PlayMode가 모두 정지된 정상 편집 상태였다. Console Error/Warning 조회는 0건이었다. 단, 활성 `GameplayScene`은 수정 상태이므로 이 문서는 커밋 기준점이 아닌 **현재 로컬 작업 상태**를 설명한다.

## 3. 플레이어가 실제로 하는 일

### 3.1 던전을 설계한다

- 그리드 위에 방, 벽, 문, 가구, 작업·생산·상업·방어 시설을 배치한다.
- 시설은 즉시 생기지 않고 건설 현장, 재료 운반, 작업을 거쳐 완성된다.
- 방의 면적, 출입구, 역할, 청결, 미관, 조명, 온도, 환기, 보호 상태를 관리한다.
- 문별로 집단·개인 출입 권한과 잠금 정책을 설정한다.
- 시설을 합성·진화시키며, 현재 개발 중인 인스턴스 진화에서는 사용 이력이 시설의 성격으로 남는다.

### 3.2 몬스터 사회를 운영한다

- 던전 주인과 직원을 모집하고 작업 우선순위와 허용 작업을 조절한다.
- 캐릭터는 자율 AI로 욕구를 해결하고 일을 찾으며 위험에 반응한다.
- 플레이어 명령은 매 순간 직접 이동시키기보다 중요한 목표와 우선순위를 지정하는 방식에 가깝다.
- 배고픔, 갈증, 위생, 기분, 건강, 피로, 사회적 기억과 불만이 업무·이탈·폭력에 영향을 준다.
- 부상, 질병, 정신 부담, 쓰러짐, 구조, 치료, 수술과 장기 성장을 관리한다.
- 장기 결손·이식, 보철, 이종 장기와 수술 후 재활은 캐릭터의 실제 신체 능력에 반영된다.

### 3.3 물리 경제를 굴린다

- 금화를 제외한 주요 자원은 월드의 실제 아이템 스택이다.
- 재료는 창고에 저장되고 목적지에 예약된 뒤 운반자가 시설 버퍼로 옮긴다.
- 생산 주문은 재료, 연구, 작업자와 시설 상태를 확인해 진행된다.
- 상점, 손님 소비, 제작, 식사, 무장, 원정 보급, 전리품 회수와 도난이 같은 물류 체계를 사용한다.
- 작물·목재·광물·축산물은 채집·재배·사육·가공을 거쳐 음식, 약품, 약물, 장비와 건설 재료가 된다.
- 식단, 약물, 재질, 사육, 폐기와 재고 정책을 조절해 같은 원료도 서로 다른 소비망으로 보낸다.
- 부패물은 조용히 삭제되지 않고 사료, 퇴비, 연료, 독소, 소각과 오염 위험으로 이어진다.
- 골드는 건설 재료가 아니라 임금, 외부 조달, 용병, 정보, 정밀 재단조, 오버클럭과 유료 방어를 선택하는 운영 자금으로 사용한다.
- 전력·상수·하수·컨베이어를 연결해 수동 운반 중심의 작업장을 단계적으로 공장화한다.
- 영업 결산에서 매출, 재고, 유지보수, 직원 상태, 급여·부채와 사건을 확인한다.

### 3.4 손님을 만족시킨다

- 일반 손님과 종족별 방문객을 받고 접객·시설 이용·결제·퇴장을 처리한다.
- Slime, Orc, Vampire는 서로 다른 선호를 가진 핵심 고객·직원 종족이다.
- 입구, 접수, 경비, 대기 공간과 외부 청결이 첫인상에 영향을 준다.
- 만족, 종족별 방문, 시설별 매출과 소비 재고가 운영 결산에 누적된다.

### 3.5 인간 침입을 막는다

- 침입 위협이 상승하면 경고를 보고 경비 인력, 동선, 시설, 장비와 전술을 준비한다.
- 근접 차단, 예비 경비 교대, 원거리 사격, 엄폐, 제압, 방패·방어구·탄약을 사용한다.
- 던전 주인은 위험할 때 행정실 또는 가장 안전한 위치로 대피한다.
- 침입을 버티면 런은 계속되지만 방어 보스를 처치하는 것만으로 최종 승리하지는 않는다.

### 3.6 인간 영역으로 원정한다

- 최대 5명을 전열·중열·후열의 6칸 진형에 편성한다. 던전 주인은 원정대에 들어가지 않는다.
- 런 시드로 생성된 영구 육각 월드에서 동적 거점, 고정 보스 권역과 긴급 거점을 발견한다.
- 지형·도로·날씨·부상·적재량을 반영한 육각 A* 경로로 실제 이동한다.
- 이동·정찰·협상·잠입·야영·전리품·귀환 사건에서 좌우 두 선택지 중 하나를 고른다.
- 전투에서는 캐릭터별 명령 카드, 적 의도, 맞대응, 전술 사슬과 덱 밖 명령을 조합한다.
- 체력, 스트레스, 보급, 탄약, 장비, 결의와 전리품을 관리하며 생존자는 실제 외부 진입로로 귀환한다.
- 목표 달성 뒤에는 특정 귀환로를 강제하지 않고 최단거리 칸 수만큼 안전 이동 보호를 받는다.
- 긴급 거점을 방치하면 던전의 온도·위생·기분·조명·방어 효율과 침공 경고가 악화된다.
- 마지막 `truth_core`에서 진실을 밝혀야 런의 최종 승리가 된다.

### 3.7 산업 기반을 자동화한다

- 발전기, 축전지, 차단기와 우선순위 회로를 연결해 의료·식수·방어·생산의 전력 배분을 관리한다.
- 상수도와 하수도를 위생, 조리, 수술, 농업과 산업 시설에 연결한다.
- 물통 급수와 직원 운반은 비상 대체 수단으로 남기고, 안정된 배관망은 반복 노동을 줄인다.
- 컨베이어의 입력·출력·필터·분배·합류·우선순위와 층간 리프트를 구성한다.
- 막힌 물류망은 원인을 추적하고 오버플로 게이트로 예비 창고 또는 바닥에 실물 아이템을 배출한다.
- 기존 시설은 철거하지 않고 전력 보조와 자동화 모듈을 설치해 `Manual → PoweredAssist → Automatic`으로 개조한다.

## 4. 전체 게임 루프

### 4.1 런 전체 흐름

```text
타이틀/세이브 선택
        ↓
시작 준비
  └─ 주인 1명 + 같은 종족 직원 2명
  └─ 후보 교체·리롤·초기 스킬/특성 생성·확정
        ↓
던전 기반 구축
  └─ 방·시설 건설
  └─ 물류·생산·연구·직원·기반 시설 배치
        ↓
일상 운영
  └─ 손님 접객 → 소비 → 매출
  └─ 욕구 해결 → 작업 → 재고 변화
  └─ 전력·상하수도·자동화 상태 관리
  └─ 결산 → 문제 원인 파악 → 다음 선택
        ↓
위협 상승과 침입
  └─ 경고 → 방어 준비 → 교전 → 피해 복구
        ↓
외부 원정
  └─ 파티 편성 → 육각 이동·선택 사건 → 명령열 전투
  └─ 거점 해결·지역 약화 → 안전 이동 → 실물 귀환
        ↓
10일 주기 보스와 무한 방어 강화
        ↓
최종 진실 발견 = 승리
주인 사망/런 붕괴 = 패배
        ↓
런 결과와 메타 보존 → 다음 런
```

### 4.2 날짜별 런 단계

| 날짜 | 단계 | 의도 |
|---|---|---|
| 1~3일 | `Preparation` | 최소 생활·물류·접객 기반 마련 |
| 4~6일 | `Growth` | 생산·연구·직원·시설 확장 |
| 7~9일 | `Escalation` | 침입 대비와 외부 원정 압박 상승 |
| 10일 이후 | `EndlessDefense` | 반복 보스와 누적 강화 속 장기 생존 |

보스 침입은 10일마다 예약된다. 주기마다 보스 체력과 피해는 약 35%, 위협 상승은 약 20%씩 누적 강화된다. 방어는 생존과 성장 시간을 벌어 주지만 최종 승리는 공격 원정의 진실 발견에 연결된다. 따라서 “기지에서 더 버틸 것인가, 위험을 감수하고 밖으로 나가 결말을 앞당길 것인가”가 장기 긴장을 만든다.

### 4.3 하루 운영 흐름

```text
재고·직원·방 상태 확인
  → 작업/생산/연구 우선순위 조정
  → 재료 예약과 운반
  → 전력·급수·배수·컨베이어 가동 확인
  → 시설 가동·접객·욕구 해결
  → 고장·오염·교착·부상·불만·외부 사건 대응
  → 매출·소모·급여·계약·자동 조달·사건 결산
  → 원인을 추론해 다음 날 건설·구매·배치·자동화 결정
```

UI의 기획 원칙은 정답을 바로 표시하기보다 **문제 발생 → 감정/알림 → 상세 기록 → 원인 지식 축적 → 해결책 추론 → 다음 선택 실행**의 흐름을 제공하는 것이다.

## 5. 구현된 시스템 상세

### 5.1 타이틀, 시작 준비, 세이브

**상태: 구현·연결됨**

빌드 씬 순서는 `TitleScene → StartPreparationScene → GameplayScene → SampleScene`이다. `CharacterAiTestScene`은 빌드 밖의 테스트 씬이다. `SampleScene`은 출시 빌드에서 필요한지 점검할 필요가 있다.

타이틀 씬은 설정, 오디오, 세이브 슬롯, 난이도와 씬 이동에 집중한다. 시작 준비 씬은 주인·캐릭터 카탈로그, 로컬 LLM 큐, 스킬 생성과 시작 3인 편성 UI를 구성한다.

- 주인 1명과 같은 종족 직원 2명으로 시작
- 선발 직원 2명과 예비 직원 4명을 드래그로 교체
- 전체·정체성·재능·스킬 리롤과 첫 액티브·패시브 생성
- 주인별 고정 전용 스킬 4칸과 별도의 일반 성장 슬롯
- 주인은 원정 참가 불가
- 오펜스 원정 파티 최대 5명

`SampleScene`은 디버그용으로 역할이 바뀌었지만 현재도 `GameplayScene` 뒤에 빌드 씬으로 등록되어 있다. 제품 경로는 `TitleScene → StartPreparationScene → GameplayScene`이며 출시 전 `SampleScene`의 빌드 포함 여부를 정리해야 한다.

세이브는 다음 범주를 분리해 보존한다.

- 난수 스트림과 런 흐름
- 물리 아이템, 창고, 작업, 생산 주문, 재고 정책
- 금고 거래 장부, 임금·용병 계약, 자동 조달, 오버클럭과 유료 방어 정책
- 전력 노드, 상하수도 유량·수질, 컨베이어 운반물·교착·오버플로와 시설 자동화 상태
- 지역 공급 계약, 대형 프로젝트, 폐기물
- 야생동물, 월드 자원, 작물
- 생존 욕구, 신체 건강, 의료
- 해부 구조, 수술 주문, 장기·보철, 수술 정책과 회복
- 장비, 장비 진화, 유지보수
- 방어 전술·직접 명령
- 포획·서커스·사육
- 외부 구역·외부 사건
- V17 육각 월드, 동적·긴급 거점, 이동·선택 사건, 명령 덱·전투, 안전 이동과 원정 귀환
- 침입과 결산·알림
- 연구, 상점, 손님, 불만, 도감
- 런 변수와 메타 진행

현재 전역 저장 버전은 V17이다. 하위 도메인은 독립 섹션 버전을 가지며 V17이 아닌 전역 세이브는 복원을 거부한다. 일부 오래된 검증 코드는 아직 V16을 기대하므로 최신 전체 회귀에서 갱신해야 한다.

공유 ScriptableObject를 개별 진행 저장소로 직접 변형하지 않고 캐릭터·시설·장비 인스턴스 상태를 별도로 저장하도록 설계되어 있다.

### 5.2 그리드, 건설, 방과 문

**상태: 구현·연결됨**

```text
건설 명령 → 건설 현장 → 재료 요청 → 창고 예약
→ 운반 → 작업량 누적 → 완성 건물로 교체
```

작업 주문은 `WaitingForMaterials`, `Ready`, `InProgress`, `Completed`를 기본 흐름으로 가지며 `Blocked`, `Cancelled`도 제공한다. 취소 시 목적지 예약과 운반 중 재료를 해제·회수할 수 있다.

방은 다음 값을 계산한다.

- 사용 가능 여부, 열린 경계, 문 누락, 독립 공간 여부
- 면적, 빈 공간, 문·벽 수, 방 역할
- 고급스러움, 위생, 공간감, 아름다움, 청결
- 인상도, 차폐, 온도, 환기, 조명

방 환경은 시설 선호와 운영·연구·보급·경비·제작 시간에 최대 약 ±15% 영향을 준다. 구조·시설·오염 버전을 이용한 캐시도 있다.

물리 Grid는 던전 내부뿐 아니라 입구, 하차장과 외부 진입로까지 이어진다. 셀은 내부, 입구, 하차장, 외부 통로, 차단 외부를 구분하며 방 판정은 내부 셀만 사용한다.

연속 벽·문 공사는 `ConstructionSafetyPlanner`가 완성 후 점유를 가상 계산해 작업자 퇴로, 남은 공사와 재료 배송 경로를 막는 후보를 뒤로 미룬다. 직접 강제 공사는 허용하지만 갇힘 위험을 표시한다.

문은 다음 출입 규칙을 지원한다.

- 사장, 직원, 손님, 포로, 침입자, 야생동물, 포획 동물 그룹
- 영속 ID 기반 개별 허용·차단
- 모두 허용, 직원 전용, 손님 구역, 감방, 동물 우리 프리셋
- 같은 방 적용과 정책 복사·붙여넣기
- 호송 작업용 임시 통행권과 플레이어 직접 명령 우회
- 권한 변경 시 경로 캐시 무효화와 이동 직전 재검사

문 함정 같은 복합 방어는 장기 후보지만 출입 통제 자체는 현재 기능이다.

### 5.3 물리 아이템, 창고와 운반

**상태: 구현·연결됨**

```text
  → 목적지에 예약된 Stored
  → 작업자가 운반 중인 Carried
  → FacilityBuffer
  → 생산/건설/진화에서 소비
```

구현 내용:

- 아이템 스택 생성·병합·분할·바닥 드롭

- 스택 일부 수량 예약과 운반자별 중복 방지
- 같은 방향·가까운 경로·같은 저장 권역을 묶는 다중 픽업 운반 계획

한 칸에 여러 스택이 겹치면 대표 마커 하나와 총수량·종류 배지를 표시한다. 클릭하면 같은 칸의 모든 스택을 행 목록으로 보여 주고, 행을 선택하면 수량, 무게, 가치, 상태, 예약자, 목적지, 신선도와 처리 명령을 보여 주는 상세 화면으로 전환한다. 선택 스택이 병합·운반·삭제되면 목록으로 안전하게 돌아간다.

클릭 선택 우선순위는 기본적으로 `Character > Wildlife > Item > Construction > Building`이며 Alt로 정확한 칸의 아이템 더미를 우선 선택할 수 있다. 근처 시설을 추정 선택하지 않는다.

### 5.6 생존, 건강, 위생과 사회적 붕괴

**상태: 구현·연결됨**

생존 상태는 배고픔, 갈증, 위생, 기분, 건강, 피로와 작업 가능 상태를 포함한다. 결핍이 심해지면 절박한 욕구 해소, 안전하지 않은 물 섭취, 굶주림 폭력, 식인, 붕괴, 비치명 제압으로 이어질 수 있다. 실제 식사 완료 때만 영양을 소비한다.

건강 체계:

- 신체 부위별 부상과 출혈
- 쓰러짐
- 감염과 질병 위험
- 정신 부담
- 금기 목격 기억
- 이동·작업 속도 변화
- 구조, 치료, 건강 UI

위생 체계는 오염·얼룩, 청소, 시체, 도축 부산물과 폐기물 처리로 연결된다.

#### 수술과 전문 의료 시설

**상태: 구현·연결·PlayMode 검증됨**

수술은 일반 치료와 분리된 `work:surgery` 주문이다. 환자, 의사, 집도 시설, 같은 방의 지원 설비, 약품·마취제·이식 부품을 예약하고 다음 단계를 누적 작업량으로 진행한다.


해부 구조는 문자열 ID 기반이며 현재 인간형, 사족형, 슬라임 3개 프로필을 제공한다. 13개 수술은 응급 봉합, 수혈, 이물 제거, 절단, 장기 봉합, 생체·사체 적출, 자연 장기 이식, 보철·임플란트 설치, 이종 이식, 비전 개조와 재활을 다룬다.

전문 의료 시설은 13종이다.

| 구분 | 시설 |
|---|---|
| 응급·해부 | 응급 처치대, 해부대 |
| 일반 외과 | 외과 수술대, 세정대, 마취 장치 |
| 보철·회복 | 보철 조립대, 재활 보조대 |

같은 닫힌 의료 방의 정상 시설만 무균도, 마취 안정성, 이식·면역과 회복 보정을 제공한다. 장기·보철은 기증자, 종족, 부위, 품질, 신선도와 오염을 가진 고유 인스턴스이며 장기 보관함은 보존 기간을 연장한다. 적출 중복, 생명 장기 제거, 이종 적합도, 거부 반응, 감염과 돌연변이 위험을 추적한다.

실제 포인터로 수술 예약, 약품 운반·소비, 12 작업량 누적, 전체 단계 진행과 환자 회복을 검증한 QA 기록이 있으며 해당 기록의 Console Error/Warning은 0건이다.

### 5.7 생산, 연구와 운영 경제

**상태: 구현·연결됨**

생산 주문은 지정 횟수 반복 또는 목표 재고 도달 모드를 사용한다. 주문별 중단, 최소 비축량, 허용 재료·작업자, 연구 조건을 설정할 수 있다. 재료 부족 시 `WaitingForMaterials`, 준비되면 `Ready`, 수행 중에는 `InProgress`가 된다.

데이터에 준비된 생산 사슬:

- 농사·수확·채집
- 벌목·제재·숯
- 채석·석재 가공
- 채굴·제련·귀금속
- 밀링·양조
- 직조·무두질
- 퇴비·폐기물
- 증류
- 조리·훈연·사료
- 제약·연금술
- 대장간·장비 제작

현재 경제 데이터는 아이템 101개, 생산 조합 129개, 작물 8개, 장비 주재료 12개, 약물·기호품 7개다.

- 장비 형태와 주재료를 분리해 같은 무기·방어구도 피해, 관통·방어, 내구도, 무게와 가치가 달라진다.
- 음식은 실제 재료를 기준으로 비건·채식·혼합·육식과 금기를 판정한다.
- 약물 정책은 금지, 의료 전용, 전투·기분 조건과 예약 복용을 지원하며 내성·중독·금단을 저장한다.
- 축산은 길들이기, 방목장·축사, 성별·성장·번식, 산출물, 합사 위험과 자동 도축으로 이어진다.
- 재고 정책은 최소·목표·최대량과 초과 판매·가공·퇴비·해체를 제공한다.
- 지역 공급 계약과 대형 프로젝트가 후반 원자재·가공재·완제품 소비처가 된다.

연구는 현재 자산 기준 118개 프로젝트다.

- 기존 생산·생존·운영 연구 72개
- `해부학 → 외과술 → 보철 공학 → 장기 보존 → 이종 이식 → 이형 개조` 의료 연구 6개
- 증기 동력, 배전, 축전, 전동 공구, 컨베이어, 분류, 자동 생산, 정밀 자동화와 룬 산업 연구 32개
- 배관 기초, 저수와 밸브, 전동 급수, 수세 위생, 하수 배관, 오수 침전, 정수 재이용과 룬 정화 순환 연구 8개

연구 화면은 카드 목록이 아니라 결정적 레이어드 배치의 전체 화면 트리다.

- 이름·설명·해금 콘텐츠 검색과 분야 필터
- 빈 공간 드래그 이동, 커서 중심 `0.55~1.45` 확대·축소와 맞춤 보기
- 자동 선행 연구 큐, 활성 연구 고정, 대기 순서 드래그
- 프로젝트별 영구 진행률과 차단 사유
- `None`, `Required`, `Shortcut` 설계도 규칙
- 하차장에 도착한 물리 설계도를 연구실의 8칸 보관대까지 운반하는 흐름
- 보관대 파괴·열린 방·도난 시 연구 일시 중단과 진행률 보존
- 1600×900 전체 화면과 900×1600 상세/연구 큐 하단 시트
- 선택형 연구 화면 자동 일시정지와 기존 배속 복원

#### 금고 중심 경제

골드는 월드 스택이 아니라 추상 자금으로 유지한다. 일반 건설과 제작은 골드가 아니라 물리 재료와 작업량을 사용하며, 골드는 **외부 시장·계약을 이용하거나 위험한 성능을 짧게 끌어내는 선택 자원**이다.

- 시작 사장과 시작 직원 2명은 무임금이다.
- 이후 영입 직원은 `30 + 레벨×2 + 역할 가산금`의 임금을 받는다.
- 용병은 `60 + 레벨×4 + 장비 등급 가산금`의 일급을 선불·갱신 방식으로 받으며 갱신 실패 시 실제 출구로 떠난다.
- 지출 우선순위는 `임금 → 용병 갱신 → 유료 시설 계약 → 자동 구매`다.
- 모든 성공·실패 거래는 출처, 대상, 금액, 게임 시각과 실패 사유를 `EconomyTransactionLedger`에 기록한다.

자동 조달은 상점 갱신 직후 하루 한 번 실행한다.

- 원자재·소모품은 목표 수량, 최대 단가, 일일 최대 수량과 우선순위를 설정한다.
- 설계도·장비·시설 키트는 정확한 ID 또는 태그 기반 찜 목록을 사용한다.
- 기본 일일 예산은 500골드다.
- 보호 자금은 플레이어 최소액과 향후 3일 임금·용병·계약비 중 큰 값이다.
- 창고뿐 아니라 하차장, 운반 중, 시설 버퍼와 예약 배송을 보유량에 포함한다.
- 구매품은 창고에 순간 추가되지 않고 하차장 실물 스택으로 도착한다.
- 날짜와 상품 처리 키를 저장해 로드 재구매를 막는다.

골드를 쓰는 고급 운용은 기본 성장 조건을 대체하지 않는다.

- 정밀 재단조는 결과 변동 축소, 부담 계열 억제, 외부 기술 지원 중 최대 2개를 구매한다.
- 장비·지원 시설 오버클럭은 24게임시간 동안 통제·공격적·임계 단계의 성능과 오작동·과부하를 함께 부여한다.
- 금고 연동 방어시설은 위협도, 보스 전용, 침공당 예산과 보호 자금을 확인한 뒤 발사마다 골드를 지불한다.
- 뇌물과 정보 구매는 사건 생성 시 가격과 결과가 고정되며 오펜스에서는 출정 시 배정한 현장 자금을 사용한다.

HUD의 골드는 좌측 대형 패널이 아니라 우측 상단 자원 목록 마지막에 표시한다. 골드를 선택하면 오늘 수입·지출, 임금, 용병비, 자동 구매 예산, 보호 자금과 3일 예상 잔액을 확인한다.

영업 결산은 매출, 방문 수, 만족도, 시설별 매출, 종족별 방문, 소비·창고 재고, 보급 실패, 시설 피해·수리, 사건·알림, 직원 근무·피로·기분, 유지비·급여, 부채·지급·마감 잔액과 연속 적자를 집계한다. 이력은 최근 20개까지 보존한다.

### 5.8 손님, 상점, 평판과 불만

**상태: 구현·연결됨**

일반 손님 런타임, 종족별 방문객, 손님 스포너와 방문 스케줄이 Gameplay composition root에 연결되어 있다.

- 손님 유입과 대기
- 접수와 첫인상
- 종족 선호에 따른 시설 선택
- 시설 이용과 재고 소비
- 상점 재고와 구매
- 만족도, 평판과 정산
- 불만, 불평, 이탈과 반란 행동
- 보상 방문객과 특수 손님
- 손님·시설·종족 도감

이 영역은 방 환경, 직원 서비스, 외부 구역, 물류와 결산을 묶는 일상 루프의 중심이다.

### 5.9 전투 공통 규칙과 장비

**상태: 구현·연결됨**

공통 전투 해석기를 던전 방어, 외부 원정과 사냥이 공유한다.

- 근접·원거리·회수 가능 투척
- 사거리와 발사 모드
- 명중, 회피, 공격 방향
- 엄폐, 아군 오사와 관통
- 신체 부위 타격, 출혈과 제압
- 무기, 방어구, 방패, 탄약
- 장비 품질과 내구도

현재 장비 데이터는 무기 9종, 방어구 8종, 방패 2종이며 엄폐 건물은 3종이다. 공격, 방패 막기, 방어구 피격은 현재 개발 중인 장비 진화·조율 사용 기록에도 공급된다.

전투 태세에서는 생활 AI를 중단하고 이동, 공격, 강제 사격, 엄폐, 무기 교체, 재장전, 사격 모드, 사격 중지와 구조 명령을 직접 내릴 수 있다. 피아 관계는 직원·사장, 보호 중립 손님, 적대 침입자·반란자와 사냥 지정 동물을 구분한다. 자동 사격은 아군·중립 사선을 보류하고 강제 사격만 실제 중간 인물 오발을 허용한다.

쓰러진 캐릭터는 비차단 점유로 바뀌고 모든 일반 작업·전투 예약을 해제한다. 현장 안정화, 실제 환자 운반, 병상 치료와 복귀가 같은 의료 주문 흐름으로 이어진다. 팔·다리·의식·혈액 손실은 이동, 조작, 재장전과 작업 능력에 반영된다.

장비 수리 정책은 자동 수리 임계값, 복귀 내구도, 침공 중 탈착과 대체 장비 우선 여부를 캐릭터별로 배정한다. 수리·재장전·투사체·출혈·구조·치료 연출과 시간은 게임 정지 중 진행되지 않는다.

### 5.10 침입과 던전 방어

**상태: 구현·연결됨**

- 위협도와 침입 경고
- 일반·10일 주기 보스 침입
- 경비 정책과 배치
- 선두 차단자 1명과 인접 예비 경비 교대
- 원거리 사격과 엄폐
- 직접 전투·제압 명령
- 방어 전술 오버레이
- 장비·탄약·시설 준비
- 주인 대피
- 침입 결과 보고서
- 시설 피해와 사후 수리

침입자는 즉시 던전에 나타나지 않고 외부에서 집결해 준비 시간을 제공한다. 경비는 외부 집결 중인 적에게 몰려가지 않고 침입자가 내부에 들어온 뒤 저지 위치를 잡는다. 선두 경비와 침입자가 서로 다른 인접 칸에서 교전하며, 저지된 침입자는 시설 공격이나 추가 진격을 할 수 없다. 예비 경비는 뒤에서 교대를 기다리고 빈 전선이 생기면 침입자가 다시 전진한다.

교전 중 이동은 각 그리드 스텝 전 대상을 다시 확인해 오래된 위치를 따라가거나 자유 이동을 막지 않게 한다. 원거리 경비는 엄폐, 유효 거리, 사선, 혼잡, 탄약과 후퇴 경로를 평가하고 전술 조정기가 여러 침입자에게 목표를 분산한다.

### 5.11 공격 원정과 세계 진행

**상태: V17 구현·연결·전용 시나리오/시각 검증됨**

제품 경로는 기존 3인 선형 노드 원정이 아니라 **영구 육각 월드맵, 실제 여행, 두 선택지 사건, 5인 명령열 전투와 실물 귀환**이다. 레거시 원정 모델과 패널은 호환 코드로 남아 있으나 V17 원정에서는 기존 전투 표면을 숨긴다.

#### 육각 세계와 거점

- 런 시드로 지형, 도로, 강, 지역 경계와 안개 상태를 결정적으로 생성한다.
- 일반 거점은 날짜·세력 활동·사건에 따라 생성·강화·이동·소멸한다.
- 경쟁 던전과 `truth_core`는 고정 보스 권역이다.
- 농장, 상단, 무기고, 채석장, 감시탑, 순찰대, 폐허, 기록소, 수송대와 의식 장소를 포함한 12개 거점 원형을 제공한다.
- 지형 비용, 도로, 날씨, 부상과 적재 무게를 반영한 육각 A* 경로로 이동한다.
- 거점 해결은 점령이 아니라 지역의 물류·무장·병력·정보 압력과 물리 전리품으로 남는다.

#### 긴급 거점과 던전 압박

긴급 거점은 징후, 경고, 위기, 철수 준비, 철수 단계로 진행한다. 현재 6개 원형이 던전의 온도·연료 부담, 기분·휴식, 위생·질병, 조명·원거리 명중, 자동 방어 효율과 침공 경고를 실제로 수정한다.

플레이어는 거점을 파괴하거나 냉각 운전, 방어망 재조율, 방음, 방역, 추가 조명, 역정찰 작업으로 일부를 완화할 수 있다. 완화는 시설·재료·연료와 `work:threat-mitigation` 작업량을 요구하며 거점 자체를 제거하지는 않는다.

#### 두 선택지 사건

이동, 정찰, 협상, 잠입, 야영, 전리품과 귀환 단계에서 좌우 두 선택지 카드를 사용한다. 현재 초기 사건 카드는 49개다.

- 수치 대신 보급 감소, 경계 상승, 부상 위험 같은 방향·강도를 먼저 표시
- 인물, 장비, 도구와 정보 조건에 따른 선택지 강화·변형
- 높은 정보에서 증원, 매복, 철수로와 숨은 보상 공개
- `runSeed + expeditionId + eventSequence` 기반 결정론으로 저장 재굴림 차단
- 골드를 뇌물, 통행료, 정보 구매, 거래와 현장 수리에 사용

#### 5인 명령열 전투

원정대는 최대 5명이며 전열 2, 중열 2, 후열 2의 6칸 진형을 사용한다. 현재 전투 인카운터 원형은 6개다.

- 캐릭터별 개인 명령 덱과 매 턴 두 장의 후보
- 적 의도, 대상과 공격 종류 상시 표시
- 방어, 재장전, 무기 교체, 아이템, 후퇴는 덱 밖 명령
- 적 의도 가로채기와 1~3단계 맞대응
- 저지, 기동, 파쇄, 지원, 집행 태그의 전술 사슬
- 행동 성공 100%, 자동 재지정 75%, 맞대응 완패 50%, 행동 전 무력화 25%, 불법·취소 0%의 사슬 전달
- 두 명 연속 행동 불능일 때 사슬 종료
- 결의 100에서 전투당 한 번 사용하는 별도 궁극기

연출은 기술마다 전용 프리팹을 만들지 않는다. 런타임 카드 프레임, 명령 인장과 공용 파편을 조합해 카드 격돌을 표현하고 실제 캐릭터에는 짧은 흔들림, 피격 플래시, 부위·피해·출혈 표시만 사용한다. 카드를 선택하거나 격돌을 실행할 때 관련 없는 UI를 어둡게 하고 현재 맞대응·기존 대상·다음 사슬 연결만 강조한다.

#### 안전 이동과 귀환

목표 달성 시 현재 위치에서 던전까지의 최소 육각 칸 수를 `safeStepBudget`으로 지급한다. 보호 경로는 만들지 않으며 어느 방향으로 이동해도 실제 한 칸당 하나를 소비한다.

- 보호 이동 중 스트레스 증가와 위험 사건 가중치 감소
- 위험 사건 뒤 두 번의 보호 이동은 비전투 사건으로 제한
- 심각한 부상·쓰러짐·무기 부족 시 강제 전투 차단
- 다른 거점 공격을 시작하면 남은 보호 제거
- 예산 소진 뒤에도 귀환 강제 없이 정상 위험으로 자유 활동

출정 보급은 창고에서 집결지까지 실제 운반한다. 생존자는 외부 진입로로 걸어 돌아오고 전리품·남은 보급·포로·특수 동물은 하차장에 실물로 생성된다. 부상, 장비 내구도와 탄약은 던전의 수술·재활·수리·생산 루프로 돌아간다.

난이도 표시는 쉬움·보통·어려움이며 데이터 확장이 가능한 구조다. 마지막 `truth_core`에서 `OffenseTruthRevealedEvent`가 발생해야 승리한다. V17 전용 검증은 콘텐츠 수, 월드 결정성, 긴급 거점, 안전 이동, 전술 사슬, 저장 왕복, 진실 귀환과 1600×900·900×1600 지도·선택·전투 화면을 다룬다.

### 5.12 야생동물과 자연 자원

**상태: 구현·연결됨**

현재 5종은 Cave Rat, Moss Boar, Rune Deer, Shadow Hare, Shadow Wolf다.

- 서식지 자원과 방목
- 허기·갈증, 영역 중심과 무리 거리
- 풀, 물, 굴, 수풀과 소굴 패치의 소모·재생
- 풀·꽃 섭취 시 실제 장식 자원 감소와 재생
- 포식
- 사냥과 반격
- 신체 부상
- 도축
- 사체 신선도와 재생성
- 장식·환경 연결

동물은 외부의 정상 바닥 칸에서 스폰하며 종 설정이 허용할 때만 던전 내부로 들어온다. 평화 상태의 동물은 영역·먹이·물·은신처를 기준으로 이동하고 사냥·위협·고착 때만 전체 경로를 재탐색한다. 체력바는 다치거나 교전할 때만 표시한다. 사냥도 공통 전투 해석기를 사용한다.

### 5.13 외부 구역과 사건

**상태: 구현·연결됨**

외부 역할 구역은 입구, 하역, 접수, 경비 초소, 순찰, 야외 휴식, 원정 집결, 사건 지점이다. 청결, 피해, 순찰·접수 준비도, 대기 방문객, 첫인상과 작업 완료도를 추적한다.

### 5.14 포획, 사육과 서커스

**상태: 구현·연결됨**

살아 있는 쓰러진 침입자는 현장 안정화, 장비 압수, 구속구·감방 예약과 실제 호송을 거쳐 포로가 된다. 포로는 의지, 공포, 신뢰, 원한, 타락, 순응도와 탈출 위험을 가진다. 정책과 상태에 따라 청소, 운반, 급수, 연료, 건설, 수리, 도축과 제작 보조 노역을 수행한다.

강압, 격리, 심문, 회유, 교화, 각인, 혈액·기억 추출, 강제 개조와 타락 의식은 등록형 상호작용이며 담당자, 시설, 재료와 작업량을 요구한다. 의지가 낮아도 원한이 높으면 거짓 복종과 배신 위험이 남는다.

포획·서커스 관련 건물은 10종이다. 공연은 비치명 공연, 위험 묘기, 포로 결투, 야수 쇼, 야수 경기, 공개 처벌, 처형극, 타락 의식을 포함한다.

```text
구성 → 참가자 호송 → 관객 입장 → 공연
→ 정산 → 청소/치료 → 완료 또는 취소
```

치사 정책은 쓰러지면 중단, 사고 허용, 죽을 때까지 진행, 지정 대상 처형으로 나뉜다. 포획 야생동물은 운송·우리·공연·복귀·방생·탈출 상태를 가지며 먹이, 물, 질병, 길들이기와 탈출 확률이 연결된다.

길들인 동물은 방목장·축사, 합사 정책, 사료·물·깔짚, 성별·성장·번식, 산출물과 자동 도축을 사용한다. 포식자·피식자 합사는 허용하되 경고하며 굶주린 포식자는 사료, 동물성 부패물, 사체, 살아 있는 피식자 순으로 먹이를 찾는다.

### 5.17 개발자 모드와 디버그 팔레트

**상태: 구현·연결·PlayMode 검증됨**

설정의 `개발` 탭에서 기본 비활성인 개발자 모드를 켜면 HUD 중상단에 `디버그` 버튼이 나타난다. 팔레트는 게임을 자동으로 멈추지 않는 비모달 UI이며 검색과 치트, 소환, 캐릭터, 건물·작업, 생존·야생, 사건·방어, 범위, 기록 탭을 제공한다.

현재 명령 레지스트리는 중복 없는 112개 명령을 가진다.

- 자금·시간·정산 제어
- 정확한 칸의 아이템·야생동물·오염·물 소환
- 캐릭터 회복, 욕구·기분·XP·붕괴·피해 제어
- 공사·작업·연구·제작 완료와 건물 상태 제어
- 날씨, 질병, 부패, 서식지와 생존 상태 제어
- 일반·보스 침공, 외부 사건과 방어 결과 제어
- Grid, 방, 점유, 경로, 예약, 운반, AI, 야생동물, 물·오염, 침공 전선 오버레이

위치 명령은 정확한 대상이나 Grid 셀만 받는다. 좌클릭 실행, Shift 반복, 우클릭·Esc 취소를 지원하며 UI 클릭은 월드에 전달되지 않는다. 개발자 모드를 끄면 팔레트, 타기팅, 일시 치트와 오버레이가 즉시 해제된다.

팔레트 열기와 순수 오버레이는 런을 오염시키지 않는다. 상태 변경 명령이나 치트를 사용하면 `debugModified`가 저장되고 타이틀·세이브 슬롯에 `디버그 사용` 배지가 붙는다. 최근 명령 50개는 게임 시각, 명령 ID, 대상과 결과를 보존하지만 일시 치트는 로드 후 꺼진다.

실제 포인터로 설정 토글, 팔레트, 정확한 셀 소환, Shift 반복, 우클릭·Esc 취소, 오버레이, 캐릭터·야생동물·침공 명령, 1600×900·900×1600 반응형 레이아웃과 저장 메타데이터를 검증한 기록이 있다.

### 5.18 월드 가독성, 카메라와 알림

**상태: 구현·개별 시나리오 검증됨**

캐릭터와 야생동물은 월드 오브젝트 위에 이름표를 가진다. 캐릭터 이름은 평상시에도 읽을 수 있게 유지하고 체력바는 최대 체력일 때 숨긴다. 피해를 받거나 교전 중인 대상만 체력바를 드러내며, 디펜스 교전처럼 이름표가 겹칠 수 있는 상황에서는 양쪽 이름표에 수평 오프셋을 적용한다. 화면 밖 이름표와 변화가 없는 표시는 `CharacterPresentationScheduler`가 낮은 빈도로 갱신한다.

월드 카메라는 마우스 휠과 키보드 확대·축소를 지원한다. 이동과 줌은 게임 배속이 아닌 UI 시계를 사용하므로 `X5`에서도 카메라 속도가 함께 빨라지지 않는다. Pixel Perfect Camera와 UI 위 휠 입력을 고려하며, 배경 피터는 카메라 위치·화면비·orthographic size가 바뀔 때 하늘과 외부 배경을 현재 시야보다 넓게 다시 맞춘다.

이벤트 알림은 좌클릭으로 관련 정보나 위치를 열고 우클릭으로 현재 알림 목록에서 숨길 수 있다. 숨김은 사건 기록 자체를 삭제하지 않으며 같은 원인이 다시 발생하면 새 알림으로 돌아올 수 있다. UI 입력은 월드 클릭과 카메라 조작으로 전파되지 않는다.

### 5.19 전력, 상하수도, 컨베이어와 자동화

**상태: 구현·연결·GameplayScene PlayMode 검증됨**

산업 기반 시설은 기존 물리 아이템·작업량·건물 능력 구조를 교체하지 않고 그 위에 전력, 유체와 자동 운송을 추가한다. 산업 건물 자산은 32개다.

#### 공통 Utility Grid

`GridLayer.Utility`는 다음 세 채널을 같은 셀에 독립적으로 저장한다.

| 채널 | 역할 |
|---|---|
| `Power` | 발전, 저장, 배전, 소비와 차단 |
| `CleanWater` | 수원, 펌프, 탱크, 위생·조리·수술 공급 |
| `Wastewater` | 시설 폐수, 오수 저장, 처리와 역류 |

전선과 배관은 벽·바닥 아래 설치되어 이동을 막지 않는다. 연결 요소는 설치·파괴·밸브 변경 시에만 다시 계산하고 평상시에는 네트워크 스냅샷을 재사용한다. 건설에는 실제 재료 운반과 `work:plumbing`을 포함한 작업량이 필요하다.

#### 전력망

- 발전원은 목재·석탄 증기 발전기, 수차와 마나 발전기다.
- 축전지, 차단기, 변압기와 회로 구역을 구성할 수 있다.
- 소비 우선순위는 `1 의료·생명 유지·식수`, `2 방어·조명·하수`, `3 음식·위생·냉난방`, `4 생산·컨베이어`, `5 장식·비필수`다.
- 공급이 부족하면 낮은 우선순위부터 정지하고, 전력이 돌아오면 네트워크 상태에 따라 재가동한다.
- 과부하는 발열 → 효율 저하 → 차단기 작동 → 수리 작업 순서로 악화된다.
- 발전, 소비, 충전, 발열과 고장은 게임 정지 중 진행되지 않는다.

플레이어는 단순한 `전력 부족` 문구 대신 총생산, 총수요, 공급률, 저장량, 차단 상태와 정지한 소비자 목록을 본다. 소비자 상세에서는 현재 우선순위와 필요한 전력, 실제 공급 비율을 변경·확인한다.

#### 상수도, 하수와 위생

배관 내부 물은 연속 유량으로 계산하지만 기존 `Water` 물리 스택을 없애지 않는다. 물통 충전·병입 시설이 스택과 배관 유량을 상호 변환하고, 단수 시 허용된 시설은 직원이 물통을 직접 운반해 임시로 가동한다.

수질은 다음 용도를 구분한다.

| 수질 | 사용처 |
|---|---|
| `Clean` | 음용, 세면, 조리, 수술 |
| `Unsafe` | 변기, 청소, 농업, 축산, 산업 냉각 |
| `Foul` | 폐수 처리와 폐기 |

수세 시설은 실제 물을 소비하고 같은 양의 폐수를 하수망에 보낸다.

| 시설·작업 | 깨끗한 물 | 폐수 |
|---|---:|---:|
| 화장실 | 0.25 | 0.25 |
| 세면대 | 0.15 | 0.15 |
| 목욕 | 1.00 | 1.00 |
| 샤워 | 0.45 | 0.45 |
| 조리 주문 | 0.25 | 작업별 배출 |
| 수술 주문 | 0.20 | 작업별 배출 |

하수 저장 공간이 가득 차거나 배관이 막히면 시설은 `배수 불가`와 `역류 위험`을 구분해 표시한다. 역류는 해당 시설과 인접 배수구에 `Sewage` 오염을 실제 생성하며 청소와 배관 수리가 필요하다.

- 침전: 폐수 10 → Unsafe 물 6 + 슬러지
- 소독: Unsafe 물 10 → Clean 물 8.5
- 룬 정화: 폐수 10 → Clean 물 9
- 슬러지: 퇴비, 저급 연료, 독성 연금 재료 또는 소각

#### 컨베이어 물류

`GridLayer.Conveyor`의 운반물은 새로운 추상 토큰이 아니라 기존 `WorldItemStack`이다. 일반 스택, 장비, 장기, 사체와 설계도의 영구 ID·품질·신선도·오염·사체 메타데이터를 유지한다. 살아 있는 캐릭터·포로·동물은 싣지 않는다.

- 입력기, 출력기, 분배기, 합류기, 우선순위 게이트와 층간 리프트
- itemId, 재고 분류, 재질, 품질, 신선도, 오염과 금지 상태 필터
- 방향, 속도, 전력 소비, 최대 적재량과 목적지
- 컨베이어가 없는 구간의 기존 직원 운반

각 운반물은 마지막 이동 시각, 마지막 성공 노드, 대기 사유와 경로 버전을 가진다. 네트워크는 다음 상태를 구분한다.

| 상태 | 의미 |
|---|---|
| `Running` | 운반물이 정상 전진한다. |
| `Stalled` | 전원이 있고 가동 중이지만 30초 이상 전진하지 못했다. |
| `Deadlocked` | 순환 구역이 가득 차고 출구가 막혀 네트워크 전체가 전진하지 못한다. |
| `Unpowered` | 정전으로 멈췄으며 교착 시간에 포함하지 않는다. |
| `Stopped` | 플레이어 또는 시설 정책으로 의도적으로 정지했다. |

정체 원인은 `입력 포트 가득 참`, `필터 불일치`, `목적지 용량 부족`, `다음 구간 점유`, `경로 없음`, `순환 교착`과 `오버플로 출구 차단`으로 표시한다. 필터·목적지·네트워크가 바뀌면 경로 버전을 올리고 정지한 운반물을 즉시 다시 탐색한다.

`ConveyorOverflowDumpPort`는 영구 교착을 해소한다.

1. 30초 이상 막힌 운반물 중 가장 오래된 것을 선택한다.
2. 지정 예비 창고 또는 같은 분류를 허용하는 창고를 찾는다.
3. 저장할 수 없으면 게이트 앞의 이동 가능한 칸에 loose stack으로 배출한다.
4. 첫 게이트가 막혔으면 다음 도달 가능한 게이트를 찾는다.
5. 모든 게이트가 막힌 경우에만 교착과 경고를 유지한다.

오버플로는 아이템을 삭제하거나 골드로 바꾸지 않는다. 고유 장비, 장기와 사체의 ID·메타데이터도 보존한다. 순환 벨트에 배출구가 없으면 건설 UI가 경고하지만 플레이어의 설치 자체를 금지하지 않는다.

#### 시설 자동화

기존 생산 시설은 입력·출력 포트와 자동화 모듈을 설치해 다음 단계로 운용한다.

| 모드 | 작업 방식 |
|---|---|
| `Manual` | 직원이 재료 운반과 작업을 모두 수행한다. |
| `PoweredAssist` | 직원이 필요하지만 전력으로 작업 속도를 높인다. |
| `Automatic` | 재료 공급과 출력 공간이 있으면 무인 반복 생산한다. |

자동 생산도 기존 레시피, 재료, 시설 버퍼, 작업량과 물리 출력 스택을 그대로 사용한다. 고품질 제작과 수술에는 계속 숙련 작업자가 필요하다. 유지보수를 방치하면 속도 저하 → 품질 저하 → 정지로 악화되며 직원은 설정, 필터 교체, 고장 수리, 청소와 막힘 제거를 담당한다.

#### 산업 UI와 저장

산업 화면은 전력 수급, 회로 우선순위, 상수·하수 유량과 수질, 오수 용량, 컨베이어 상태와 자동화 시설을 다섯 개 섹션으로 묶는다. 월드 오버레이는 전력, 상수, 하수와 컨베이어를 독립 토글하며 HUD보다 뒤, 월드 오브젝트보다 앞에 표시하고 입력을 받지 않는다.

전역 V17은 유지하며 다음 섹션이 자기 버전으로 저장된다.

- `infrastructure.power`
- `infrastructure.fluids`
- `infrastructure.conveyor`
- `economy.automation`

실제 `GameplayScene` PlayMode 검증에서는 35개 시설을 배치한 상태에서 전력 `32 공급 / 10 수요`, 샤워를 통한 깨끗한 물 소비와 폐수 `0.45` 생성, 일반 물리 아이템의 컨베이어 10칸 이동, 자동 생산 모드, `28/28` 적재 순환망의 30.02초 교착 판정과 고유 사체 메타데이터를 보존한 오버플로 배출을 확인했다. 최종 Console은 Error 0 / Warning 0이었다.

별도 합성 스트레스는 Utility 10,000셀과 컨베이어 경로 2,000개에서 토폴로지·경로 계산의 규모만 측정했다. 이는 실제 FPS 검증이 아니며 제품 성능 근거와 구분한다.

## 6. 현재 개발 중: 시설·장비 인스턴스 무한 진화

**상태: 현재 개발 중**

현재 핵심 개발은 **같은 종류의 시설과 장비도 실제 사용 이력에 따라 서로 다른 개체로 진화하는 시스템**이다.

### 6.1 공통 원칙

- 방 자체는 영구 성장시키지 않는다.
- 시설과 장비 인스턴스가 진행 주체다.
- 사용 기록은 무한 원본 대신 계층 압축한다.
- 후보와 효과는 결정론적으로 계산한다.
- 이득에는 부담 또는 성격 변화가 붙는다.
- 촉매는 실제 아이템·경제·운반·작업을 거친다.
- LLM은 이름과 서사만 담당하며 기계 규칙을 정하지 않는다.

### 6.2 사용 기록

원본 사용 이벤트는 현재 최대 128개로 제한되고 오래된 기록은 압축 레벨, 세대 범위, 이벤트 수, 누적 크기, 결정론적 해시, 주요 사건, 참여자와 태그를 가진 세그먼트로 보존된다. 장기 런의 저장 크기를 제한하면서도 “왜 이렇게 진화했는가”의 증거를 남기는 구조다.

### 6.3 시설 진화

시설은 사용 이력과 방 환경에서 다음 3개 후보를 만든다.

- 주 역할 강화
- 방 시너지
- 위험 촉매 과부하

숙련 요구량은 현재 `120 + 60 × 세대`다. 플레이어가 세 후보 중 하나를 선택한다. 개조에는 결속 재료, 촉매, 작업량과 실제 시설 버퍼가 필요하며 재보정은 별도 주문이다.

시설 이전은 `해체 → 패키지 대기 → 재설치 → 완료/막힘` 상태를 가지며 영속 ID와 진화 이력을 유지한다. 기본 작업량은 해체가 원 건설의 약 25%, 재설치가 약 50%다.

모듈 방향은 생산량, 서비스, 연구, 생존, 방어, 오락, 방 시너지와 위험 과부하이며 이득과 부담을 함께 부여한다.

### 6.4 장비 진화와 조율

장비 방향은 균형, 근접, 원거리, 명중, 처형, 차단, 보호, 생존이다. 공격, 방패 막기, 방어구 피격이 사용 기록으로 쌓이고, 플레이어가 재련 재료를 선택하면 실제 사용 성향에서 방향이 유도된다.

재련 주문은 재료 대기, 준비, 진행, 완료, 취소, 막힘 상태를 가진다. 조율은 소유자 영속 ID별 친화도, 각성 단계, 시작 세대, 루트와 이력 노드를 기록한다.

### 6.5 촉매 경제

- 물리 촉매 예약·운반·시설 버퍼 투입
- 기존 Craft 작업을 통한 개조·재련
- 촉매 분해
- 같은 등급 정제
- potency 강화
- 기준 가치 150% 금화 교환

공통 모델, 사용 기록, 압축, 해시, 노드, 모듈, 조율과 저장 골격은 상당 부분 구현되었다. 그러나 시설·장비·촉매·작업·LLM·UI 전체 통합과 최종 회귀 검증은 활성 계획에서 아직 완료가 아니므로 출시 완료로 간주하지 않는다.

## 8. 맞물리는 하위 루프

### 건설

```text
필요 발견 → 설계/연구 → 위치·방 선택 → 재료 확보
→ 운반 → 건설 → 방 환경·동선 변화 → 효과 관찰
```

### 생산·물류

```text
목표 재고 → 원료 부족 → 채집/구매/생산 → 창고
→ 예약·운반 → 작업 → 결과 저장 → 운영/원정에서 소비
```

### 금고·자동 조달

```text
예상 임금·계약비 → 보호 자금 계산 → 상점 갱신
→ 목표 재고·찜 목록 검사 → 예산·단가 판정 → 하차장 배송
→ 실제 운반·입고 → 거래 장부·3일 잔액 예측 → 정책 조정
```

### 전력·상하수도

```text
시설 수요 증가 → 발전·저장·급수·배수망 연결 → 우선순위 공급
→ 시설 가동·위생·조리·수술 → 열·폐수·고장 누적
→ 차단·역류·단수 진단 → 연료 보충·배관 수리·정수 → 정상화
```

### 컨베이어·자동화

```text
반복 운반 병목 → 포트·필터·벨트 설치 → 전력 공급
→ 수동/전동 보조/자동 생산 → 물리 아이템 이동
→ 정체 원인 표시 → 경로 수정 또는 오버플로 배출 → 생산 재개
```

### 연구

```text
필요 기능 발견 → 연구 트리 검색 → 선행·설계도 조건 확인
→ 설계도 하차·운반·보관 → 큐 등록 → 연구 작업량
→ 시설·수술·조합 해금 → 새 생산·운영 문제 해결
```

### 직원 관리

```text
욕구·기분·건강 관찰 → 우선순위 설정 → AI 작업 선택
→ 이동·예약·실행 → 피로·경험·불만 변화 → 휴식/치료/통제
```

### 손님·상업

```text
외부 첫인상 → 입장·접수 → 시설 선택 → 소비·서비스
→ 만족·평판·매출 → 결산 → 시설·직원·재고 개선
```

### 생존 위기

```text
식량·물·위생·의료 부족 → 능률·기분 저하
→ 절박 행동/질병/폭력 → 오염·부상 확대 → 구조·치료·복구
```

### 수술

```text
부위 손상·장기 결손 → 수술 계획·위험 비교
→ 환자·의사·시설·재료 예약 → 운반·마취·집도
→ 장기/보철 변화 → 회복·거부 반응·재활 → 능력 복귀
```

### 축산·폐기물

```text
야생 포획 → 길들이기·합사·번식 → 먹이·물·청결 관리
→ 우유·알·털·고기·가죽 생산 → 조리·제작
→ 사체·부패물 → 사료·퇴비·연료·연금/소각
```

### 포로·흥행

```text
쓰러진 적 포획 → 안정화·압수·감방 호송 → 교화/노역/타락
→ 공연 편성·관객 입장 → 수익·명성·부상·평판
→ 영입/계약/석방 또는 탈출·배신·보복
```

### 방어

```text
위협·정찰 → 경비·동선·엄폐·장비 준비 → 침입
→ 자동 교전 + 우선 목표 명령 → 피해/약탈 → 보고서 → 복구
```

### 원정

```text
대원·장비·보급 실물 준비 → 육각 목적지·A* 이동
→ 두 선택지 사건 → 5인 명령열 전투 → 거점 해결·지역 약화
→ 안전 이동 칸 사용 → 실물 귀환·치료·수리 → 최종 진실
```

### 진화

```text
반복 사용 → 이력 축적·압축 → 성향 분석 → 후보 제시
→ 촉매·방향 선택 → 물리 작업 → 이득+부담의 새 세대
```

이 루프들은 독립 미니게임이 아니다. 원정을 위해 장비와 식량을 생산하면 직원 노동과 창고 재고가 줄고 운영 서비스와 방어 준비가 약해질 수 있다. 부상자를 살리려면 연구, 의료 방, 약품, 깨끗한 물, 전력, 장기 보관과 숙련 의사가 필요하다. 축산과 폐기물 정책은 음식·약품·연료·위생과 하수 처리량을 동시에 바꾸고, 공장 자동화는 반복 노동을 줄이는 대신 전력·유지보수·교착 대응을 요구한다. 자동 조달과 오버클럭은 위기를 빠르게 넘길 수 있지만 보호 자금과 장기 임금을 압박한다. 반대로 외부 압력을 낮추면 원정·침입 난도가 완화되고 더 좋은 보상으로 던전을 성장시킬 수 있다.

## 9. 코드에서 드러나는 기획 방향

### 9.1 정답 배치보다 살아 있는 문제 해결

시설 효과는 방 배치, 청결, 직원 상태, 재고, 동선과 사건에 따라 달라진다. 고정 최적 배치를 외우기보다 관찰한 문제에 맞춰 운영 구조를 바꾸는 게임을 지향한다.

### 9.2 직접 조종보다 자율 사회

캐릭터는 욕구와 작업을 스스로 선택한다. 플레이어는 우선순위, 접근 권한, 정책, 생산 주문과 비상 명령으로 사회를 간접 통제한다.

### 9.3 숫자가 아니라 물건이 이동하는 경제

재료, 음식, 장비와 촉매를 실제 아이템으로 유지한다. “재고 10 감소”보다 누가 어느 창고에서 무엇을 가져와 어디에 넣었는지가 생산 성공과 실패를 만든다.

### 9.4 방어만으로 끝나지 않는 양방향 전쟁

방어는 시간을 벌고 외부 원정은 적 지역을 약화하며 최종 승리를 연다. 플레이어는 위험을 선택해 런의 결말을 앞당길 수 있다.

### 9.5 시스템이 만든 역사를 콘텐츠로 전환

캐릭터 서사, 시설·장비 사용 이력, 사건 토큰, 도감과 LLM 표현 계층은 플레이 중 생긴 사건을 고유한 이야기로 남기려는 방향이다.

### 9.6 이득과 부담이 함께 있는 성장

진화는 순수 상위호환보다 장점과 부담을 함께 준다. 무한 성장에서도 선택이 자동화되지 않고 각 인스턴스에 성격과 운용 조건이 생긴다.

### 9.7 선택 폭을 늘리는 로그라이트 메타

주인 종족, 시작 시설, 합성 계보, 직원, 방어, 런 변수, 원정 보상을 조합한다. 메타 강화는 단순 공격력보다 후보 수, 설계 보존, 비용과 경고처럼 **다음 런의 선택 폭과 준비 능력**을 늘리는 비중이 높다.

## 10. 게임 경험과 UX 설계

이 장은 기능의 존재 여부가 아니라 **플레이어가 기능을 어떤 순서로 발견하고, 무엇을 보고 판단하며, 어떤 조작으로 개입하고, 결과를 어떻게 이해하는가**를 규정한다. 새 기능은 아래 공통 계약을 따라야 한다.

### 10.1 경험 원칙

1. **원인이 보이는 시뮬레이션**
   결과 수치만 보여 주지 않는다. 물 부족이면 빈 탱크, 끊긴 배관, 낮은 공급 우선순위 또는 오염된 수원까지 추적할 수 있어야 한다.
2. **직접 조종보다 운영 명령**
   평상시에는 정책, 우선순위, 허용 구역, 생산 주문과 목표 재고로 개입한다. 직접 이동·공격·구조는 비상 상황과 전투 태세에서 명확히 구분한다.
3. **숫자보다 월드의 물리 변화**
   구매품은 하차장에 도착하고, 재료는 운반되며, 부패·오염·사체·폐수·컨베이어 화물은 월드에 남는다. UI는 이 변화를 설명하되 대신하지 않는다.
4. **강한 결과에는 사전 신호와 복구 경로**
   결핍 붕괴, 역류, 정전, 침입, 수술 실패와 교착은 징후 → 경고 → 위기 순서로 악화된다. 즉시 게임오버보다 준비·완화·복구 선택을 먼저 제공한다.
5. **다크 판타지는 결과의 무게로 표현**
   잔혹한 선택은 단순 보상 버튼이 아니라 부상, 오염, 원한, 목격자 반응, 세력 보복과 영구 기록을 남긴다. 과도한 시각적 고어보다 운영 결과와 사회적 파장을 강조한다.
6. **깊이는 단계적으로 공개**
   처음에는 현재 문제와 다음 행동을 보여 주고, 상세 패널에서 계산 근거·정책·기록으로 내려간다. 모든 수치를 첫 화면에 동시에 노출하지 않는다.

### 10.2 플레이 흐름과 학습 순서

첫 플레이는 모든 탭을 한꺼번에 열지 않고 실제 문제 발생에 맞춰 기능을 소개한다.

| 단계 | 먼저 경험하는 문제 | 해금·강조되는 조작 |
|---|---|---|
| 시작 준비 | 주인과 시작 인원 구성 | 후보 비교, 드래그 교체, 스킬 확인 |
| 생존 기반 | 잠자리, 식량, 물, 화장실 부족 | 건설, 창고, 작업 우선순위, 방 정보 |
| 첫 영업 | 손님 대기와 재고 소모 | 접수, 상점, 서비스, 결산 |
| 생산 확장 | 반복 구매와 원료 부족 | 생산 주문, 목표 재고, 연구 트리 |
| 방어 준비 | 침입 징후와 장비 부족 | 경비 정책, 엄폐, 탄약, 전투 태세 |
| 외부 진출 | 던전 안에서 구할 수 없는 자원·정보 | 원정 편성, 육각 이동, 선택 사건 |
| 산업화 | 반복 운반과 물·전력 병목 | 배전, 배관, 컨베이어, 자동화 |
| 고급 운영 | 장기 부상, 포로, 진화와 대형 사업 | 수술, 포획, 촉매, 금고 정책 |

튜토리얼은 고정 팝업 연속 재생보다 현재 런의 실제 상태를 사용한다. 예를 들어 첫 단수 때 상수도 전체를 설명하지 않고, `물통 운반`과 `배관 연결` 두 해결 경로를 제시한 뒤 상세 도움말에서 장기 차이를 보여 준다. 이미 해결한 문제의 안내는 반복하지 않으며 개발자 모드와 기존 세이브에서는 건너뛸 수 있다.

### 10.3 정보 계층

정보는 세 단계로 나눈다.

| 계층 | 표시 내용 | 원칙 |
|---|---|---|
| 상시 HUD | 시간·배속, 중요한 사건, 핵심 자원 요약, 현재 선택 | 화면을 가리지 않고 상태 변화만 즉시 반영 |
| 맥락 정보 | 이름표, 진행률, 경고 표식, 선택 오버레이, 툴팁 | 선택·호버·위험 상황에서만 확장 |
| 상세 표면 | 캐릭터, 방, 시설, 아이템, 연구, 산업, 방어, 원정 패널 | 원인, 계산 근거, 정책, 명령과 기록 제공 |

상시 HUD는 모든 재고를 나열하지 않는다. 우측 상단 자원 목록에는 플레이어가 고정한 핵심 물리 재고와 골드를 표시하고, 골드는 목록 마지막에 둔다. 부족·위험 자원은 수치와 아이콘 상태가 함께 바뀐다. 상세 운영 화면에서 전체 재고, 예약, 운반 중, 시설 버퍼와 예상 소비를 분리한다.

### 10.4 공통 조작 문법

- **좌클릭**: 정확히 포인터가 닿은 대상 또는 Grid 셀을 선택한다. 근처 대상을 추정하지 않는다.
- **우클릭**: 선택 대상에 대한 상황 명령을 열거나 이벤트 알림을 숨긴다. 빈 공간에서는 현재 타기팅을 취소한다.
- **Esc**: 타기팅 → 하위 상세 → 전체 화면 순서로 한 단계씩 뒤로 간다.
- **Shift**: 전투 다중 선택, 디버그 반복 실행, 대기열·목록의 연속 선택처럼 문맥에 맞는 반복·다중 조작에 사용한다.
- **드래그**: 시작 명단 교체, 연구·생산 큐 정렬, 월드맵 이동과 선택 영역처럼 순서·위치를 직접 바꾸는 곳에만 사용한다.
- **Alt**: 겹친 대상 중 아이템 더미를 정확한 칸에서 우선 선택한다.
- UI 위 포인터 입력은 월드 선택, 카메라 이동과 타기팅으로 전달하지 않는다.
- 직접 이동·공격·강제 사격처럼 평상시 AI 규칙을 우회하는 명령은 별도 모드와 위험색 상태를 표시한다.
- 파괴적 명령과 비가역 선택은 대상명, 비용과 예상 결과를 버튼 근처에 표시한다.

월드 선택 우선순위는 `Character > Wildlife > Item > Construction > Building`이다. 같은 칸의 대상이 가려졌을 때는 반복 클릭에 의존하지 않고 선택 목록 또는 보조 선택 키를 제공한다. 이미 열려 있는 동물을 연속으로 다시 클릭해도 상세 패널이 갱신되어야 한다.

### 10.5 시간, 정지와 비동기 처리

- 기본 시간 조작은 `정지 / X1 / X5`다.
- 카메라, UI 전환, 툴팁과 메뉴 애니메이션은 `IUiClock`을 사용해 배속에 영향받지 않는다.
- 이동, 작업, 조준, 투사체, 출혈, 수술, 치료, 오버클럭 지속 시간, 컨베이어와 유체 시뮬레이션은 `IGameClock`을 사용하며 정지 중 진행되지 않는다.
- 전체 화면 연구 창의 자동 일시정지는 선택 옵션이며 기본값은 꺼져 있다. 닫을 때 열기 전 배속과 정지 상태를 정확히 복원한다.
- 오펜스에서 해결되지 않은 선택 사건과 전투는 해당 원정대만 멈추고 던전 시간은 계속 흐른다. 던전 위기 발생 시 원정 화면에서도 축약 경고를 볼 수 있다.
- LLM 응답은 실시간 판단이나 진행 조건을 막지 않는다. 검증된 결과가 도착하기 전에는 실패 문구·임시 문구·로딩 서사를 노출하지 않고 해당 역사 노드를 숨긴다.

### 10.6 월드 가독성과 오버레이

- 캐릭터 이름은 평상시에도 읽을 수 있는 크기를 유지한다.
- 체력바는 피해, 출혈, 교전, 쓰러짐 위험이 있을 때만 나타난다.
- 이름표는 캐릭터·시설·천장에 가려지지 않는 월드 UI 레이어에 두고, 인접 교전에서는 겹치지 않도록 오프셋한다.
- 시설, 야생동물과 월드 아이템의 피벗은 실제 점유 셀과 맞아야 하며 스프라이트 방향 전환이 Grid 위치를 바꾸지 않는다.
- 카메라 줌은 커서 중심으로 동작하고 하늘·배경은 현재 화면비와 orthographic size보다 넓게 다시 맞춰 빈 띠를 만들지 않는다.
- 오버레이는 한 번에 하나의 질문에 답한다. 방, 온도, 위생, 전력, 상수, 하수, 컨베이어, 사선, AI 경로와 야생 서식지를 독립 토글한다.
- 색만으로 상태를 구분하지 않는다. 선 모양, 패턴, 아이콘, 라벨을 함께 사용한다.
- 오버레이는 월드 오브젝트보다 앞, HUD보다 뒤에 표시하며 레이캐스트를 받지 않는다.

### 10.7 경고, 사건과 원인 추적

모든 운영 문제는 다음 수명주기를 따른다.

```text
징후 발견 → 원인 요약 → 영향받는 대상 → 가능한 대응
→ 플레이어 또는 AI 대응 → 상태 변화 → 해결/악화 기록
```

| 심각도 | 예시 | 표시 방식 |
|---|---|---|
| 정보 | 배송 도착, 연구 완료 | 짧은 알림과 관련 위치 링크 |
| 주의 | 목표 재고 미달, 경미한 정체 | 자원·시설 배지와 운영 목록 |
| 경고 | 단수, 병상 부족, 침입 집결 | 상단 사건, 월드 표식, 대응 버튼 |
| 위기 | 역류, 붕괴 직전, 내부 침입 | 강한 시청각 신호와 자동 포커스 후보 |

알림은 동일 원인을 매 틱 새로 만들지 않고 하나의 사건으로 갱신한다. 좌클릭은 원인 대상이나 관련 패널로 이동하고 우클릭은 현재 알림만 숨긴다. 숨겨도 사건 기록과 실제 문제는 남으며 심각도가 상승하거나 재발하면 새 알림으로 돌아온다.

차단 사유는 행동 가능한 문장으로 쓴다. `실행 실패` 대신 `깨끗한 물 0.20 부족`, `필수 설계도가 연구실 밖에 있음`, `문 권한 때문에 경로 없음`, `보호 자금 아래라 자동 구매 보류`처럼 원인과 해결 위치를 함께 표시한다.

### 10.8 운영 화면과 탐색 구조

하단의 주 탭은 건설, 건물, 직원, 상점, 창고, 운영, 방어, 원정, 연구, 포획·흥행과 산업 같은 큰 업무 맥락을 바꾼다. 각 표면은 같은 구조를 따른다.

1. 상단 또는 좌측에 상태 요약과 검색·필터
2. 중앙에 비교 가능한 목록·그래프·월드 정보
3. 우측 또는 하단에 선택 대상 상세
4. 상세 하단에 현재 가능한 명령
5. 명령 직후 결과, 비용과 다음 차단 사유

카드는 반복 개체와 명확히 프레임이 필요한 도구에만 사용한다. 페이지 섹션을 카드 안에 다시 넣지 않는다. 목록은 현재 상태, 위험도, 위치와 다음 행동을 한 행에서 비교할 수 있어야 하며 행 선택은 월드 포커스와 상세 패널을 동기화한다.

### 10.9 건설, 작업과 물리 아이템 UX

건설 모드에서는 설치 가능 셀, 최종 footprint, 문 방향, 작업 위치와 예상 동선 차단을 미리 보여 준다. 배치 후에는 완제품 대신 청사진을 표시하고 다음 정보를 제공한다.

- 필요 재료 / 예약 / 납품 수량
- 필요 작업량 / 완료 작업량 / 진행률
- 예약 직원과 현재 작업 단계
- 접근 불가, 문 선행, 퇴로 차단과 강제 공사 경고
- 취소 시 회수될 재료와 해제될 예약

캐릭터 이름표의 상태 문구는 `벽 건설 42%`, `하차장 물품 운반`, `배관 수리`, `수술 봉합 중`처럼 목표와 단계를 짧게 표시한다.

아이템 더미는 칸마다 대표 마커 하나, 총수량 배지와 종류 배지를 표시한다. 더미 목록은 종류·상태·가치 순으로 정렬하고 상세에서는 수량, 무게, 가치, 신선도, 오염, 예약자, 목적지와 처리 정책을 보여 준다. 선택한 스택이 병합·운반·삭제되면 닫히거나 잘못된 대상을 가리키지 않고 같은 칸의 목록으로 돌아간다.

컨베이어 운반물도 같은 아이템 상세를 사용한다. 네트워크 상세에서는 현재 구간, 목적지, 정지 시간, 정체 원인, 다음 오버플로 출구와 배출 예상 위치를 추가한다.

### 10.10 캐릭터, AI와 건강 UX

캐릭터 상세는 `상태 / 성장 / 기분 / 기록 / AI / 전투 / 건강`을 기본 축으로 사용한다.

- 상태: 현재 활동, 욕구, 일정, 위치와 소지 무게
- 성장: 스탯, 특성, 스킬, 경험과 역할
- 기분: 현재 요인, 지속 시간, 사회적 기억과 붕괴 위험
- 기록: 최근 사건과 구조화된 서사 장부
- AI: BT 분기, 현재 의도, 단계, 목표, 상위 후보, 탈락 사유와 다음 판단
- 전투: 장비, 탄약, 사거리, 엄폐, 명중·회피 계산과 수리 정책
- 건강: 신체도, 부위·장기 효율, 상처·출혈·감염, 구조·치료·수술 주문

플레이어용 AI 설명은 `배가 고파 식당으로 이동`, `하차장 물품을 먼저 옮김`, `방이 더러워 휴식을 피함`처럼 한 문장으로 제공한다. 개발용 점수와 BT 추적은 AI 탭 안쪽에 두고 평상시 HUD를 채우지 않는다.

욕구 0은 단순 숫자 경고가 아니라 건강 부담과 행동 변화로 이어진다. 부담 40, 70, 확정 붕괴 직전의 단계를 서로 다른 아이콘과 문구로 구분한다. 극단 행동은 목표와 이유를 머리 위 표식과 건강 탭에 보여 주고, 제압·자원 공급·치료 같은 실제 중단 방법을 제공한다.

수술 예약 화면은 수술명, 부위, 사용할 장기·보철, 의사, 집도 시설, 마취·약품과 전후 능력치를 한 흐름에서 비교한다. 성공률만 크게 보여 주지 않고 감염, 출혈, 장기 손상과 사망 확률의 계산 근거를 함께 표시한다.

### 10.11 침입, 방어와 전투 UX

침입 경험은 `징후 → 외부 집결 → 장비 수령·배치 → 내부 진입 → 저지·사격 → 붕괴·복구`로 읽혀야 한다.

- 집결 중에는 남은 준비 시간, 예상 경로, 적 구성과 부족 장비를 표시한다.
- 경비는 내부 침입 뒤 출동하며 이름표에 `저지하러 이동`, `교전 중`, `교대 대기`, `후퇴 중`을 표시한다.
- 근접 저지 칸, 예비 경비 칸, 원거리 사격 위치, 사선과 엄폐 방향을 선택 대상에 한해 오버레이한다.
- 저지된 침입자가 실제 Grid에서 멈췄는지 이동 표식으로 확인할 수 있어야 한다.
- 일반 공격은 정확한 적대 대상만 받으며 강제 사격은 중립·아군 오발 위험을 명시한다.
- 피해 결과는 피해 유형, 부위, 방어·관통, 출혈과 제압을 짧은 VFX·숫자·아이콘으로 전달한다.
- 쓰러짐 뒤에는 현장 안정화, 구조자, 병상, 치료와 복귀가 하나의 추적 가능한 의료 흐름으로 이어진다.

전투 태세 명령 바는 하단 주 메뉴 위에 나타나며 태세 해제 시 생활 AI와 예약이 안전하게 복원된다. 선택한 명령이 탄약·사선·문 권한·경로 때문에 중단되면 캐릭터가 서 있는 채로 방치되지 않고 재장전, 무기 교체, 재배치, 후퇴 또는 명시적 중단으로 이어진다.

### 10.12 오펜스 UX

육각 월드맵은 지형, 도로, 안개, 거점, 현재 원정대와 도달 예상 시간을 한 화면에서 비교한다. 이동을 확정하기 전 예상 보급 소비, 위험 단계와 도착 시간을 보여 주되 숨은 사건의 결과 수치는 공개하지 않는다.

Reigns식 사건 카드는 항상 좌우 두 선택지를 사용한다. 각 선택은 `보급 감소`, `경계 크게 상승`, `부상 위험`처럼 방향과 강도를 표시하고 정보·인물·도구 조건으로 변형된 결과를 구분한다. 저장 재굴림을 막기 위해 사건 시드와 확정 결과는 저장한다.

5인 명령열 전투는 한 번에 하나의 합에 집중시킨다.

- 평상시 적 의도는 대상 초상과 행동 아이콘으로 축약한다.
- 아군 카드를 선택하면 관련 없는 캐릭터·카드·의도를 25~35% 밝기로 낮춘다.
- 선택 중에는 아군→적 의도, 적 의도→기존 대상, 연결 가능한 다음 아군의 세 선만 표시한다.
- 확정한 명령은 `1~5` 순번과 하단 명령열로 접고 호버할 때만 선을 다시 펼친다.
- 실행 중에는 현재 격돌 카드와 관련 캐릭터만 밝힌다.
- 사슬 중단은 `Full`, `Degraded`, `Residual`, `Broken`을 선 모양과 아이콘으로 구분한다.
- 카드 격돌 인장 파괴 수는 실제 남은 실행 단계와 일치해야 한다.

목표 달성 뒤에는 `안전 이동 N칸 남음`만 표시한다. 특정 경로를 강제하거나 강조하지 않으며 실제로 이동한 육각 칸마다 하나를 소비한다. 다른 거점 공격을 시작하면 보호 해제를 명확히 확인시키고, 예산이 끝난 뒤에도 귀환을 강요하지 않는다.

### 10.13 연구, 생산, 금고와 산업 UX

연구는 118개 노드를 자동 배치한 전체 화면 트리로 제공한다. 완료, 진행, 대기, 연구 가능, 조건 부족, 설계도 운반 중과 우회 가능 상태를 색뿐 아니라 아이콘·라벨·연결선으로 구분한다. 먼 노드를 큐에 넣을 때 자동 추가될 선행 연구와 등록되지 못한 필수 설계도를 먼저 보여 준다.

생산 주문은 반복 횟수와 목표 재고 모드를 명확히 구분한다. 재료 필터를 바꾸면 현재 예약·보존 재고와 예상 결과가 즉시 갱신된다. 장비 제작은 형태, 주재료, 품질 예상, 무게, 피해·방어와 수리 재료를 제작 전에 비교한다.

금고 화면은 잔액보다 **현금 흐름과 예약된 선택**을 중심으로 한다.

- 오늘 수입·지출과 실패 거래
- 다음 임금·용병·계약비
- 자동 조달 일일 예산과 보호 자금
- 대기 배송과 건너뛴 상품의 정확한 사유
- 3일 예상 잔액
- 침공당 금고 방어 예산과 실제 사용액

산업 화면은 전력, 상수, 하수, 컨베이어와 자동화 섹션을 한 표면에서 전환한다. 네트워크 전체 상태 → 문제 노드 → 실제 월드 위치 순서로 내려가며, 정전과 의도적 정지를 교착으로 오인하지 않는다. 오버플로 명령 전에는 배출 대상, 창고 또는 바닥 위치와 메타데이터 보존 여부를 보여 준다.

### 10.14 포로, 서커스와 가혹한 선택 UX

포획·심문·노역·타락·생체 적출·공개 처벌처럼 큰 결과를 만드는 행위는 일반 작업 우선순위만으로 우발 실행되지 않는다. 플레이어가 정책 또는 개별 주문으로 허용해야 하며 대상, 필요 시설·재료, 작업량, 예상 부상, 원한·탈출·세력 위험을 확인한다.

감방과 우리는 문 권한과 실제 폐쇄 경계를 함께 검사한다. 수용 대상이 사용할 수 있는 문이 있으면 `안전한 감방`으로 표시하지 않고 해당 문을 직접 강조한다.

서커스 공연은 편성, 호송, 관객 입장, 공연, 정산, 청소·치료 단계를 진행률로 보여 준다. 치명성 정책, 공연자 부상, 관객 성향, 예상 수입과 중단 조건을 공연 시작 전에 비교한다. 침공·화재·반란으로 취소되면 관객 대피, 포로 재구속과 치료 주문이 어디까지 수행됐는지 남긴다.

### 10.15 반응형 레이아웃과 가독성

- 1600×900을 기본 작업 화면으로 설계한다.
- 900×1600에서는 좌우 분할을 억지로 축소하지 않고 목록 → 상세 순서의 세로 흐름과 스크롤 가능한 하단 시트로 전환한다.
- 고정 형식 보드, 카드, 버튼, 체력바와 타일은 안정된 크기·aspect ratio를 사용해 내용 변화로 흔들리지 않게 한다.
- 폰트 크기를 viewport 폭에 비례해 축소하지 않는다. 긴 한국어는 줄바꿈, 최소 너비와 스크롤로 처리한다.
- 본문, 보조 설명, 비활성 텍스트와 위험색은 배경 대비를 확보한다.
- 상태는 색만이 아니라 아이콘, 문양, 선 형태와 텍스트를 함께 사용한다.
- 아이콘 버튼은 익숙한 기호를 사용하고 낯선 아이콘에는 한국어 툴팁을 제공한다.
- 숫자는 단위를 붙이고 같은 화면에서 소수 자릿수 규칙을 통일한다.
- 깨진 한글과 내부 enum·기술 로그는 플레이어 표면에 노출하지 않는다.

### 10.16 빈 상태, 차단, 변경과 복구

모든 상세 표면은 다음 상태를 명시적으로 처리한다.

- **빈 상태**: 데이터가 없다는 사실과 데이터를 만드는 첫 행동을 표시한다.
- **준비 중**: 생성·운반·연구·LLM 요청처럼 아직 결과가 없는 상태를 기술 문구 없이 표현한다.
- **차단**: 필요한 자원, 권한, 경로, 연구, 방 조건 또는 전력을 정확히 표시한다.
- **대상 변경**: 선택 대상이 병합·이동·파괴되면 가장 가까운 유효 상위 목록으로 돌아간다.
- **예약 상실**: 누가 무엇을 잃었는지 기록하고 AI가 재계획한다.
- **복원 불일치**: 사라진 대상과 중복 예약을 조용히 합치지 않고 해제·재계산하며 진단 기록을 남긴다.

진행률은 큐 제거, 재료 분실, 정전과 작업자 교체 때문에 초기화되지 않는다. 연구, 건설, 제작, 수술과 자동화는 가능한 지점부터 재개한다. 취소가 진행률이나 재료를 잃게 만들면 실행 전에 정확한 손실을 표시한다.

### 10.17 UX 완료 기준

기능은 코드가 동작하는 것만으로 완료하지 않는다. 다음을 모두 만족해야 한다.

1. 플레이어가 현재 상태와 가장 큰 문제를 5초 안에 찾을 수 있다.
2. 경고에서 원인 대상과 실제 대응 명령까지 두 번 이하의 전환으로 도달한다.
3. 선택은 정확한 대상에만 적용되고 UI 클릭이 월드에 새지 않는다.
4. 진행 중인 작업은 목표, 단계, 진행률과 차단 사유를 제공한다.
5. 위험한 선택은 비용, 대상, 예상 위험과 복구 가능성을 사전에 표시한다.
6. 정지 상태에서 게임 시간 기반 이동·연출·소비·피해가 진행되지 않는다.
7. 1600×900과 900×1600에서 텍스트·버튼·월드 정보가 겹치지 않는다.
8. 색각에 의존하지 않고 아이콘·문양·라벨로 상태를 구분한다.
9. 로드, 대상 파괴, 예약 상실과 네트워크 변경 뒤에도 잘못된 상세나 유령 명령이 남지 않는다.
10. PlayMode 실제 포인터 검증, 화면 캡처와 Console Error 0 / Warning 0을 통과한다.

과거 장기 목록에 있던 전체 원정 월드맵과 깊은 생산 체계는 각각 V17 육각 월드와 자원 순환 경제로 대체 구현됐다. 현재 우선순위는 새 대분류를 더 늘리는 것보다 인스턴스 진화 통합, V17·수술 밸런스, 기존 시스템 간 연결과 첫 플레이 이해도를 검증하는 데 가깝다.

## 12. 기술 구조

### 12.1 주요 기술과 규모

- Unity `6000.3.8f1`
- URP 2D `17.3`
- Input System `1.18`
- VContainer `1.19`
- Behavior Designer 포함
- `Assets/Scripts` 프로젝트 C# 912개
- Behavior Designer 외부·에디터 코드 약 533개는 별도

주요 도메인은 AI, Buildings, Characters, Combat, Debugging, Economy, Evolution, Invasion, Items, Medical, Offense, Research, Rooms, Survival, Wildlife, Work, World, Foundation, Infrastructure, Presentation이다. Infrastructure 안에는 전력, 유체, 컨베이어와 자동화가 분리된 런타임·저장 섹션으로 들어간다. Character, Infrastructure, UI, Buildings의 비중이 커서 프로젝트 중심이 단일 전투보다 캐릭터 사회와 운영에 있음을 보여 준다.

### 12.2 Gameplay 조립

`DungeonRuntimeLifetimeScope`가 Gameplay composition root다.

```text
Foundation / Work
→ Combat / Invasion
→ World Simulation
→ Save
→ Core Infrastructure
→ Facility
→ Character
→ AI / Rooms
→ Progression / Research / Offense V17 / Medical / Industrial
→ Debugging
→ Presentation
```

`OwnerCommandController`, `RegularCustomerRuntime`처럼 하나만 있어야 하는 서비스는 `SingleRequired`로 중복·누락을 조용히 넘기지 않는다. 결산, 알림, 런 변수, 건설, 주인 선택, V17 원정, 침입, 시설 진화·합성·도감, 로컬 LLM, 평판·불만·손님·AI, 상점·연구·메타, 생산·금고 경제, 수술, 야생동물·외부 구역, 전력·상하수도·컨베이어·자동화와 개발자 도구가 이 루트에 연결된다.

### 12.3 현재 Gameplay 씬

```text
__Scene
  ├─ Cameras / Main Camera
  ├─ Input / EventSystem / OwnerCommandController
  ├─ Grid
  ├─ UI
  └─ World / Background

__Systems
  ├─ Managers / GameManger / OwnerRunManager
  ├─ Spawners / CharacterSpawner
  └─ Runtime Services / DungeonRuntimeSystems

__Runtime
  ├─ Buildings
  ├─ Characters
  ├─ Construction
  ├─ Exterior
  ├─ Items
  ├─ Survival
  ├─ Wildlife
  ├─ Combat
  ├─ Infrastructure
  ├─ World UI
  └─ Debug

__Debug Fixtures
```

씬에는 Slime·Orc 일반 캐릭터, 낮은 기분 손님, 보상 방문객, 스냅샷 손님 같은 테스트 픽스처도 있다.

### 12.4 실패 처리와 성능 방향

필수 서비스가 없을 때 조용히 대체하기보다 명확한 실패를 선호한다. AI 작업 실패, 경로 지연, 재료 부족, 막힌 주문과 중복 서비스가 각각 드러난다.

- `GridPathSearchBroker`의 공유 탐색, 경로 예산과 Grid 버전 무효화
- 화면 안·선택·위험 대상을 우선하는 due-time AI 스케줄링과 tick dilation
- 프레임 여유에 따라 AI·표시 작업량을 나누는 동적 작업 예산
- 캐릭터·시설·작업·아이템·야생동물 registry와 주변 조회용 공간 버킷
- 그리드 구조·이동 버전 분리, 방·시설 후보·작업 후보 캐시
- 보이는 이름표만 자주 갱신하는 presentation scheduler
- 오래된 사용 이력과 AI 추적 기록의 상한·계층 압축
- 연결 변경 때만 계산하는 전력·유체 연결 요소 캐시와 컨베이어 SCC 교착 검사

현재 Editor 성능 기록에는 단순 빈 Grid가 아니라 실제 새 런, 캐릭터 프리팹, 렌더링, UI, 물리와 대량 시설을 포함한 측정이 있다.

| 측정 | 조건 | 결과와 해석 |
|---|---|---|
| 대형 월드 100명 | `1024×1024`, 32개 활성 층, 밀집 시설 8,192개 | 유효 측정, 60 FPS p95·p99 기준 통과 |
| 대형 월드 500명 | `1024×1024`, 32개 활성 층, 밀집 시설 8,192개 | p95 기준은 통과했지만 p99 실패, 1% low 약 14 FPS로 큰 스파이크가 남음 |
| 5배속 생활 시뮬레이션 | `1024×1024`, 100명, 밀집 시설 900개, 3840×2160, 30초 | p95·p99 기준과 Error/Warning 0건 통과, 1% low 약 68.8 FPS |
| 산업 실제 시나리오 | `GameplayScene`, 시설 35개, 전력·수세·컨베이어·자동화·교착·오버플로 | 기능과 실제 월드 연동 검증, FPS 보장 측정은 아님 |
| 산업 합성 스트레스 | Utility 10,000셀, 컨베이어 경로 2,000개 | 토폴로지 약 244.7ms, 경로 약 457.6ms의 일괄 계산 규모 확인, 프레임률 측정 아님 |

따라서 현재 결과는 **100명·5배속과 대형 월드의 실용 가능성을 뒷받침하는 Editor 측정**이지 모든 하드웨어·모든 장기 런에서 60 FPS를 보장한다는 뜻은 아니다. 500명 스트레스에서는 프레임 꼬리 지연이 크고, 5배속 측정에도 작업 backlog·판단 지연과 누적 할당이 기록되어 있다. 출시 전에는 대표 하드웨어 빌드 프로파일, 장시간 soak, 실제 생산·전투·운반이 동시에 몰리는 최악 상황을 다시 통과해야 한다.

## 13. 검증 현황

기존 구현 근거와 QA는 다음을 실제 씬·UI·저장 상태로 검증한 기록이 있다.

- AI 계획과 초기 시설
- 손님 AI와 캐릭터 종족·주인
- 작업 우선순위와 출입 권한
- 재고·공급·정산·피드백
- 침입·방어·전투 보고서
- 상점·연구 트리·물리 설계도·합성
- 시설 진화·감정
- 직원 불만·모집·반란
- 런 종료와 메타 진행
- V17 육각 지도·선택 사건·명령열 전투·안전 이동·귀환
- 수술 예약·약품 운반·작업량·회복
- 개발자 모드·정확한 타기팅·오버레이·저장 표식
- 이벤트 우클릭 숨김, 조건부 체력바, 배속 독립 카메라와 줌 대응 배경
- 금고 거래, 임금·용병, 자동 조달, 정밀 재단조, 오버클럭과 유료 방어
- 전력 우선순위, 상수·하수 소비, 역류, 컨베이어 이동·교착·오버플로와 자동 생산
- `1024×1024` 대형 Grid, 밀집 시설, 100·500명과 100명 `X5` Editor 성능 프로필

오래된 통합 기록은 29개 스위트 전체 PASS 근거가 있다. 최신 개별 기록에는 수술 PlayMode, 연구 트리, 개발자 모드, V17 화면·시나리오와 산업 인프라 실제 GameplayScene 검증이 추가됐다. 산업 검증은 35개 시설, 실제 물리 아이템 운송, 수세 시설 폐수, 자동화와 순환 교착·오버플로를 포함했으며 Error/Warning 0건으로 끝났다. Utility 10,000셀과 경로 2,000개 검증은 알고리즘 규모를 확인한 합성 스트레스이며 실제 프레임률 근거로 사용하지 않는다. 일부 구 검증기가 아직 전역 저장 V16을 기대하고 현재 시설·장비 진화 관련 변경도 많으므로 다음을 구분해야 한다.

- 과거 자동화 검증: 강한 근거 있음
- 최신 수술·개발자 모드·V17 시각 검증: 각 기록상 Error/Warning 0건
- 최신 산업 인프라 GameplayScene PlayMode 검증: 실제 시설·물리 화물·UI 포함 Error/Warning 0건
- 산업 10,000셀·2,000경로 스트레스: 토폴로지·경로 계산 근거, FPS 보장 근거 아님
- 현재 권위 저장 계약: V17
- 구 V16 고정 검증기: 최신 계약으로 갱신 필요
- 현재 변경분 포함 전체 EditMode/PlayMode 회귀: 최종 실행 필요
- 깨끗한 신규 프로필 첫 런의 사람 중심 검증: 최종 제품 게이트

## 14. 현재 완성도 판단

### 기술적으로 강한 부분

- 핵심 시스템이 같은 composition root와 저장 구조에 실제 연결됨
- 물리 아이템, 운반, 건설, 생산과 소비가 같은 소유권 흐름을 공유
- AI, 방, 생존, 전투, 원정과 결산의 상호작용이 깊음
- 공통 전투 해석기를 방어·원정·사냥이 재사용
- 자동 QA와 디버그 명령 범위가 넓음
- 결정론적 규칙과 LLM 표현을 분리
- 장기 런을 위한 캐시, 스케줄링, 이력 압축 고려
- 육각 월드·수술·생산 경제도 기존 물리 아이템·작업량·저장 흐름을 재사용
- 금고 경제와 산업 인프라도 기존 거래 장부·물리 아이템·건물 능력·작업·저장 흐름을 재사용

### 제품 관점의 주요 과제

1. **첫 플레이 이해도**: 왜 실패했고 다음에 무엇을 해야 하는지 단계적으로 가르쳐야 한다.
2. **콘텐츠 밀도와 반복성**: 많은 데이터가 실제로 서로 다른 결정을 만드는지 검증해야 한다.
3. **운영·방어·원정 보상 리듬**: 어느 한 축도 다른 축의 준비 노동으로만 느껴지지 않아야 한다.
4. **인스턴스 진화 통합**: 기존 진화, 새 무한 진화, 저장 마이그레이션, UI, 촉매와 LLM 서사를 한 사이클로 검증해야 한다.
5. **V17 전술 가독성과 반복성**: 5인 명령열, 맞대응과 사건 카드가 실제 장기 플레이에서도 읽히고 반복되지 않는지 확인해야 한다.
6. **수술·이식 밸런스**: 전문 시설·재료·숙련의 투자 가치와 치명 실패 위험을 장기 경제에서 조정해야 한다.
7. **현재 변경분 회귀 안정성**: 구 V16 고정 검증기를 고치고 전체 테스트를 다시 돌려야 한다.
8. **출시 씬 정리**: 디버그용 `SampleScene`과 테스트 픽스처를 배포 구성에서 분리해야 한다.
9. **꼬리 지연과 할당**: 100명 `X5` 목표는 근거가 있지만 500명 스트레스의 p99 스파이크, backlog와 장시간 메모리 할당은 계속 줄여야 한다.
10. **산업망 장기 밸런스**: 자동화가 수동 운반을 완전히 무의미하게 만들지 않고 전력·수질·유지보수·교착 부담과 교환되는지 확인해야 한다.
11. **금고 의사결정 밀도**: 임금·조달·오버클럭·유료 방어가 강제 세금이나 무조건 정답이 되지 않고 위기 대응 선택으로 남는지 검증해야 한다.

### 종합 판정

DungeonStory는 핵심 루프를 찾는 초기 프로토타입이 아니다. 이미 다음 구조가 성립한다.

```text
던전을 건설한다
→ 몬스터 사회와 물류를 운영한다
→ 손님에게 서비스를 제공해 경제를 만든다
→ 생존·불만·사건과 침입을 감당한다
→ 외부 원정으로 적을 약화하고 진실에 접근한다
→ 런 결과를 다음 시작 선택지로 바꾼다
```

현재 핵심 과제는 새로운 대분류 시스템을 계속 늘리기보다 이미 넓게 구현된 시스템을 플레이어가 읽을 수 있는 경험으로 묶고, 인스턴스 진화를 완전히 통합하며, V17 원정·전투와 수술·생산 경제의 장기 밸런스, 첫 런의 이해도·속도·보상을 다듬는 것이다.

현재 DungeonStory의 정체성은 다음과 같다.

> **자율적으로 살아가는 몬스터 사회를 물리 물류와 시설로 운영하고, 반복되는 인간 침입을 막으면서 외부 원정을 통해 세계의 진실을 밝히는 로그라이트 던전 경영 시뮬레이션**

핵심 루프와 대부분의 하위 시스템은 코드·데이터·씬·저장·QA 수준에서 연결되어 있다. 최근에는 118개 연구 트리, 전문 수술실, 금고 중심 경제, 전력·상하수도·컨베이어·자동화, 5인 명령열 오펜스 V17과 개발자 팔레트까지 제품 흐름에 들어왔다. 현재 가장 큰 미완료 축은 시설과 장비가 사용 역사를 기억하고 고유한 이득·부담·서사를 얻는 인스턴스 진화의 최종 통합이다. 장기적으로는 함정, 더 복합적인 방·시설 계보, 침입·원정 콘텐츠 다양화와 다중 던전 운영까지 확장하려는 방향이 보인다.

다음 완성도 단계는 세 가지에 달려 있다.

1. 현재 진화 작업의 통합, 구 V16 검증기 갱신과 전체 V17 회귀 검증
2. 깨끗한 신규 프로필로 시작 준비부터 `truth_core`·귀환까지 이어지는 사람 중심 플레이테스트
3. 수술·생산·금고·산업·방어·원정 선택이 읽히도록 튜토리얼, 알림, 결산과 콘텐츠 리듬 정리
