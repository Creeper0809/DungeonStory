# 09. 저장, 복원과 이어지는 세계

## 저장이 지켜야 하는 것

저장은 플레이어가 만든 세계를 같은 상태로 이어 주는 약속이다. 주민의 이름과 가족, 시설의 사용 이력, 장비의 계보, 물건의 위치와 예약, 세력의 의무와 진행 중인 원정은 불러오기 전후에 같은 의미를 가져야 한다. 결과만 비슷하게 다시 만드는 것으로는 충분하지 않다.

이 원칙이 필요한 이유는 DungeonStory의 선택 비용이 진행 중인 상태에 많이 남기 때문이다. 건설 현장에 묶인 재료, 환자를 옮기는 주민, 제작 중인 장비, 귀환 중인 원정대와 아직 지급되지 않은 계약 보상도 세계의 일부다. 저장으로 이런 부담이 사라지거나 두 배가 되면 물리 경제와 장기 계획을 신뢰할 수 없다.

## 진행 중인 일도 세계 상태다

완료된 결과만 저장하면 중간 과정이 복원될 때 새로 시작되거나 사라진다. 따라서 다음 상태는 완료 여부와 별개로 보존해야 한다.

- 물건과 목적지에 걸린 예약
- 운반자가 집어 든 물건과 남은 배송량
- 건설 현장과 생산 주문에 투입된 재료와 작업량
- 완성되었지만 아직 목적지에 인계되지 않은 출력
- 수술 단계, 사용한 약품과 남은 의료 작업
- 원정대의 보급품, 조우, 결정, 전리품과 귀환 단계
- 사건과 계약의 선택, 기한, 진행 작업과 아직 전달되지 않은 결과

취소와 파괴도 같은 원칙을 따른다. 이미 도착한 재료, 이동 중인 물건, 회수 가능한 부품과 손실된 작업을 구분하지 않고 전부 돌려주거나 지우면 취소가 복제 수단 또는 손실 회피 수단이 된다. 저장은 이 결산을 건너뛰는 우회로가 되어서는 안 된다.

## 현재 누가 책임지고 있는가

하나의 물건이나 결과를 여러 시스템이 동시에 소유하면 복원할 때 복제와 누락이 생긴다. 그래서 이동과 처리 과정마다 현재 책임을 한곳에 둔다.

창고의 약품을 수술에 쓰는 경우를 예로 들면, 처음에는 물리 재고가 약품을 관리한다. 의료 작업이 물건을 예약하고 운반자가 집어 들면 인계 상태가 바뀐다. 수술이 실제로 소비한 양은 의료 진행 기록에 남고, 사용하지 않은 물건은 다시 물리 재고로 돌아간다. 화면은 이 상태를 보여 줄 뿐 별도 약품 수량을 저장하지 않는다.

책임의 이동이 기록되어 있으면 불러오기 뒤에도 어디에서 다시 시작해야 하는지 알 수 있다. 책임이 불명확하거나 둘 이상이 같은 대상을 주장하면 복원을 계속하기보다 손상으로 판정해야 한다.

## 질량은 정의와 구성요소에서 다시 계산한다

물건의 저장 기록은 종류, 수량, 위치, 개별 구성요소와 현재 책임을 보존한다. 종류 정의에서 오는 기본 질량은 물건마다 별도 값으로 복사해 두지 않는다. 불러올 때 현재 아이템 정의와 장착 부품, 재료처럼 실제 무게를 바꾸는 구성요소에서 같은 gram을 다시 계산한다.

진행 중인 운반과 입고 예약은 약속 당시의 exact gram과 관련 판본을 검증 증거로 남길 수 있다. 질량 권위는 현재 정의와 구성요소에 있고, 이 동결값은 같은 운반을 재개할 때 수량이나 구성이 달라지지 않았는지 대조하는 데만 사용한다.

불러온 직후 새 운반 한도나 창고 용량을 넘는다고 해서 물건을 삭제하거나 가까운 빈칸으로 옮기지 않는다. 원래 위치와 책임을 유지한 채 새 픽업과 입고를 막고, 하역이나 재배치 작업으로 해결한다. 저장을 이용해 과적, 창고 포화와 운반 비용을 없앨 수 없어야 하기 때문이다.

이 계약은 현재 형식으로 저장한 세계의 연속성을 다룬다. 과거 버전에서 작성된 kg를 새 기준으로 바꾸는 마이그레이션은 별도 작업이며, 완료 여부는 [시스템 구현 권위 체크리스트](../system-implementation-checklist.md)가 관리한다.

## 중간에 끊겨도 같은 결과로 이어지는 방식

물건 소비와 보상처럼 여러 상태가 함께 바뀌는 행동에는 하나의 작업 정체성을 부여한다. 각 단계는 무엇을 예약했고, 무엇을 완료했고, 어느 결과를 이미 반영했는지 기록한다. 다시 실행할 때는 처음부터 같은 효과를 반복하지 않고 남은 단계만 이어 간다.

이 방식은 다음 문제를 막는다.

- 생산품은 생겼는데 주문이 미완료로 돌아와 같은 출력이 다시 생기는 일
- 계약 물건은 사라졌지만 보상과 관계 변화가 적용되지 않는 일
- 원정대의 물건이 귀환 인계 도중 기지 재고와 원정 소지품에 동시에 존재하는 일
- 수술 재료는 다시 지급되었는데 치료 결과는 그대로 남는 일

완료된 작업은 이미 처리되었다는 사실을 남기고, 아직 전달하지 못한 결과는 별도로 보관한다. 저장 시점과 무관하게 완료가 중복되거나 누락되지 않게 하는 장치다.

## 플레이에서 드러나는 사례

### 원정 귀환

원정대가 전리품을 들고 돌아오는 도중 저장했다면, 불러오기 뒤에도 같은 인원, 부상, 장비, 소비한 보급과 전리품을 가진 채 같은 귀환 단계에서 이어져야 한다. 전리품이 기지에 들어온 뒤에는 원정 소지품에서 사라져야 하며, 인계가 끝난 결과를 다시 지급해서는 안 된다.

### 시설 이전과 진화

오래 사용한 시설을 해체하고 포장하는 도중 저장해도 개체의 사용 이력과 진화 성질은 유지되어야 한다. 포장된 시설은 원래 자리에 가동 중인 시설로 남아 있으면 안 되며, 재설치 뒤에는 새 방의 조건에 따라 활성 또는 휴면 상태를 다시 판정한다. 이전은 시설 복제나 활성 조건 초기화에 사용할 수 없다.

### 수술과 생산

수술과 제작은 실제 투입 재료, 기여 작업량과 확정된 결과를 보존한다. 완료 직전 저장을 반복해 품질이나 수술 결과를 다시 뽑을 수 없어야 한다. 시설 파괴나 환자 상태 변화로 계속할 수 없다면 이미 사용한 재료와 회수 가능한 물건을 구분해 실패 경로로 보낸다.

### 사건과 계약

선택한 사건은 같은 참여자, 시설, 비용과 기한을 유지해야 한다. 완료 보상이나 세력 관계를 적용한 뒤 저장했다면 같은 결과를 다시 받을 수 없어야 한다. 여러 날에 걸친 공통 사건 작업과 완료 영수증의 적용 범위는 아직 [시스템 구현 권위 체크리스트](../system-implementation-checklist.md)가 판정한다.

## 손상된 저장을 억지로 열지 않는 이유

필수 데이터가 없거나, 서로 의존하는 상태의 순서가 잘못되었거나, 같은 물건을 두 권위가 동시에 주장한다면 임의의 기본값으로 메우지 않는다. 일부만 복원된 세계는 처음에는 정상처럼 보여도 이후 생산, 가족, 원정과 보상에서 더 큰 손상을 만든다.

복원은 먼저 모든 저장 구역의 버전, 의존 관계와 참조를 검사하고 후보 상태를 준비한다. 전부 준비된 뒤에만 실제 세계를 교체한다. 중간 단계가 실패하면 준비한 후보를 버리고 불러오기 전 상태를 유지한다. 이 경계는 실패한 복원으로부터 현재 플레이 상태를 보호한다. 손상된 저장 자체의 복구는 별도 범위다.

## 같은 상태에서는 같은 판정

저장과 불러오기로 후보, 품질, 보상과 사건 결과를 다시 추첨할 수 없어야 한다. 게임 규칙에 영향을 주는 판정은 런의 난수 기준값, 안정 식별자, 입력 상태와 작성 정의의 판본에서 재현할 수 있어야 한다.

결정론의 보존 범위는 물건 소비, 전투와 치료 결과, 진화 후보, 사건 선택 결과와 같은 게임 규칙이다. 서술 문구나 화면 투영은 저장된 사실에서 다시 만들 수 있지만 그 사실을 바꾸어서는 안 된다. 프레임 단위의 화면 움직임은 이 범위에 포함되지 않는다.

## 복원 구조

저장 데이터는 책임 영역별로 나뉘고, 각 영역은 자신의 판본과 먼저 복원되어야 할 영역을 밝힌다. 중앙 복원 절차는 의존 관계를 검사한 뒤 후보 상태를 준비하고, 실제 세계 객체가 필요한 영역과 함께 한 번에 게시한다. 게시가 끝나기 전에 문제가 생기면 역순으로 준비 상태를 폐기한다.

아이템, 생산, 인물, 신체와 의료, 침입, 원정, 세력, 연구, 시설과 사건이 이 구조 안에서 각자의 상태를 맡는다. 화면용 목록과 캐시는 저장 권위가 아니며 복원된 상태에서 다시 만든다. 구체적인 저장 구역, 복원 순서와 도메인 간 인계는 [트랜잭션과 멱등성](../architecture/05-persistence-transactions-and-idempotency.md), [도메인 간 거래와 실패 경계](../architecture/10-cross-domain-transactions.md), [영속성과 검증 시스템](../architecture/systems/17-session-save-and-determinism.md)에서 확인한다.

## 검증의 층

저장 신뢰성은 파일을 한 번 열어 보는 것으로 확인할 수 없다.

1. 작성 정의의 중복 식별자와 잘못된 참조를 검사한다.
2. 저장 영역의 판본, 의존 관계와 그 관계의 순환을 검사한다.
3. 물질, 수량, canonical gram, 현재 책임, 용량과 제작 중 상태의 보존 규칙을 검사한다.
4. 취소, 부분 운반, 출력 포화, 파괴와 중간 저장 시나리오를 검사한다.
5. 실제 주민 작업과 월드 객체를 포함한 통합 흐름을 검사한다.
6. 장기 플레이에서 전략 다양성, 악용 가능성과 복구 경험을 확인한다.

이번 편찬은 코드, 작성 자산과 기존 문서를 정적으로 교차 확인했다. Unity 컴파일, 테스트와 플레이 모드는 실행하지 않았다. 정적 구현의 존재는 실행 성공이나 장기 플레이 품질을 증명하지 않는다. 현재 확인 범위와 남은 검증은 [시스템 구현 권위 체크리스트](../system-implementation-checklist.md)가 관리한다.
