# 04. 시각·상호작용 디자인

## 디자인 방향

나무위키의 색과 외형을 복제하지 않는다. 가져올 것은 빠른 내부 이동, 촘촘한 목차, 역링크, 표 중심 정보 밀도다. 최종 방향은 포스트 아포칼립스와 다크 판타지가 겹친 생존 기록 보관소다. 어두운 석재·그을린 종이·낡은 금속 표식의 분위기를 쓰되 장식보다 가독성을 앞세운다.

## 레퍼런스에서 가져올 원리

| 레퍼런스 | 채택 | 채택하지 않음 |
|---|---|---|
| 나무위키 | 고정 검색, 목차, 내부 링크, 역링크, 빠른 스캔, 아이콘 기반 문서 디렉터리의 빠른 훑기 | 고유 색상·컴포넌트 복제, 광고형 밀도, 커뮤니티 편집 UI |
| BG3 Wiki | 대표 이미지와 구조화 인포박스의 균형 | 게임 고유 장식과 자산 모사 |
| Factorio Wiki | 생산 입력·출력과 사용처의 양방향 탐색 | 표를 맥락 없이 과밀하게 나열 |
| RimWorld Wiki | 고밀도 능력치 표와 실전 설명의 공존 | 작은 글씨와 모바일 가독성 희생 |
| PCGamingWiki | 템플릿 규율, 상태 표식, 일관된 정보 위치 | 이 게임과 무관한 플랫폼·문제 해결 구조 |

RimWorld Wiki와 Factorio Wiki를 주 기능 레퍼런스로 삼고, 다른 경영·생존·콜로니 시뮬레이션 위키도 표 밀도, 생산 관계, 연구 선행 조건, 실전 설명 배치를 비교한다. 화면이나 자산을 복제하지 않고 반복해서 검증된 정보 구조 원리만 채택한다.

## 금지할 시각 문법

- 보라·청색 중심의 무의미한 그라데이션과 과도한 네온 glow
- glassmorphism, 큰 pill, 화면을 카드로만 쪼개는 SaaS dashboard 문법
- 목적 없는 입자·룬·빛기둥·추상 배경과 서로 화풍이 다른 장식 이미지
- 과도하게 매끈한 AI 생성 concept-art 인상, 가짜 세부 묘사, 읽을 수 없는 장식 문자
- 같은 의미의 수식어와 아이콘을 반복하는 홍보형 화면
- 표·수치·관계보다 큰 hero 이미지나 빈 여백

게임 원본 로고와 스크린샷을 우선 사용한다. 새 장식 이미지는 정보 기능과 출처가 명확할 때만 추가하며, AI 생성 이미지를 기본 채움 자산으로 사용하지 않는다.

## 화면 골격

- 상단 바: 로고, 전체 검색, 게임 버전 선택기, 주요 카테고리, 테마 전환
- 홈·전체 둘러보기: section band와 1px 경계로 묶은 아이콘 디렉터리 보드; 큰 카드·hero 대신 직접 문서 진입점을 제공
- 왼쪽 rail: 현재 영역의 계층, 접은 상태 기억
- 본문: 최대 읽기 폭을 제한하되 넓은 표는 별도 full-bleed 영역 허용
- 오른쪽 rail: 데스크톱에서 인포박스와 목차; 스크롤 위치에 따라 목차 강조
- 하단: 현재 게임 버전과 업데이트 기록, source snapshot 기준, 라이선스, 수정 제안 경로

콘텐츠 우선순위는 `제목 → 요약 → 핵심 사실 → 획득/사용 관계 → 세부 설명`이다. 장식 이미지는 이 순서를 밀어내지 않는다.

## 반응형 동작

| 폭 | 동작 |
|---|---|
| 1280px 이상 | 좌·본문·우 3열, 넓은 관계 표 |
| 768~1279px | 왼쪽 rail 축소, 인포박스 본문 상단, 목차 floating 버튼 |
| 767px 이하 | 단일 열, drawer 탐색, 카드형 핵심 수치, 표 가로 스크롤 |

모바일 표에는 첫 열 고정, 단위가 포함된 헤더, 스크롤 가능성 힌트를 제공한다. 중요한 수치를 카드로 중복할 수 있으나 값은 같은 데이터 객체에서 렌더링한다.

디렉터리 보드는 1280px 이상 3열, 768~1279px 2열, 767px 이하 1열이다. 시스템 인덱스의 왼쪽 icon rail은 모바일에서 각 row 상단 제목으로 이동한다. 두 보드 모두 cell/row의 텍스트 link를 유지하며, 아이콘만으로 탐색을 요구하지 않는다.

## 시각 토큰 초안

소유자가 게임 로고·대표 이미지·스크린샷의 위키 사용을 승인했다. 아래 방향 토큰을 실제 게임 UI 캡처와 대조해 최종 색상값으로 좁힌다.

- 배경: 숯·철·먹색에 가까운 저채도 암색, 읽기 면은 한 단계 밝은 중성색
- 본문: 고대비 회백색, 보조 정보는 대비 기준을 지키는 회색
- 강조: 오래된 황동·녹슨 구리 중 하나를 주 강조로 사용하고, 상호작용 색은 실제 게임 UI와 대조 후 하나만 선택
- 위험: 적색, 경고: 황색, 성공: 녹색을 사용하되 아이콘·문구를 병행
- 표면: 과한 그림자 대신 1px 경계와 명도 차
- 모서리: 작은 반경으로 도구·기록물 인상 유지
- 움직임: 150~200ms, `prefers-reduced-motion`에서 제거

## 타이포그래피

- 한국어 시스템 sans-serif를 기본으로 사용해 외부 폰트 요청과 초기 로딩을 없앤다.
- 브랜드 폰트는 라이선스와 한글 글리프를 확인한 뒤 self-host한다.
- 본문 기본 16px 이상, 줄 높이 1.65 전후, 한 줄 65~80자 범위를 목표로 한다.
- 숫자 비교 표에는 tabular numerals를 사용한다.
- 제목 계층은 크기뿐 아니라 여백과 landmark로 구분한다.

## 핵심 컴포넌트

- 전역 검색/명령 팔레트
- 홈·전체 둘러보기 `DirectoryBoard`와 system hub `SystemIndexBoard`
- same-document 게임 버전 선택기와 게임 버전별 문서 부재 안내
- breadcrumb와 문서 상태 배지
- 유형별 인포박스
- 접을 수 있는 스포일러 블록
- 관계 표와 역링크 목록
- 생산식·연구 edge 카드
- 제작·연구 관계 그래프 explorer: 방향·유형·깊이 필터, node 선택 상세, 확대·맞춤 보기, 표 fallback
- 필터·정렬 가능한 목록
- 게임 버전·업데이트 기록과 source snapshot/자동 생성 알림
- 빈 상태, 오류 상태, 리디렉션 알림
- 복사 가능한 영구 링크와 절 링크

## 상호작용 규칙

- hover가 없어도 모든 기능을 사용할 수 있어야 한다.
- 클릭 가능한 행은 링크 텍스트와 focus 표시를 갖는다.
- 접힘 상태가 핵심 사실을 숨기지 않으며 스포일러만 기본 접힘이다.
- URL query로 검색·필터 상태를 공유할 수 있게 한다.
- 그래프 확대·이동은 선택 기능이고 키보드·표 대안을 제공한다.
- 그래프는 한 페이지의 관계를 읽는 보조 도구다. 전체 게임을 한 화면에 쌓지 않고, 중심 node에서 작은 범위를 기본으로 열며 노드 유형은 모양·아이콘·문구로도 구분한다.
- 필터 적용, 선택 node, 깊이는 URL query로 공유하지만 pan/zoom은 로컬 보기 상태로만 유지한다.
- 테마 선택은 localStorage에만 저장하고 기능 사용에 동의를 요구하지 않는다.

## 디자인 산출물 순서

1. 게임 UI·로고·스크린샷 자산 감사
2. 흑백 정보 구조 wireframe
3. 홈, 가이드, 아이템, 시설, 생산식, 연구, 검색의 7개 대표 화면
4. desktop·mobile 고충실도 시안
5. 토큰과 컴포넌트 상태표
6. 실제 데이터가 들어간 브라우저 프로토타입
7. 대비·키보드·긴 한국어·빈 데이터·스포일러 시각 QA

시각 승인에는 “AI 생성 사이트처럼 보이지 않는가”를 별도 항목으로 둔다. 표·본문·탐색을 제거했을 때 남는 장식만으로 분위기를 만들려 했다면 실패로 판정한다.

시안을 승인하기 전 대량 페이지 템플릿을 확정하지 않는다.

대표 페이지별 정보 순서와 상태 화면은 [페이지 구성과 콘텐츠 경험 명세](15-page-composition-and-content-experience.md)에 고정하고, 이 문서는 그 화면이 공유할 시각 규칙만 소유한다.

디렉터리 보드의 그룹·cell·icon·게임 버전·스포일러·검증 계약은 [디렉터리 보드와 허브 탐색 명세](17-directory-board-and-hub-navigation.md)에 고정한다.
