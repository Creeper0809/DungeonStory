# 16. 외부 위키 참고 기반 콘텐츠 구조

## 목적과 경계

이 문서는 플레이어용 DungeonStory 위키가 **무엇을 어떤 크기의 문서로 나누고, 페이지 사이를 어떻게 연결할지** 정한다. [페이지 구성과 콘텐츠 경험 명세](15-page-composition-and-content-experience.md)가 한 페이지 안의 화면 순서를 정한다면, 이 문서는 여러 페이지를 묶는 콘텐츠 계층과 편집 단위를 정한다.

나무위키 게임 문서, 특히 림월드의 게임 허브와 연구·자원·이벤트·업데이트 문서를 참고했다. 참조한 것은 한 게임의 큰 시스템을 상위 허브로 묶고, 개별 데이터·규칙은 별도 문서에서 찾아가게 하는 **정보 구조와 탐색 패턴**뿐이다. 문장, 표의 내용, 문서명 체계, 접이식 UI, 스킨·CSS, 이미지와 아이콘은 가져오거나 모방하지 않는다.

## 참고 관찰과 채택 판단

| 관찰한 패턴 | 참고 근거 | DungeonStory 적용 | 적용하지 않는 부분 |
|---|---|---|---|
| 게임 허브에서 목표·시스템·자원·인물·사건·업데이트 같은 큰 진입점을 한곳에 모은다 | [림월드 게임 허브](https://dark.namu.moe/w/%EB%A6%BC%EC%9B%94%EB%93%9C) | 홈에 `시작하기`, `시스템`, `콘텐츠 도감`, `관계 도구`, `게임 버전·업데이트`를 고정 진입점으로 둔다 | 원문 관련 문서 상자의 구조·명칭·시각 디자인을 복제하지 않는다 |
| 연구는 시대/분야로 묶되, 각 항목에서 조건·비용·해금 결과를 구분한다 | [림월드/연구](https://dark.namu.moe/w/%EB%A6%BC%EC%9B%94%EB%93%9C/%EC%97%B0%EA%B5%AC) | 연구 허브는 분야·단계 filter, 연구 페이지는 `선행 → 현재 → 해금`과 graph를 제공한다 | 매우 긴 연구 항목 나열이나 원문 공략 서술을 이식하지 않는다 |
| 자원·제작품은 상위 재료군에서 하위 종류로 내려가며, 관련 획득/교역 맥락을 함께 둔다 | [림월드/자원](https://dark.namu.moe/w/%EB%A6%BC%EC%9B%94%EB%93%9C/%EC%9E%90%EC%9B%90) | 아이템 도감은 원료·중간재·소모품·장비 재료 등으로 범주화하고, 개별 페이지에서 획득·사용처·생산망을 분리한다 | 네 단계 이상 제목을 계속 중첩해 목록을 탐색의 주수단으로 만들지 않는다 |
| 사건은 성격과 플레이 맥락으로 그룹화하고, 개별 결과를 같은 범주 안에서 읽게 한다 | [림월드/이벤트](https://dark.namu.moe/w/%EB%A6%BC%EC%9B%94%EB%93%9C/%EC%9D%B4%EB%B2%A4%ED%8A%B8) | 사건·축제·침입·조우는 `우호/사회`, `생존·환경`, `전투 위협`, `원정`, `서사·엔드게임`으로 먼저 찾게 하고 spoiler tier를 명시한다 | 결과를 제목·목차·검색 snippet으로 먼저 노출하지 않는다 |
| 업데이트는 버전별 상위 항목과 변화 종류를 분리해 장기 이력을 보존한다 | [림월드/업데이트 내역](https://dark.namu.moe/w/%EB%A6%BC%EC%9B%94%EB%93%9C/%EC%97%85%EB%8D%B0%EC%9D%B4%ED%8A%B8%20%EB%82%B4%EC%97%AD) | 게임 버전을 최상위 filter로 삼고, 각 버전에서 added/changed/fixed/known issues/migration과 영향 콘텐츠를 연결한다 | 사람이 계속 늘어놓는 거대한 변경 로그나 위키 배포 버전을 게임 버전으로 오인하게 하는 표기는 쓰지 않는다 |

직접 나무위키 원문은 외부 조회 환경에서 열리지 않아, 위키 편집 링크가 연결된 공개 미러로 구조를 확인했다. 구현 전에는 이 문서의 링크를 재검토하되, 외부 문서의 사실이나 표현을 DungeonStory 원천으로 사용하지 않는다.

## 채택한 플레이어 탐색 모델

```text
홈
├─ 시작하기                         처음 하는 플레이의 순차 가이드
├─ 시스템 허브                       규칙과 의사결정의 설명
│  ├─ 정착·시설                     ├─ 생산·물류
│  ├─ 연구·발전                     ├─ 인물·사회
│  ├─ 생존·의료                     ├─ 전투·방어
│  └─ 세계·원정·사건
├─ 콘텐츠 도감                       데이터형 목록과 비교
│  └─ 개별 콘텐츠 페이지             사실·관계·관련 가이드
├─ 관계 도구                         제작 / 연구 / 시설 그래프
└─ 게임 버전·업데이트                현재·과거 snapshot과 변경 영향
```

어느 깊이에서든 독자는 다음 세 가지 길을 가져야 한다.

1. **위로:** 상위 시스템·카테고리로 돌아가 범위를 다시 잡는다.
2. **옆으로:** 같은 목적의 대안, 같은 분류의 항목, 비교 표로 이동한다.
3. **아래로:** 현재 항목의 조건·결과·사용처를 개별 문서 또는 제한된 관계 그래프로 따라간다.

breadcrumb은 canonical 주 분류를, 페이지 하단의 `관련 가이드`·`역링크`는 실제 관계를 보여 준다. 두 기능을 같은 링크 묶음으로 중복하지 않는다.

## DungeonStory 콘텐츠 지도

큰 분류는 플레이 행동으로 나누고, 데이터 유형은 여러 분류에 중복 노출할 수 있다. 각 엔터티의 canonical 페이지는 하나뿐이다.

| 플레이어가 찾는 일 | 시스템 허브 | 도감·하위 콘텐츠 | 대표 제공 요소 |
|---|---|---|---|
| 살아남을 기반을 만든다 | 정착·시설 | 시설, 방, 건설 재료, 보관·물류 설비 | 건설 조건, 공간·입출력, 가능한 작업, 지원 관계 |
| 재료를 얻어 생산한다 | 생산·물류 | 원료, 중간재, 아이템, 제작식, 생산 주문 | 획득처, 입력·시설·출력, 부산물, 사용처, 대체 경로 |
| 발전 경로를 고른다 | 연구·발전 | 연구, 해금, 이정표, 엔드리스 관련 진입점 | 선행, 비용·요구, 해금 목록, 후속 분기, 연구 그래프 |
| 주민과 사회를 운영한다 | 인물·사회 | 종족, 특성, 손님, 세력, 계약, 포로 | 적용 조건, 관계 상태, 선택·보상 범주, 관련 사건 |
| 식량·건강·환경을 관리한다 | 생존·의료 | 농업, 축산, 식품, 의료, 질병 | 환경·성장/발병 조건, 예방·치료, 필요한 물자·시설 |
| 싸우고 원정한다 | 전투·방어 / 세계·원정 | 무기, 방어구, 방패, 의복, 부품, 적, 침입, 원정, 전투 조우 | 장비 조건, 위협·보상 범주, 대응 수단, 준비물 |
| 세계와 이야기를 이해한다 | 세계·사건 | 사건, 축제, 세력, 서사, 엔드게임 | 안전한 개요, 발생/접근 조건, 대응, spoiler-protected 결과 |
| 이번 버전에서 달라진 것을 확인한다 | 게임 버전·업데이트 | 버전 노트, 정정, 비교 대상 | 영향 요약, added/changed/fixed, legacy/부재 안내 |

`아이템`과 `시설`처럼 여러 행동에 걸치는 유형은 상위 시스템의 목록에도 나타날 수 있다. 예를 들어 의료용 아이템은 `생존·의료`와 `콘텐츠 도감 > 아이템` 모두에서 찾지만, 같은 `/entry/{slug}/`로 간다.

## 허브와 목록의 구성

### 홈

홈은 홍보 랜딩 페이지가 아니라 다음 행동을 고르는 지도다.

핵심 진입점은 긴 텍스트 목록이 아니라 icon·짧은 라벨·section band를 가진 `CoreDirectoryBoard`로 보인다. 전체 공개 분류는 별도 `/directory/`에서 확인하며, 시스템 페이지에는 더 깊은 `SystemIndexBoard`를 쓴다. 화면 문법과 data contract는 [디렉터리 보드와 허브 탐색 명세](17-directory-board-and-hub-navigation.md)를 따른다.

- `처음 시작하기`: 첫 정착·생존·생산의 짧은 순서형 가이드
- `지금 찾기`: 전체 검색, 아이템·시설·연구 빠른 진입
- `시스템 이해`: 여섯 개 시스템 허브와 한 줄 설명
- `관계로 찾기`: 제작·연구·시설 graph explorer
- `이번 게임 버전`: 현재 버전, 업데이트 요약, 이전 게임 버전으로 이동
- `주의`: 공통 spoiler 정책, 데이터 기준, 정정 상태

최근 업데이트 카드는 최대 세 개의 플레이 영향만 표시한다. 홈페이지를 긴 변경 이력이나 모든 콘텐츠 카드의 집합으로 만들지 않는다.

### 시스템 허브

시스템 허브는 읽는 순서가 있는 설명 문서다.

```text
시스템 한줄 정의와 대상 게임 버전
이 시스템에서 반복하는 행동 순환
지금 내리는 핵심 선택 3개 이하
처음 할 일 → 흔한 실패 → 회복 방법
주요 콘텐츠·관계 도구 바로가기
심화 가이드 / 관련 시스템 / 변경 이력
```

시스템 허브에는 모든 세부 수치를 재작성하지 않는다. 수치·제작 입력·정확한 해금은 개별 콘텐츠 페이지와 관계 표의 권위로 남긴다.

### 카테고리·목록 허브

카테고리 페이지는 카드 벽보다 밀도 높은 표와 filter를 우선한다.

- 범위 설명과 하위 분류를 먼저 보여 준다.
- 기본 filter는 게임 버전·공개/스포일러 허용 상태·유형이며, 도메인별 filter를 추가한다.
- 예: 아이템은 획득 방식·용도·보관 조건, 연구는 분야·단계·해금 유형, 사건은 성격·위협·플레이 단계다.
- 표 행은 제목, 안전한 짧은 설명, 유형별 핵심 1~3개 fact, 마지막 변경 게임 버전만 가진다.
- 모바일은 행을 세로 facts로 재배열하고, filter는 선택 수와 초기화 버튼을 명시한다.

정렬과 filter가 없이는 찾아보기 힘든 30개 이상의 동급 항목을 한 페이지 본문 제목으로 계속 쌓지 않는다.

## 개별 콘텐츠 페이지의 필수 요소

공통 화면 순서는 [페이지 구성과 콘텐츠 경험 명세](15-page-composition-and-content-experience.md)를 따르고, 이 표는 각 콘텐츠가 최소로 제공해야 할 정보 계약이다.

| 콘텐츠 family | 첫 화면 facts | 관계·행동 블록 | 안전/특수 요소 |
|---|---|---|---|
| 아이템·원료·중간재 | 분류, 질량/보관, 가치·품질처럼 승인된 값 | 획득, 제작 입력/출력, 사용처, 대체재 | 생산 graph preview와 표 fallback |
| 시설·방 | 역할, 건설 조건, 공간, 작업·입출력 | 가능한 제작식·주문, 지원 시설, 병목 | 배치 좌표·내부 구현은 비공개 |
| 제작식·생산 주문 | 입력 → 실행 시설·작업 → 출력, 시간·요구 | 부산물, 선행 연구, 대체 제작식 | 물질 흐름과 손실을 분리 |
| 연구·이정표 | 연구 영역·단계, 비용·요구, 해금 수 | 선행 → 현재 → 해금, 후속 분기 | spoiler 해금 제목·edge는 허용 전 비노출 |
| 장비·의복·부품 | 슬롯, 역할별 핵심 값, 내구·조건 | 제작·장착·수리·소모, 비교 진입 | 긴 비교표 대신 비교 도구로 이동 |
| 종족·특성·사회 요소 | 적용 대상, 효과·관계 상태 | 관련 직업·의료·사건·계약 | 개인 서사 또는 비밀은 tier 적용 |
| 농업·축산·의료·질병 | 환경/발병·성장 조건, 산출·치료 요구 | 예방, 필요한 시설·물자, 연쇄 영향 | 위험·대응을 수치 설명보다 먼저 명시 |
| 사건·축제·침입·원정·조우 | 안전한 개요, 성격, 접근/발생 범주 | 준비·대응, 관련 세력·장비·가이드 | 결과·보상·결말은 spoiler block 안에만 둠 |
| 세력·계약·포로·적 | 관계·위협/보상 범주, 조건 | 상호작용, 관련 사건·전투·자원 | 미확정 확률·내부 AI는 공개하지 않음 |

모든 개별 페이지의 끝에는 `관련 가이드`, `같은 분류`, `이 항목을 참조하는 콘텐츠`, `게임 버전 변경/정정` 중 존재하는 것만 둔다. 단순 이름 유사성으로 추천을 자동 생성하지 않는다.

## 공통 표기와 편집 단위

### 표기 배지

각 엔터티와 목록 행에서 아래 표기를 한 위치에, 짧은 텍스트로 제공한다.

| 표기 | 목적 |
|---|---|
| 게임 버전 | 현재 읽는 snapshot을 확정한다 |
| 콘텐츠 유형 | 아이템·연구·사건 등을 즉시 구분한다 |
| 공개/스포일러 상태 | 열기 전 노출 경계를 알린다 |
| 변경 상태 | 이 버전에서 추가·변경·정정된 대상을 구분한다 |
| 데이터 신뢰 상태 | 검수된 공개 사실과 정정 존재를 안내한다 |

색, 아이콘, 줄임말만으로 의미를 전달하지 않는다. `DLC 표식`처럼 다른 게임에만 맞는 표기 대신, DungeonStory에는 `도입 게임 버전`, `현재 버전에서 부재`, `legacy`와 spoiler tier를 사용한다.

### 편집 단위

한 문서가 다음 두 책임을 동시에 지나치게 많이 갖지 않게 한다.

| 문서 종류 | 주 책임 | 분리 기준 |
|---|---|---|
| 시스템 가이드 | 플레이 순서와 선택 이유 | 독립 facts·관계가 많아지면 엔터티/목록으로 분리 |
| 카테고리 | 비교·filter·발견 | 한 항목의 운영법이 길어지면 개별 페이지/가이드로 분리 |
| 엔터티 | 검증된 facts와 직접 관계 | 초보자 순차 설명은 가이드로 이동 |
| 사건/서사 | 안전한 맥락과 선택·대응 | 결과·정체는 spoiler block 또는 별도 spoiler page로 분리 |
| 업데이트 | 해당 게임 버전의 플레이 영향 | 구현 커밋·배포 artifact·내부 수정 이력은 제외 |

## 피해야 할 패턴

- 모든 하위 페이지에 거대한 관련 문서 상자를 그대로 반복하지 않는다. 현재 위치와 직접 연결된 5~8개 이내의 local navigation을 우선한다.
- 제목 깊이가 네 단계 이상인 장문 목록을 기본 탐색으로 쓰지 않는다. 분류·filter·검색과 작은 하위 허브로 나눈다.
- 데이터 facts, 검수된 공략, 개인적 평가를 한 문단·한 표에 섞지 않는다. 사실과 전략 블록을 시각·권위상 분리한다.
- 스포일러 결과를 제목·목차·자동완성·관계 edge label에 먼저 넣지 않는다.
- 한 게임 버전의 설명을 다음 게임 버전 문서에 몰래 덮어쓰지 않는다. 게임 버전 snapshot·정정 절차는 [버전·업데이트 이력 관리](13-versioning-and-update-history.md)를 따른다.
- 외부 위키의 문장, 자료표, 이미지, 명칭·슬래시 문서 체계, CSS 또는 커뮤니티 편집 UI를 복사하지 않는다.

## 구현 순서와 완료 기준

1. 홈과 6개 시스템 허브, 게임 버전 허브의 route·breadcrumb·local navigation 계약을 만든다.
2. 아이템, 시설, 제작식, 연구의 카테고리·개별 페이지를 먼저 구현하고 생산/연구 graph와 연결한다.
3. 생존·의료, 인물·사회, 전투·원정, 사건·서사의 목록과 콘텐츠 family를 추가한다.
4. 게임 버전·업데이트에서 영향 콘텐츠와 이전 버전 비교를 연결한다.
5. 각 가족에서 대표 문서를 선정해 3회 이내 내부 이동, spoiler 비노출, JavaScript-off 표 fallback, 모바일 filter를 회귀 검증한다.

다음 조건을 만족할 때 콘텐츠 구조 구현을 완료로 본다.

- 각 공개 canonical 문서는 시스템 허브 또는 카테고리에서 도달 가능하며 고아가 없다.
- 대표 플레이어 질문이 `시스템 허브 → 목록/검색 → 개별 사실·관계` 흐름으로 해결된다.
- 선택한 게임 버전, 스포일러 허용 상태, 관계 표·graph 결과가 서로 섞이지 않는다.
- 모든 콘텐츠 family가 위의 필수 요소를 가지거나, 지원하지 않는 field를 명시적으로 `없음/해당 없음`으로 처리한다.
- 외부 위키의 원문·표·이미지를 재사용하지 않았음을 리뷰에서 확인한다.
