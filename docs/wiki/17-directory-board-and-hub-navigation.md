# 17. 디렉터리 보드와 허브 탐색 명세

## 목적

이 문서는 사용자가 제시한 두 종류의 탐색 화면을 DungeonStory 위키에 맞게 재구성한다.

- **디렉터리 보드:** 큰 분류와 직접 문서 진입점을 아이콘·짧은 이름·정렬된 격자로 한눈에 보여 준다.
- **시스템 인덱스 보드:** 한 시스템의 세부 주제를 왼쪽 식별 rail과 오른쪽 링크 묶음으로 밀도 높게 정리한다.

둘 다 일반 본문을 읽기 전에 “어디로 가야 하는가”를 해결하는 탐색 도구다. 페이지의 사실·관계·설명 순서는 [페이지 구성과 콘텐츠 경험 명세](15-page-composition-and-content-experience.md)를, 전체 콘텐츠 계층은 [외부 위키 참고 기반 콘텐츠 구조](16-reference-informed-content-architecture.md)를 따른다.

첨부 레퍼런스에서는 아이콘이 있는 격자와 왼쪽 분류 rail의 효용만 채택한다. 검은색 바, 표 비율, 글꼴, 이미지, 문서명, 문장, 슬래시 문서 구조를 복제하지 않는다.

## 배치와 역할

| 화면 | 제공하는 보드 | 독자가 해결하는 질문 | 범위 |
|---|---|---|---|
| `/` 홈 | `CoreDirectoryBoard` | 지금 무엇을 찾아야 하는가? | 현재 게임 버전의 핵심 진입점 |
| `/directory/` | `FullDirectoryBoard` | 모든 공개 시스템과 도감을 어떻게 훑는가? | 현재 게임 버전의 전체 공개 분류 |
| `/guide/{system}/` 시스템 허브 | `SystemIndexBoard` | 이 시스템에서 어떤 주제로 바로 가야 하는가? | 해당 시스템과 직접 연결된 가이드·도감·관계 도구 |
| `/category/{slug}/` | `LocalDirectoryBoard` | 이 분류의 하위 항목을 어떻게 나누는가? | 현재 카테고리와 최대 한 단계 하위 분류 |
| `/entry/{slug}/` | `LocalDirectoryBoard` 또는 관련 문서 목록 | 상위·동급·다음 관계 중 어디를 읽을까? | 4~8개 직접 연결 항목만 |

전역 상단 바에는 `둘러보기` 링크를 두어 `/directory/`를 연다. 홈에는 핵심 보드를 기본 노출하고, 전체 보드는 별도 화면에 유지해 첫 화면이 모든 항목으로 과밀해지지 않게 한다.

## CoreDirectoryBoard의 정보 구조

홈 보드는 아래 여섯 묶음을 기본으로 한다. 게임 버전에서 실제 공개된 대상만 보이며, 문서 수가 많아져도 cell의 목적은 “상위 문서로 들어가기”이지 모든 하위 엔터티를 나열하는 것이 아니다.

| 보드 묶음 | 직접 진입점 | 연결 대상 |
|---|---|---|
| 시작·정착 | 시작하기, 기본 순환, 정착·방, 보관·물류 | `/start/`, 기초 guide, 시설/방 category |
| 생산·생존 | 원료·아이템, 시설·작업대, 제작식·생산 주문, 농업·축산, 의료·질병 | category, 대표 system guide, 생산 관계 도구 |
| 연구·발전 | 연구, 해금·이정표, 엔드리스, 연구 관계 | research category/guide/graph; 스포일러는 안전한 라벨만 |
| 인물·사회 | 종족·특성, 손님·세력, 계약·포로 | entity category와 사회 system guide |
| 전투·세계 | 장비, 적·침입, 원정·조우, 사건·축제 | combat/world guide와 canonical category |
| 도구·기록 | 전체 검색, 비교, 제작 관계, 게임 버전, 업데이트 | search, compare, relation routes, `/updates/` |

`엔드리스`, 서사, 최종 조우처럼 제목 자체가 스포일러일 수 있는 대상은 보드에서 안전한 그룹명과 영향 경고만 보인다. 개별 항목 이름과 아이콘은 독자가 해당 spoiler tier를 허용한 뒤에만 렌더링한다.

## 보드의 화면 문법

### 디렉터리 보드

```text
DungeonStory 둘러보기                         [현재 게임 버전]
짧은 안내: 시스템·도감·도구에서 바로 찾기
────────────────────────────────────────────────────────────
시작·정착                                      ← section band
 [아이콘] 시작하기       [아이콘] 기본 순환     [아이콘] 정착·방
 [아이콘] 보관·물류      ...
────────────────────────────────────────────────────────────
생산·생존
 [아이콘] 원료·아이템    [아이콘] 제작식        [아이콘] 의료·질병
 ...
```

- 한 cell은 **아이콘 + 명시적인 링크 이름 + 필요할 때만 1줄 설명**으로 구성한다. 아이콘만으로 목적을 전달하지 않는다.
- 같은 묶음 안의 cell 크기와 icon 위치를 맞춘다. 표처럼 촘촘하되 SaaS 카드의 큰 그림자·큰 반경·과도한 여백은 쓰지 않는다.
- 섹션 band는 중성 다크 표면·가는 강조선·텍스트 제목으로 구분한다. 레퍼런스의 순수 흑백 bar를 재현하지 않고 프로젝트의 숯·황동/구리 토큰을 사용한다.
- 모든 cell은 anchor 하나이며 새 창을 강제하지 않는다. 전체 cell 클릭 영역은 충분히 크되, 중첩 버튼·숨은 링크를 넣지 않는다.
- 코어 묶음은 기본 접지 않는다. `더 보기`는 보조 분류나 선택적 콘텐츠에만 쓰고, 펼침 상태는 URL 조각 또는 브라우저 로컬 상태 중 하나로 일관되게 처리한다.

### 시스템 인덱스 보드

```text
┌───────────────┬─────────────────────────────────────────────────┐
│ [icon] 생산   │ 원료 · 중간재 · 제작식 · 생산 주문 · 시설 · 물류 │
├───────────────┼─────────────────────────────────────────────────┤
│ [icon] 연구   │ 연구 단계 · 선행 조건 · 해금 · 이정표 · 연구 관계 │
├───────────────┼─────────────────────────────────────────────────┤
│ [icon] 의료   │ 건강 · 질병 · 치료 · 의료 시설 · 의약품          │
└───────────────┴─────────────────────────────────────────────────┘
```

- 왼쪽 rail은 분류의 아이콘과 이름을 항상 함께 보여 준다. 오른쪽에는 2~8개의 짧은 링크를 의미 단위 줄로 묶는다.
- 현재 시스템에 속하지 않는 전역 항목을 끼워 넣지 않는다. 전역 도구는 보드 마지막의 별도 `도구·기록` row에만 둔다.
- 오른쪽 링크는 모든 같은 유형 항목을 나열하지 않고 category, 대표 guide, 관계 도구, 중요한 비교·상태 화면으로 이동한다.
- 개별 콘텐츠 페이지에서는 이 큰 보드를 반복하지 않는다. breadcrumb와 4~8개 이하의 `현재 위치에서 계속 보기`만 제공한다.

## 반응형·접근성

| 폭 | 디렉터리 보드 | 시스템 인덱스 보드 |
|---|---|---|
| 1280px 이상 | 3열 기본, 항목 수가 적은 마지막 행은 빈 cell을 채우지 않음 | 고정 폭 왼쪽 rail + 우측 링크 묶음 |
| 768~1279px | 2열, section band는 전체 폭 | rail 폭 축소, 링크는 2줄까지 자연 줄바꿈 |
| 767px 이하 | 1열, 각 cell은 icon·제목·짧은 설명을 세로 정렬 | rail을 각 row의 상단 제목으로 이동하고 그 아래에 링크 목록 표시 |

- `nav` landmark와 section heading을 사용해 screen reader가 보드 묶음을 건너뛸 수 있게 한다.
- 아이콘은 장식이면 `aria-hidden`이고 링크 텍스트가 이름을 가진다. 의미를 보강하는 아이콘이면 텍스트 대체를 중복하지 않는다.
- 키보드 tab 순서는 시각 순서와 같다. roving-tabindex나 화살표 키 전용 grid 조작을 요구하지 않는다.
- 200% zoom에서 cell의 제목·버전·스포일러 배지가 겹치지 않아야 한다. 긴 한국어 이름은 줄바꿈하고 말줄임표만으로 링크 의미를 감추지 않는다.
- JavaScript 없이 모든 공개 link와 보드 내용이 HTML에 존재한다. JavaScript는 선택적 열기/접기와 현재 위치 강조에만 사용한다.

## 게임 버전·공개·생성 계약

`wiki/game-versions/{game-version}/content/directory.yml`은 해당 게임 버전 보드의 curated 구조를 저장한다. 새 게임 버전은 직전 폴더 전체 복사 규칙에 따라 이 파일도 복사하고 새 버전에서만 수정한다.

| 필드 | 의미 | 금지 |
|---|---|---|
| `group_id`, `label`, `sort_order` | 보드 묶음의 안정 식별자·표시명·순서 | 화면 문구로부터의 자동 ID 추론 |
| `entry_id`, `label`, `safe_label` | 보드 항목과 스포일러 안전 표기 | 외부 위키 문서명·문장 복사 |
| `target_kind`, `target_id` | category/guide/relation/update 같은 canonical 대상 | raw URL 문자열을 수기 중복 권위로 사용 |
| `icon_ref` | 승인된 게임 자산 또는 first-party 기능 아이콘 manifest 키 | 권리 미확인 외부 이미지·AI 생성 아이콘 |
| `visibility`, `spoiler_tier` | 공개·마스킹 규칙 | CSS blur만으로 보호 |
| `min_game_version`, `retired_in` | snapshot별 도입·부재 안내 | 다른 게임 버전 대상의 자동 혼입 |

빌드는 `target_id`가 선택 게임 버전의 공개 canonical 대상인지, label·safe label·icon이 manifest에 있는지, 같은 대상이 의도 없이 여러 보드에서 중복되지 않는지 검사한다. 대상이 없는 경우 생성 실패가 기본이다. “비슷한 문서”로 바꾸는 fallback은 허용하지 않는다.

## 구현과 검증

1. `DirectoryBoard`, `DirectoryGroup`, `DirectoryEntry`, `SystemIndexRow`의 정적 HTML 컴포넌트와 schema를 만든다.
2. 현재 게임 버전의 홈·전체 디렉터리·생산·연구 system hub fixture에 실제 공개 대상만 연결한다.
3. game-version selector, spoiler 상태, 좁은 화면, keyboard, JavaScript-off를 포함한 browser test를 추가한다.
4. 나머지 시스템 허브와 category local board를 연결한 뒤, 73개 원천 유형의 노출 위치를 검증한다.

필수 acceptance:

- 홈 보드의 모든 link가 현재 게임 버전의 공개 canonical page 또는 허용된 도구 route로 한 번에 이동한다.
- 핵심 보드 여섯 묶음과 시스템 인덱스의 행이 360px·768px·1280px에서 의미·순서·접근성을 잃지 않는다.
- 허용하지 않은 spoiler의 제목·아이콘·target URL이 보드 HTML·검색·sitemap·preload에 없다.
- 과거 게임 버전에서는 그 snapshot의 directory manifest만 읽고, 부재 대상은 안전한 상위 category/version 안내로 처리한다.
- 사용자 제시 레퍼런스와 나란히 검토했을 때, ‘밀도 높은 구조화된 길잡이’라는 목적은 충족하지만 외형·문장·아이콘·문서명 복제로 보이지 않는다.
