# 02. 정보 구조와 URL

## 구조 원칙

위키의 최상위 구조는 저장소 폴더가 아니라 플레이어의 질문을 따른다. 문서형 가이드와 데이터형 엔터티를 분리하되, 페이지 안에서는 양쪽을 강하게 연결한다.

## 1차 탐색

| 영역 | 내용 |
|---|---|
| 시작하기 | 게임 소개, 기본 순환, 첫 정착, 생존 기본 |
| 시스템 | 건설, 생산·물류, 연구, 인물·사회, 전투, 의료, 사건, 저장 세계 |
| 콘텐츠 | 아이템, 시설, 생산식, 연구, 장비, 종족·특성, 농축산, 질병, 사건, 세력, 원정·조우 |
| 도구 | 전체 검색, 비교 표, 생산 관계, 연구 관계 |
| 위키 정보 | 데이터 기준, 변경 이력, 공개 정책, 라이선스 |

홈·시스템 허브·도감·개별 콘텐츠·관계 도구·게임 버전의 역할 분담과 콘텐츠 family의 세부 구성은 [외부 위키 참고 기반 콘텐츠 구조](16-reference-informed-content-architecture.md)를 따른다. 이 계층은 나무위키 게임 문서의 탐색 장점만 참고한 독자 구조이며, 문서명·UI·본문을 복제하지 않는다.

## 라우트 계약

| 라우트 | 역할 |
|---|---|
| `/` | 홈, 핵심 진입점, 최근 갱신, 대표 카테고리 |
| `/directory/` | 현재 게임 버전의 전체 시스템·도감·도구를 아이콘 기반 디렉터리 보드로 탐색 |
| `/start/` | 초보자용 순차 가이드 |
| `/guide/{slug}/` | 시스템·공략·용어 설명 |
| `/entry/{slug}/` | 개별 콘텐츠의 canonical 페이지 |
| `/category/{slug}/` | 유형·주제별 목록과 하위 분류 |
| `/compare/{slug}/` | 승인된 유형의 비교 표 |
| `/relations/production/` | 생산 입력·출력·시설 관계 탐색 |
| `/relations/production/{slug}/` | 특정 아이템·제작식을 중심으로 한 제작 그래프와 관계 표 |
| `/relations/research/` | 연구 선행·해금 관계 탐색 |
| `/relations/research/{slug}/` | 특정 연구를 중심으로 한 연구 그래프와 관계 표 |
| `/search/` | 전체 검색과 필터 |
| `/updates/` | 게임 버전별 공개 업데이트 기록 |
| `/updates/{game-version}/` | 특정 게임 버전의 변경·수정·source snapshot·알려진 문제 |
| `/changes/` | `/updates/`로 보내는 영구 리디렉션 |
| `/game-versions/{game-version}/` | 선택 게임 버전의 홈과 탐색 시작점 |
| `/game-versions/{game-version}/entry/{slug}/` | 선택 게임 버전의 엔터티 스냅샷 |
| `/game-versions/{game-version}/guide/{slug}/` | 선택 게임 버전의 가이드 스냅샷 |
| `/game-versions/{game-version}/relations/production/{slug}/` | 선택 게임 버전의 제작 그래프 |
| `/game-versions/{game-version}/relations/research/{slug}/` | 선택 게임 버전의 연구 그래프 |
| `/about/data/` | 데이터 기준, 자동 생성 범위, 신뢰도 설명 |
| `/about/license/` | 게임 자산·텍스트·외부 자료의 이용 조건 |
| `/404.html` | 별칭 검색과 상위 카테고리로 복구하는 오류 페이지 |

배포 경로가 GitHub 프로젝트 하위 경로가 되더라도 문서 내부 링크는 Astro의 base 설정을 사용한다. 문자열로 `/저장소명/`을 박지 않는다.

## canonical URL과 슬러그

- 화면 제목과 URL 슬러그를 분리한다.
- canonical 슬러그는 `wiki/game-versions/{game-version}/content/slug-registry.csv`에 포함한다. 새 게임 버전은 이전 registry를 함께 복사하므로 기존 slug를 삭제·재배정하지 않는다.
- 기본 슬러그는 사람이 읽을 수 있는 한국어 kebab-case다. 브라우저 전송 시 퍼센트 인코딩될 수 있다.
- 동명이인은 유형 또는 세계관 한정어로 구분한다. 예: `철-아이템`, `철-연구`가 아니라 실제 의미가 드러나는 `철-광석`, `철-가공-연구`를 우선한다.
- 표시명 변경 시 기존 슬러그는 별칭과 영구 리디렉션으로 남긴다.
- 안정 ID는 생성·검증 키지만 공개 URL에 기본 노출하지 않는다.
- 게임 버전 URL은 소유자가 정한 `0.0.1v` 형식을 그대로 사용하며 이미 공개한 게임 버전 경로를 재사용하지 않는다.
- 대소문자, Unicode 정규화, 공백·구두점 규칙은 생성기에서 단일 구현한다.

## 계층과 다중 소속

엔터티는 canonical 페이지 하나만 가지며 여러 카테고리에 동시에 속할 수 있다. 폴더 계층을 데이터 분류로 오해하지 않는다.

예를 들어 하나의 약품은 `의료`, `소모품`, `생산품`, 특정 연구 해금 카테고리에 함께 노출되지만 주소는 하나다. breadcrumb는 사용자가 들어온 경로가 아니라 canonical 주 분류를 표시하고, 다른 분류는 태그와 관련 목록으로 제공한다.

## 페이지 내 탐색

데스크톱은 세 영역을 사용한다.

- 왼쪽: 전역 카테고리와 현재 계층
- 가운데: 제목, 상태, 본문, 관계 표
- 오른쪽: 인포박스 또는 목차, 관련 문서, 역링크 요약

모바일은 검색을 상단에 유지하고 왼쪽 탐색은 drawer, 오른쪽 영역은 본문 내 접이식 블록으로 바꾼다. 핵심 사실을 열기 전까지 숨기지 않는다.

관계 그래프는 각 엔터티 페이지의 관계 절에서 작은 미리보기로 제공하고, `관계 그래프 열기`가 위의 dedicated route로 이동한다. 전역 전체 그래프 route는 만들지 않는다. 그래프 URL의 `type`, `direction`, `depth`, `nodeKinds`, `edgeKinds` query는 선택 게임 버전 범위 안에서만 해석하며, 표 fallback에도 같은 필터 결과를 표시한다.

홈과 `/directory/`는 전역 분류를 아이콘·짧은 라벨·정렬된 cell로 보여 주는 `DirectoryBoard`를 제공한다. 시스템 가이드는 같은 원리를 더 깊은 topic 목록에 적용한 `SystemIndexBoard`를 제공한다. 범위·보드 데이터·반응형·접근성·게임 버전 계약은 [디렉터리 보드와 허브 탐색 명세](17-directory-board-and-hub-navigation.md)를 따른다.

## 게임 버전 선택기

- header와 footer에서 현재/과거 게임 버전을 선택한다.
- 같은 stable ID 또는 guide ID가 대상 게임 버전에 있으면 그 문서로 바로 이동한다.
- 대상 게임 버전에 없으면 해당 게임 버전 홈에서 부재 이유와 category/search 복구 링크를 제공한다.
- 게임 버전을 선택한 뒤 내부 링크·역링크·관계·비교·검색은 모두 같은 게임 버전 범위에 머문다.
- unversioned route는 current 게임 버전 canonical이고, 과거 게임 버전 route는 열람 가능하되 `noindex,follow`다.

전체 snapshot과 복사 규칙은 [버전·업데이트 이력 관리](13-versioning-and-update-history.md)를 따른다.

## 문서 연결 규칙

- 처음 등장하는 핵심 용어만 자동 링크하고 같은 절에서 반복 링크하지 않는다.
- 모호한 표시명은 자동 링크하지 않고 명시적 대상 ID가 있을 때만 연결한다.
- 존재하지 않거나 공개 차단된 대상 링크는 공개 HTML에 만들지 않는다.
- 역링크는 관계 유형별로 묶고 최대 항목 뒤에는 전체 목록 링크를 둔다.
- 외부 링크는 내부 링크와 시각적으로 구분하고 새 창을 강제하지 않는다.

## 사이트맵과 탐색 완전성

- 공개 canonical 페이지만 XML sitemap에 포함한다.
- 리디렉션, 검색 결과, 필터 조합, 내부 QA 페이지는 색인하지 않는다.
- 모든 공개 페이지는 홈에서 링크 그래프로 도달 가능해야 한다.
- 고아 페이지 검사는 빌드 실패 조건이다.
