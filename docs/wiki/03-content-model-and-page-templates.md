# 03. 콘텐츠 모델과 문서 템플릿

## 공통 엔터티 계약

모든 생성 페이지는 다음 공통 모델을 갖는다.

| 필드 | 의미 | 공개 여부 |
|---|---|---|
| `stable_id` | 원천과 재생성을 잇는 불변 키 | 내부 기본 |
| `kind` | 아이템·시설·연구 등 유형 | 공개 |
| `title` | 현재 표시명 | 공개 |
| `slug` | canonical URL 키 | 공개 |
| `aliases` | 이전 이름·검색 별칭 | 검색용 |
| `summary` | 검수된 1~3문장 소개 | 공개 가능 |
| `facts` | 원천에서 추출한 유형별 사실 | 공개 필드만 |
| `relations` | 입력·출력·해금·요구·사용처 등 typed edge | 공개 대상만 |
| `graph_capabilities` | 이 엔터티에서 열 수 있는 제작·연구·시설 graph 종류와 허용 relation type | 공개 |
| `categories` | 탐색 분류 | 공개 |
| `directory_groups` | 홈·시스템·카테고리 보드에서 노출될 curated 분류 키 | 공개 |
| `visibility` | `public`, `spoiler`, `internal`, `blocked` | 빌드 제어 |
| `spoiler_tier` | `none`, `progression`, `narrative`, `endgame` | UI·검색 제어 |
| `game_version` | 이 문서 snapshot이 속한 게임 버전 | 공개 |
| `source_snapshot_digest` | 해당 게임 버전을 생성할 때 사용한 source digest | 축약 공개 |
| `last_changed_in_game_version` | 이 페이지의 공개 의미가 마지막으로 바뀐 게임 버전 | 계산 가능할 때 공개 |
| `quality_flags` | 미해결 참조·수동 검토 등 | 내부 QA |

## 수기 overlay 계약

`wiki/game-versions/{game-version}/content/curated/`의 파일은 안정 ID로 같은 게임 버전의 생성 엔터티를 가리킨다. 허용 필드는 `summary`, `overview`, `strategy`, `examples`, `notes`, `related_guides`, `visibility_override`다.

수기 overlay가 숫자, 요구량, 제작 시간, 비용, 해금 조건, 능력치, 드롭률을 정의하거나 덮어쓰면 스키마 검증이 실패해야 한다. 이런 사실은 원천 자산·승인 문서에서 고친 뒤 재생성한다.

published 게임 버전의 모델과 overlay는 수정하지 않는다. 게임 업데이트는 직전 게임 버전 폴더를 새 게임 버전으로 복사한 뒤 새 폴더에서만 수행한다.

## 공통 페이지 순서

1. 제목, 유형, 공개 상태, 선택된 게임 버전과 source snapshot digest
2. 짧은 소개
3. 유형별 인포박스
4. 획득·요구·해금 경로
5. 사용처·영향·대안
6. 상세 규칙 또는 수치 표
7. 플레이 해설과 주의점
8. 관련 콘텐츠와 가이드
9. 역링크와 마지막 변경 게임 버전
10. 관계 그래프 미리보기와 같은 정보를 가진 표 fallback

빈 절은 숨긴다. 데이터가 없다는 사실이 의미 있을 때만 `없음`으로 표시한다. 추측으로 채우지 않는다.

## 가이드 템플릿

가이드는 `docs_final/handbook`의 구조를 그대로 노출하지 않고 플레이어 질문에 맞게 재편집한다.

- 무엇인가
- 언제 중요해지는가
- 플레이어가 내리는 핵심 결정
- 기본 흐름
- 실패 원인과 회복법
- 관련 콘텐츠 예시
- 더 깊은 문서

구현 클래스, 저장 경계, 미구현 계획은 공개 본문에서 제외한다. 목표 설계와 현재 구현이 다르면 현재 구현만 사실로 공개하고 목표안은 노출하지 않는다.

페이지의 공통 블록, 유형별 실제 화면 순서, 탐색·오류 상태와 컴포넌트 경계는 [페이지 구성과 콘텐츠 경험 명세](15-page-composition-and-content-experience.md)를 따른다.

시스템 허브·카테고리·개별 엔터티·사건/서사·업데이트를 어느 책임 단위로 나눌지는 [외부 위키 참고 기반 콘텐츠 구조](16-reference-informed-content-architecture.md)를 따른다.

아이콘 격자형 홈/전체 디렉터리와 시스템별 icon rail 인덱스의 별도 manifest·공개·게임 버전 검증 계약은 [디렉터리 보드와 허브 탐색 명세](17-directory-board-and-hub-navigation.md)를 따른다.

## 관계 표현

- 생산 관계는 `입력 → 시설·생산식 → 출력`으로 방향을 고정한다.
- 연구 관계는 `선행 → 연구 → 해금`으로 방향을 고정한다.
- 표에는 단위와 의미를 열 이름에 포함하고 색만으로 상태를 구분하지 않는다.
- 그래프는 보조 표현이다. 동일 관계를 접근 가능한 목록·표로도 제공한다.
- graph node와 edge는 이 typed relation에서만 생성한다. 숫자·조건·방향을 별도 graph 전용 필드로 복제하지 않는다.
- `internal`, `blocked`, 미허용 spoiler 대상은 graph projection에도 존재하지 않는다.
- 순환 관계, 끊어진 대상, 다형성 해금은 별도 품질 규칙으로 검증한다.

## 자동 문장 정책

템플릿은 검증된 필드를 문장으로 조합할 수 있지만 새로운 해석을 생성하지 않는다. 예: `A 연구로 해금된다`는 typed relation에서 만들 수 있다. `초반 최고의 선택이다` 같은 평가는 수기 검수된 공략 overlay에서만 쓴다.

## 미디어 계약

- 이미지마다 출처, 권리 상태, 대체 텍스트, 대상 안정 ID를 manifest에 기록한다.
- 승인 이미지가 없으면 일관된 유형 아이콘과 텍스트 인포박스를 사용한다.
- 자동 생성 자리표시자는 실제 게임 스크린샷처럼 보이게 만들지 않는다.
- 스포일러 이미지는 흐림 처리만 믿지 않고 초기 DOM·검색 색인 정책까지 분리한다.
