# 15. 페이지 구성과 콘텐츠 경험 명세

## 목표와 기준

이 문서는 플레이어가 페이지를 열었을 때 보게 되는 실제 정보 순서와 조작을 정한다. 화면을 예쁜 카드 모음으로 만들지 않고, **대상 확인 → 지금 필요한 사실 → 다음 행동과 관계 탐색**의 흐름으로 구성한다.

모든 콘텐츠 페이지는 선택한 게임 버전의 공개 snapshot만 읽는다. 게임 구현·수치·관계의 권위는 원천 자산과 승인 문서에 있으며, 위키 페이지는 검증된 사실을 읽기 좋게 조합하는 표현 계층이다.

홈·시스템 허브·카테고리·개별 콘텐츠·게임 버전을 어떤 단위로 나눌지는 [외부 위키 참고 기반 콘텐츠 구조](16-reference-informed-content-architecture.md)를 따른다.

## 공통 페이지 골격

```text
상단 전역 바: 로고 | 전체 검색 | 주요 분류 | 게임 버전 | 테마
────────────────────────────────────────────────────────────────
breadcrumb
제목 + 유형 + 공개/스포일러 상태 + 게임 버전
짧은 요약                                  [영구 링크] [변경 이력]
────────────────────────────────────────────────────────────────
핵심 사실(인포박스) | 본문과 관계 표 | 목차·관련 문서·역링크 요약
────────────────────────────────────────────────────────────────
관계 그래프 미리보기 + "관계 그래프 열기" + 같은 정보의 표
────────────────────────────────────────────────────────────────
관련 가이드 | 역링크 | 버전별 변경 | 정정/출처 상태
────────────────────────────────────────────────────────────────
footer: 게임 버전 | 업데이트 | 데이터 기준 | 라이선스
```

### 고정 규칙

- 제목 바로 아래에는 **무엇인지**를 한두 문장으로, 그 다음에는 유형별 핵심 사실을 둔다. 서술형 공략이나 긴 관계 그래프가 인포박스보다 먼저 오지 않는다.
- 데스크톱은 좌측 탐색, 본문, 우측 정보 rail의 3열이다. 본문 표·그래프는 필요할 때만 좌우 rail을 넘어 넓게 사용할 수 있다.
- 태블릿은 좌측 rail을 접고 인포박스를 제목 아래로 이동한다. 모바일은 단일 열이며 목차·필터·관계 그래프 설정만 접을 수 있다.
- `게임 버전`, `스포일러`, `정정 존재`, `자동 생성 범위`는 아이콘만으로 표시하지 않는다. 짧은 텍스트를 함께 둔다.
- 아무 데이터가 없을 때 빈 카드·가짜 설명을 만들지 않는다. `현재 게임 버전에서 확인된 정보 없음`과 상위 문서/관련 검색 링크를 보여 준다.

## 전역 shell

| 영역 | 항상 제공하는 것 | 세부 동작 |
|---|---|---|
| 상단 바 | 로고, 검색, 주요 카테고리, 게임 버전 선택기 | 검색은 `/search/`와 같은 query를 공유한다. 게임 버전 변경은 가능한 같은 stable ID 문서로 이동한다. |
| 홈·둘러보기 | 아이콘 디렉터리 보드, 짧은 범위 안내, 선택 게임 버전 | 핵심 시스템·도감·도구를 직접 link로 보여 주고, 전체 보드는 `/directory/`에서 연다. |
| 왼쪽 탐색 | 현재 섹션, 인접 카테고리, 접기 상태 | 현재 위치를 명확히 표시하고 URL만으로 독자가 길을 잃지 않게 한다. |
| 본문 | 제목, 요약, 사실, 관계, 설명 | JavaScript 없이 제목·본문·관계 표·내부 링크를 읽을 수 있다. |
| 오른쪽 rail | 인포박스/목차, 관련 문서, 역링크 요약 | 스크롤 중 목차의 현재 절만 강조한다. rail이 본문보다 중요한 정보를 숨기지 않는다. |
| 하단 | 현재 게임 버전, update record, data snapshot, 라이선스 | 실제 서비스 중인 게임 버전만 표시한다. |

## 콘텐츠 페이지의 공통 블록

각 블록은 데이터가 있을 때만 나타나며, 순서는 아래를 기본으로 한다.

| 순서 | 블록 | 독자 질문 | 필수 데이터/행동 |
|---|---|---|---|
| 1 | 제목 영역 | 이것은 무엇인가? | title, kind, summary, category, spoiler warning, 게임 버전 |
| 2 | 핵심 사실 | 지금 알아야 할 수치·조건은? | 유형별 인포박스; 값마다 단위와 조건 |
| 3 | 획득·요구·해금 | 어떻게 얻거나 사용할 수 있나? | typed relation의 짧은 경로와 canonical 링크 |
| 4 | 생산·사용·영향 | 무엇에 쓰이며 무엇이 바뀌나? | 입력/출력/사용처/효과를 관계 표로 표시 |
| 5 | 상세 설명 | 언제 유용하고 무엇을 조심해야 하나? | 검수된 overview·strategy·notes; 사실 수치 중복 금지 |
| 6 | 관계 그래프 | 연결망에서 어디에 있나? | 한 단계 미리보기, graph route, semantic 표 fallback |
| 7 | 관련 문서 | 다음에 무엇을 읽어야 하나? | related guides, same category, 역링크 |
| 8 | 이력·신뢰 | 어느 게임 버전 기준인가? | 게임 버전, update link, source snapshot 축약, errata 상태 |

## 콘텐츠 유형별 페이지

### 1. 아이템·원료·중간재

```text
제목 / 분류 / 게임 버전
요약
[질량] [보관] [가치] [품질] [스택]       ← 검증된 값만
획득 경로 ─ 제작식·채집·거래·사건
사용처   ─ 제작 재료·건설·장비·치료·연구
제작 흐름 그래프(입력 1단계 + 출력 1단계)
생산식 표 | 사용처 표 | 대체재 표
운용 팁·주의 | 관련 시설·연구 | 변경 이력
```

| 블록 | 필수 필드 | 조작 |
|---|---|---|
| 핵심 사실 | 분류, 질량, 보관 조건, 가치, 품질/스택 조건 | 수치의 헤더에 단위를 포함하고 비교 표로 이동 |
| 획득 | 제작식, 공급원, 필요한 시설·연구 | `입력 보기`, `제작식 열기`, `대체 경로` |
| 사용처 | 소비 제작식, 건설·장비·의료 등 typed use | 사용처 유형 filter, 결과물 기준 정렬 |
| 관계 | 입력·출력·연구/시설 연결 | 제작 그래프 열기, 깊이 1↔2, 표 전환 |
| 설명 | 용도와 선택 기준 | 수치 재서술 없이 조건·대안·위험만 작성 |

### 2. 시설·방

```text
제목 / 역할 / 게임 버전
요약
[크기] [건설 재료] [작업 슬롯] [입출력/보관] [필요 연구]
건설 조건과 배치 전제
가능한 작업·생산식
입력·출력·지원 시설 관계
시설 흐름 그래프
운영 병목·대안 | 관련 연구·아이템 | 변경 이력
```

- `가능한 작업`은 시설에서 실행 가능한 제작식·주문을 기본 정렬로 보여 주며, 잠긴 연구나 비공개 콘텐츠는 안전하게 제외한다.
- 시설의 크기·배치·재료는 첫 화면에, 세부 공급 흐름은 관계 표/그래프에 둔다. 실제 씬 좌표·내부 컴포넌트·미구현 계획은 공개하지 않는다.
- 한 시설이 여러 역할을 가지면 역할별 tab을 만들지 않고 본문 안의 명시적 절과 filter 가능한 표를 사용한다. 모바일에서 탭이 숨기는 정보를 만들지 않는다.

### 3. 제작식·생산 주문

```text
제목 / 산출물 / 실행 시설 / 게임 버전
요약
[입력] → [시설·작업] → [출력·부산물]
[작업량·시간] [연구 조건] [필요 슬롯·조건]
물질 흐름 표(입력 / 출력 / 부산물 / 손실 설명)
필요 시설·연구와 대체 제작식
제작 흐름 그래프(상류·하류)
운용 팁·병목·주의 | 관련 아이템·시설 | 변경 이력
```

- 제작식 페이지는 표보다 먼저 `입력 → 실행 → 출력`을 한 줄로 보여 준다. 단위·수량·조건이 없는 아이콘만 나열하지 않는다.
- 부산물, 외부 입력, 손실 설명은 main output과 분리해 오해를 막는다. 값은 relation/recipe data에서만 가져온다.
- `대체 제작식`은 같은 결과·동등한 목적이라는 typed relation이 있을 때만 보인다. 임의 추천을 자동 생성하지 않는다.
- 관련 그래프는 입력·출력과 필요한 시설·연구가 만나는 위치를 보여 주되, 전체 생산망을 자동 확장하지 않는다.

### 4. 연구

```text
제목 / 연구 단계 / 게임 버전
요약
[비용] [필수 전제] [해금 수] [연구 영역]
선행 연구 → 현재 연구 → 해금 항목
해금 목록(시설 / 제작식 / 아이템 / 규칙) + 유형 filter
연구 그래프(선행·후속 1단계)
전략적 의미·선택 조건 | 관련 시스템 | 변경 이력
```

- 선행 연구와 해금을 같은 표에 뒤섞지 않는다. 위쪽은 `선행`, 아래쪽은 `해금`으로 명시적 방향을 가진다.
- 연구 그래프의 기본 깊이는 1이며, 후속 연구 전체를 기본으로 펼치지 않는다. 사용자가 `후속 2단계`를 요청할 때만 범위를 넓힌다.
- 해금 목록은 유형 filter와 텍스트 검색을 제공한다. 각 행은 해금된 canonical 콘텐츠 페이지로 이동한다.
- 스포일러가 되는 해금은 안전한 count와 경고만 먼저 보여 주고, 허용 전에는 제목·아이콘·edge label을 공개하지 않는다.

### 5. 장비·의복·부품

- 첫 정보는 장착 위치, 공격/방호/내구 같은 유형별 핵심 값과 사용 조건이다.
- 다음으로 제작 재료·필요 시설·연구·수리/소모 관계를 보여 준다.
- 여러 후보를 비교해야 하는 경우 개별 페이지는 표준 facts만 제공하고, `비교하기`가 `/compare/{slug}/`로 이동한다. 개별 페이지를 긴 비교표로 부풀리지 않는다.

### 6. 종족·특성·질병·의료·사건

- 상태·조건·영향을 먼저 쓰고, 적용 대상과 대응/관련 콘텐츠를 뒤에 둔다.
- 사건·엔드게임 콘텐츠는 처음에 스포일러 경고를 배치한다. 펼치기 전 DOM·검색·목차·그래프에는 결과를 넣지 않는다.
- 플레이어 행동에 필요한 치료·대응·요구 시설은 relation 표로 제공하되, 내부 시스템 구현이나 확률 코드 설명은 공개하지 않는다.

## 시스템 가이드 페이지

가이드는 데이터 엔터티 페이지와 달리 처음 읽는 독자의 흐름을 책임진다.

```text
가이드 제목 / 대상 게임 버전 / 예상 독자
이 시스템이 필요한 이유
핵심 결정을 세 문장 이내로 요약
기본 흐름(단계별)
대표 콘텐츠 예시와 바로가기
실패 원인·복구
심화 선택·관련 가이드
변경 이력과 스포일러 절
```

- 가이드 안의 콘텐츠 이름은 의미가 분명하고 공개된 stable relation일 때만 링크한다.
- `기본 흐름`은 실제 플레이 순서로, `상세 규칙`은 필요한 독자가 펼쳐 읽는 순서로 둔다.
- 가이드가 아이템·연구 페이지의 수치를 복사하지 않는다. 해당 페이지의 facts/관계 표로 이동시킨다.

## 탐색 페이지

### 카테고리·목록

- 제목과 짧은 범위 설명, 하위 카테고리, filter·sort 가능한 엔터티 표, 관련 가이드 순서로 둔다.
- filter는 유형별 공개된 필드만 노출한다. 상태·스포일러가 다른 항목은 서로 다른 기본 결과 집합으로 처리한다.
- 정렬은 제목, 유형, 공개된 수치, 추가된 게임 버전처럼 의미가 분명한 열만 제공한다. 숫자와 단위를 분리하지 않는다.
- 모바일에서는 주요 2~3개 필터를 먼저 보이고 나머지는 `필터` 접이식 안에 둔다. 선택한 filter 수와 초기화 action을 명확히 표시한다.

### 검색

```text
검색어와 현재 게임 버전
즉시 이동 후보(정확한 제목·별칭)
결과 수 + 유형·카테고리·스포일러 filter
결과 목록: 제목 / 유형 / 안전한 요약 / 일치 문맥
결과 없음: 가까운 별칭 / 카테고리 / 수정 제안
```

- 검색은 graph node label을 독립 문서로 중복 표시하지 않는다. 결과는 항상 canonical 페이지로 간다.
- 스포일러 미허용일 때는 결과 수·제목·snippet 모두 안전한 공개 범위에서 계산한다.

### 관계 그래프 explorer

전용 explorer의 상세 구성은 [관계 그래프 경험](14-relation-graph-experience.md)을 따른다. 이 페이지의 우선순위는 `중심 대상 → 작은 graph → 선택 상세 → 동일 관계 표`다. 전체 게임 그래프, 자동 움직이는 물리 레이아웃, 게임 보유량을 가정한 개인화 추천은 제공하지 않는다.

### 업데이트·게임 버전 페이지

- `/updates/`는 최신순 카드 목록이 아니라 날짜·게임 버전·한 줄 영향·변경 유형을 가진 간결한 목록이다.
- `/updates/{game-version}/`는 added/changed/fixed/known issues/migration을 보여 주고, 바뀐 주요 콘텐츠·가이드와 이전 게임 버전 비교로 연결한다.
- `/game-versions/{game-version}/`는 해당 버전에서 시작할 수 있는 주요 카테고리·업데이트 요약·문서 범위·이 버전에 없는 대상 안내를 제공한다.
- 과거 게임 버전은 `noindex,follow`지만 공개 열람은 가능하다. current와 history의 검색·관계·graph는 섞이지 않는다.

## 상태·오류·스포일러 페이지

| 상태 | 표시 | 제공할 action |
|---|---|---|
| 대상 없음 | "이 게임 버전에는 이 문서가 없습니다" | 같은 제목 검색, 상위 카테고리, 다른 게임 버전 선택 |
| 이전 slug | 현재 canonical로 한 번에 redirect | 이동 사실과 영구 링크 |
| 숨겨진 스포일러 | tier·영향 경고, 안전한 대체 라벨 | 명시적 펼치기 또는 전역 설정 이동 |
| 관계 부족 | 확인된 연결 없음 | 상위 가이드·카테고리·검색 |
| graph 예산 초과 | 범위를 줄여야 한다는 이유와 현재 count | depth 낮추기, 유형/관계 filter, 표 보기 |
| 생성 품질 차단 | 공개하지 않음 | 내부 QA만 기록; 플레이어 페이지에는 노출하지 않음 |

## 컴포넌트 계약

| 컴포넌트 | 입력 | 출력/행동 | 금지 |
|---|---|---|---|
| `PageHeader` | title, kind, summary, version, visibility | breadcrumb, 영구 링크, 안전한 상태 표기 | source path/내부 stable ID 노출 |
| `FactInfobox` | 유형별 검증 fact | 단위·조건을 포함한 facts | overlay 수치 덮어쓰기 |
| `RelationTable` | typed edges | filter/sort, canonical links, 표 fallback | 문자열 추론 관계 |
| `RelationPreview` | 중심 node와 depth 1 slice | graph 열기, 표와 같은 count | 전역 그래프 자동 로드 |
| `SpoilerBlock` | tier, safe label, approved content | 경고 후 명시적 열기 | CSS blur만으로 보호 |
| `VersionNotice` | game version, update, errata status | update/errata 이동 | deployment ID를 게임 버전처럼 표시 |
| `EmptyState` | 상태 코드와 복구 후보 | 상위 탐색·검색·version 전환 | 추측 콘텐츠/가짜 fallback |
| `DirectoryBoard` | version-scoped group, icon, safe label, canonical target | 아이콘 격자/목록, section 이동, 안전한 direct link | 아이콘만 링크, 외부 이미지, 없는 대상의 유사 문서 대체 |
| `SystemIndexBoard` | system label/icon, 직접 topic link 묶음 | left rail + right link rows, 모바일 단일열 전환 | 모든 하위 엔터티 나열, 전역 항목 혼입 |

## 페이지 구현 순서

1. 공통 shell, `PageHeader`, `FactInfobox`, `RelationTable`, spoiler/version/empty state를 먼저 만든다.
2. 아이템·시설·제작식·연구 4개 페이지 family를 실제 source fixture로 완성한다.
3. 홈/`/directory/`의 `DirectoryBoard`와 시스템 가이드의 `SystemIndexBoard`를 실제 공개 대상에 연결한 뒤, 카테고리, 검색, 업데이트·게임 버전 페이지를 연결한다.
4. 관계 graph preview와 explorer를 같은 relation table 위에 추가한다.
5. 장비·의료·사건 등 나머지 family를 mapping하고 desktop/mobile·keyboard·스포일러 regression을 실행한다.

## 페이지 acceptance

- 대표 질문 30개가 검색 또는 세 번 이하의 내부 이동으로 답에 도달한다.
- 대표 아이템·시설·제작식·연구 페이지에서 첫 화면만 읽어도 대상·핵심 조건·다음 행동을 알 수 있다.
- 모든 facts는 단위·조건·게임 버전을 잃지 않으며, 같은 사실이 본문·표·graph에서 다르게 보이지 않는다.
- JavaScript 없이 canonical 본문·관계 표·관련 문서·게임 버전 전환을 사용할 수 있다.
- 360px, 768px, 1280px에서 제목·표·목차·infobox·graph preview가 겹치거나 잘리지 않는다.
- `internal`, `blocked`, 미허용 스포일러가 제목·검색·목차·graph·metadata·sitemap에 전혀 나타나지 않는다.
