# R80 전투, AI와 연속 플레이 시험

현재 상태: 현재 소스 `frozen-r32.json` 및 `compile-r29`로 실제 `soak-r11`을 완료했다. 최종 판정은 `RUNTIME_TESTS_COMPLETED_WITH_MODEL_REJECTIONS`다. 실행 안정성 검사는 통과했으며 모델 응답 거절과 대기 지연은 남아 있다.

## 실제 확인한 범위

하나의 R80 8B Q4를 기존 게임 Host와 요청 대기열에 연결해 실행했다. 모델 응답이나 피해 결과를 주입하지 않았다. 사용자 저장과 기존 모델은 별도로 보존했으며 시험은 독립 저장 경로와 비대화형 Windows 데스크톱을 사용했다. 사용자의 마우스나 앱 포커스를 조작하지 않았다.

## 고친 문제

- 실제 게임의 요청 참조, 새 관측과 후보 수를 R80 입력과 연결했다. 큰 요청의 문법 준비 비용과 입력 길이 문제를 줄였다. 허용되지 않은 효과나 잘못된 근거는 최종 적용 전에 계속 거절한다.
- 기술 설명에서 선택된 부가 효과와 조건이 빠지던 입력 구성을 고쳤다. 실제 응답에서 회복과 방어, 이동과 지속 피해, 조건부 추가 타격의 함께 서술을 확인했다.
- 소수 피해와 아주 작은 피해의 표시, 인물 조사 및 전투 원인의 문구를 고쳤다. AI 기록 대기와 거절 뒤에도 원래 사실을 조회하고 저장할 수 있게 했다.
- 같은 인물의 소문, 목표와 기분 요청이 같은 종류로 중복 적체되지 않게 했다. 성공, 실패, 취소와 동기 거절 후 해당 인물만 다시 요청할 수 있는 표적 검사를 통과했다. 서로 다른 인물과 요청 종류는 독립적이며 큐 용량이나 시간 한도는 늘리지 않았다.
- R80 모델의 메모리 적재 방식을 조정했다. 앞선 메모리 부족 실패는 보존했고 보호 한도는 낮추지 않았다.
- 시설 진화가 같은 시설 ID의 이용 번호, 승인 범위와 운영 상태를 잃던 문제를 고쳤다. 이용 중인 시설 교체는 명시적으로 거절한다.
- 진화로 바뀐 시설 이름을 당일 정산이 오류로 취급하던 문제를 고쳤다. 완료된 진화 이력과 현재 월드 시설을 검증한 명시적 이름 전환만 허용하며 수치와 과거 보고서는 보존한다. 수정 전 실제 저장을 읽는 경로도 확인했다.
- 시설 숙련이 찼을 때 등록된 순수 운용 효과를 후보에서 누락하던 문제를 고쳤다. 서비스 Operate 전용 순수 속도 후보를 추가하고 실제 소비자 및 같은 축 상쇄 검사를 유지했다. 후보가 생겨도 자동으로 효과를 부여하지 않는다. 수치 영향은 [밸런스 기록](../game-design/whole-game-balance-baseline.md)을 따른다.
- 사망 시 운반 음식의 정상 신선도 감소가 물리 재고의 오래된 스냅샷과 달라 반환이 거절되던 문제를 고쳤다. 유효한 단조 감소만 물리 반환 경계에 반영하고, 증가나 보존 처리 변경 및 다른 성분 변경은 거절한다. 실제 Actor.Die를 사용한 통제 검사에서 같은 스택, 수량, 위치와 신선도 보존, 권한 해제 및 저장 복원을 확인했다.
- 직원 영구 이탈 뒤 활성 심리 기록이 남아 공식 저장을 막던 문제를 고쳤다. 같은 명령 안에서 해당 기록을 정리하며 commit 거절 시 직원과 심리 상태를 함께 되돌린다. 실제 월드의 직원 이탈 후 공식 저장 복원과 무관한 인물의 심리 상태 보존을 확인했다.
- 성격의 서로 다른 특성을 억지 인과관계로 잇거나, 소문에서 작업 종료 사유를 시설 용도로 바꾸지 않도록 생성 전 입력을 보완했다. 실제 Activity 필드를 원값 그대로 전달하고 auxiliary 지시 함수 이외 bridge AST는 보존했다. 일부 성격 문장의 어색한 표현은 실제 수정 후 응답에도 남아 있어 문장 품질 통과로 보고하지 않는다.

- 전체 월드 복원 뒤 종료된 방문객의 이전 장면 객체가 남아 전투 저장에서 동일 ID가 중복되던 문제를 고쳤다. candidate 준비 시점의 정확한 이전 객체 목록만 commit 완료 후 정리한다. 실제 실패 저장을 재생해 이전 객체 비활성, world/lifetime 조회에서 참조 제거와 새 생존객 하나 및 후속 공식 저장 복원을 확인했다. 사망 기록, 실물 시체 item stack과 body-health는 새 저장의 권위 상태를 유지한다.

## 현재 연결된 AI 기능

현재 생산 경로는 선택형4개, 성격/목표/기분/소문/기록/말풍선6개, 시설 역사1개로 총11프로필이다. 두 실제 QA 묶음에서11개 모두 성공 응답이 있다. 미사용 legacy enum을 현재 기능으로 세지 않았다. `profile-coverage-r1.json`에 생산자와 증거 경로, 소비 관측 한계를 기록했다. transport 성공은 최종 효과 적용이나 문장 품질 승인이 아니다.

## 증거와 판정 경계

기준 경로는 `Artifacts/QA/R80ExtendedPlay-20261027-r1`이다. `profiles-r16`의 실제 소비자, `facility-hostile-r3`의 실제 진화와 저장 복원, `hostile-restore-r2`의 수정 전 저장 및 자동 교전을 구분해 보존했다. `soak-r1` 메모리 실패와 `soak-r2` 약786초의 후보 생성 실패를 30분 성공으로 합산하지 않는다.

현재 소스는 `frozen-r32.json`, 컴파일과 표적 검사는 `compile-r29`을 따른다. bundled bridge 경계19검사도 PASS다. 시설 운영 상태, 정산 이름 전환, 능력별 후보 생성, 사망 시 운반 회수와 영구 이탈의 통제 검사를 실제 모델 실행과 구분했다. `soak-r3`의 약23분 사망 정리 실패와 `soak-r4`의 20분 저장 실패도 보존하며 완료 시간으로 합산하지 않는다. `soak-r5`는 15분 저장이 손님 입장 중의 기존 미지원 상태를 거절했다. 최종 r11은 같은 validator를 유지하고 이동 완료를 최대60초 기다리는 경계를 사용했다. 주기 저장5회와 종료 복원이 모두 통과했다.

이 결과는 프로토타입의 대표 실행 경로 시험이다. 모든 구형 인터페이스, 모든 전투 조합, 수동 UI 조작, 일반 플레이 화면의 프레임 속도나 전체 모델 품질 인증을 의미하지 않는다. 일부 문장의 말투와 근거 품질은 추가 개선 대상이며, 거절된 응답과 원문 표시는 원답과 함께 남긴다. 실제 큐 적체와 말풍선 만료도 관측됐으므로 실시간 대사 응답성이 충분하다고 주장하지 않는다.

손님이 입장하거나 퇴장하는 도중의 저장과 해당 이동의 재개는 현재 V18에서 미지원이다. 저장은 행을 삭제하거나 손님을 도착 처리하는 대신 명시적으로 거절하며, Capture 실패 시 기존 slot 파일을 덮어쓰지 않는다. 저장 메뉴는 게임을 멈추므로 메뉴를 닫아 이동을 마친 뒤 재시도해야 한다. 이번 QA의 안정 상태 대기는 제품의 입출구 중 저장 지원 구현과 다르다.

## 정상 런 종료와 시험 범위

`soak-r6`는 마지막 관측1461.59초에서 사장이 체력0으로 사망해 6일째 런이 정상 종료됐다. Unity 예외0과 자동 저장의 terminal Loss, meta 완료1회/보상431을 확인했다. 이 실행을30분 성공이나 게임 결함으로 보고하지 않는다. 새 시험기는 통제된 실제 사망 명령, terminal 공식 저장 복원과 실제 활성 saved world 재개를 먼저 검증하며 이 준비 시간은30분에서 제외한다. 이후 정상 종료가 오면 같은 실제 saved world를 공식 복원해 계속 관측한다. 난이도, 사망 규칙이나 무적 상태는 바꾸지 않는다.

이번30분은 실제 종료와 재개를 포함한 한 번의 연속 시험 창이다. 한 런의30분 생존이나 실패한 시도의 시간 합산을 의미하지 않는다. 게임 시계 진행량은 저장 재로드 점프를 제외한 양의 누적값이다. 자연 종료/재개의 실제 발생 횟수는 최종 result의 naturalRunCompletions로 구분한다.

OS 외부 샘플27회에서 가용 물리 메모리 최저8,773,054,464B, 자기 Unity/bridge/llama 작업 집합 합계 최대6,174,355,456B를 관측했다. Unity Profiler 추적 할당 증가1,474,268B는 전체 프로세스 메모리나 장기 누수 인증을 뜻하지 않는다. 이 실행은 격리된 실제 GameplayScene 실행이며 수동 화면 조작이나 일반 화면 FPS 측정은 아니다.

Ollama API 서버 복원 명령은 자동 승인 검토에서 정책상 차단돼 실행되지 않았다. 읽기 전용 후속 확인에서 API와 Ollama 프로세스는 모두 없었다. 구체적인 차단 사유는 제공되지 않았으며 우회 실행이나 GUI 재기동은 하지 않았다. Firefox, Discord, Nikke와 다른 사용자 세션은 종료하지 않았다. CUHA는 Intel HD620 내장 그래픽의16GB CPU 장비로 확인됐으며 원격 시험은 시작하지 않았다.
