# R80 응답성 Goal 결과

2026-10-28. 단일 R80 8B 모델의 요청 처리와 시설 이력 적용을 수정했다. 현재 소스의 실제 게임 자동 시험을30분 완료했다. 모델 전체 품질 인증이나 모든 문장의 자연스러움 승인은 아니다.

## 바뀐 동작

- 초기 기술 후보3개의 선택과 서술6단계에서 같은 게임 입력을 공통 앞부분으로 유지해 캐시를 재사용한다. 후보 수, 순서, 이전 선택과 이름 제외 및 효과 판단 함수는 유지했다. 후속 단계의 실제 입력 처리 시간 중앙값은 이전1,909.9ms에서274.4ms로 줄었다.
- 진화 이력의 고정 식별자와 효과 예산 및 전체 근거 순서는 게임 소유자가 확정한 값으로 전달한다. 모델은 원래의 이름, 설명, 이력 사유3개 문장 필드만 생성한다. 원문3값은 바꾸지 않고 게임 정보와 프로토콜 응답으로 조립한다. 효과와 근거를 코드가 새로 선택하지 않는다.
- 이력 요청을 용량 때문에 접수하지 못하면 실제 모델 실패 횟수를 늘리지 않고2초 뒤 다시 접수를 시도한다. 실제 접수 후 실패의 원래 재시도와 제한 시간은 유지한다.
- 말풍선은 짧은 완결 반응을 요청한다. r16의16자 생성 상한과 생산자의4~10단어 지시가 충돌해 문장이 끊겼으므로, 지시를1~4단어와8~16자 목표로 맞추고 생성 상한을24자로 뒀다. 원래 consumer80자, 대기 만료3초, 네트워크 제한4초, 사실 입력과 원답은 바꾸지 않았다. 생성 후 문장을 자르거나 수선하지 않는다.
- 기존 말풍선 전용 처리 자리, 용량 접수 보호, 인물 수명 취소 및 원래 내용 검사는 그대로 유지한다.

### 실제 이력 적용

기존 실제 저장의 미완료 시설3건은 별도 `history-recovery-r15`에서 모두 이름과 설명을 실제 상태에 적용하고 공식 저장 후 복원했다. 응답은3.22~3.86초, 실패0이다. 원래8개 근거의 값과 순서, 노드 근거, 효과와 예산을 보존했다. 이 표적에서는 게임 시계를 멈췄으며30분 플레이로 세지 않는다. 현재 r17도 동일한 이력 구현을 사용한다. 원 모델 raw HTTP의3개 문장 값과 게임에 전달한 문장 값의 동일성을 독립 대조했다. 위 표의 이력3성공은 이번 연속 시험의 응답이며 별도 적용 시험과 구분한다.
